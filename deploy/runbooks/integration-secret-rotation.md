# 开放集成密钥轮换

## Client Secret

1. 确认应用状态、当前凭据版本、使用方负责人和回退窗口。
2. 在管理页面创建新凭据。明文只展示一次，直接写入接入方的 Secret 管理系统。
3. 在预生产环境获取令牌并运行两种客户端契约示例。
4. 生产客户端切换后，确认新凭据签发和 API 调用正常。
5. 等待旧令牌最长有效期及约定缓冲时间，再吊销旧凭据。
6. 通过审计确认创建、使用切换和吊销，工单只记录版本和时间，不记录明文。

疑似泄露时不等待常规窗口：创建新凭据并切换后立即吊销旧凭据，检查异常来源地址、
令牌签发量和访问审计，按安全事件流程处理。

## Webhook 签名密钥

轮换后旧签名密钥保留 48 小时校验窗口。接收方应按签名版本同时接受新旧密钥，完成
切换并验证后删除旧密钥。发送验证事件只验证新密钥和网络连通性，不产生业务事件。
窗口结束后仍使用旧版本签名应视为配置漂移。

## Connector 集成 Secret

同名 Secret 轮换会产生新版本，Connector 通过逻辑引用解析当前活跃版本。先创建新
版本并执行受控连接测试，确认成功后吊销旧版本；只有合规保留期结束且确认无回退需求
时才永久销毁密文。主加密密钥轮换步骤见
[`http-connector.md`](http-connector.md#主密钥轮换)。

## 回退

凭据轮换的回退是让客户端暂时恢复使用仍处于活跃窗口的旧版本。已经吊销或销毁的密钥
不能恢复；执行这些操作前必须完成验证和负责人确认。数据库和日志中不应出现任何明文
密钥，发现明文时立即停止轮换并按泄露事件处理。
