# 集成应用凭据轮换

## Client Secret

轮换是原子替换：新凭据签发前，服务端立即撤销当前 ACTIVE 凭据，数据库不支持新旧
Client Secret 重叠有效。旧 Secret 随轮换立即失效；轮换前已签发的 Access Token 仍按
原 TTL 有效，除非停用应用。

1. 用独立预生产应用验证 OAuth Token 与 Embed launch，不能拿生产凭据做预演。
2. 确认接入方能立即更新 Secret 管理系统并滚动客户端；无法原子切换时安排短暂停机窗口。
3. 在管理页面执行轮换。新明文只展示一次，立即写入受控 Secret 管理系统，不写工单或日志。
4. 立刻切换生产客户端，验证新 Secret 可取 Token、旧 Secret 返回 `invalid_client`，再验证
   Embed launch。
5. 通过审计确认轮换版本、时间和操作者；监控 Token 签发失败、应用错误率和来源地址。

疑似泄露时先停用应用，使旧 Secret 和已签发 Token 都无法继续访问；调查来源地址、
令牌签发量和访问审计后，再轮换凭据并恢复应用。

## 回退

旧 Client Secret 不能恢复，也不存在切回旧版本的重叠窗口。新凭据丢失或切换失败时，
再次执行轮换生成另一份新凭据，并立即更新客户端；必要时保持应用停用直到联调完成。
数据库和日志中不应出现任何明文密钥，发现明文时立即停用应用并按泄露事件处理。
