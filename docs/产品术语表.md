# 产品术语表

本文档是用户界面、帮助文档和验收测试的统一用词来源。技术接口、数据库字段和代码标识可以保留英文别名，但不得直接替代面向业务用户的名称。

| 标准术语 | 用户可见含义 | 技术别名 | 使用规则 |
| --- | --- | --- | --- |
| 知会 | 将流程信息通知给不承担当前审批责任的人 | CC、cc | 页面统一使用“知会”“知会我的”“知会记录”，不使用“抄送” |
| 标识 | 跨配置、接口和环境保持稳定的机器可读名称 | Key、code | 基础模式显示“标识”；仅开发者模式可补充 Key、字段代码等技术叫法 |
| 保存草稿 | 将当前配置持久化，但不影响正在使用的发布版本 | save | 不使用“暂存”“确定”等无法说明结果的按钮名称 |
| 应用到画布 | 将节点面板中的修改写入当前设计器内存模型 | apply | 必须同时提示还需“保存草稿”才能写入服务器 |
| 发布 | 经过校验后使配置成为运行时使用版本 | publish | 发布前说明影响对象、版本变化和未保存项 |
| 回滚 | 将运行时版本切换到已存在的历史发布版本 | rollback | 不表示删除历史，也不等同于撤销当前未保存编辑 |
| 启用 / 禁用 | 控制对象是否可继续被使用 | enabled / disabled | 状态切换前说明对登录、权限、任务或运行时的影响 |
| 组织 / 部门 | 组织是顶层或业务单元，部门是组织下的工作单元 | org / dept | 创建入口和父级选择必须明确二者约束，不使用含混的“节点”代替 |

## 按钮文案

- 按钮应描述结果，例如“创建用户”“保存权限”“确认终止”“删除表单”。
- “确定”只可作为不产生业务变更的纯信息关闭动作；此类场景优先使用“关闭”。
- 危险操作的确认框标题、正文和确认按钮应分别说明对象、影响和最终动作。

## 模式分层

- 基础模式：名称、业务含义、规则、状态和影响。
- 高级模式：稳定标识、布局、校验和低频业务配置。
- 开发者模式：字段代码、数据库列、JSON、SQL、哈希、数据源和扩展注册信息。
