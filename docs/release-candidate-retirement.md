# 发布候选下线说明

日期：2026-09-20

## 下线范围与保留能力

- 移除“发布候选”页面、前端路由/API、后端 `/api/release-candidates` 接口及候选专属实现、测试。
- V099 删除候选菜单、四项 `release-candidate:*` 授权及六张 `release_candidate*` 专属表，候选冻结记录、预检结果、步骤和报告不再保留。
- 配置迁移的导出、导入、分析、映射、直接发布与批次回滚保持不变；实体、表单、列表和流程各自的发布入口保持不变。
- `config_import_package`、`config_import_item`、`config_migration_asset`、资产依赖、基线、导出包、环境映射与普通操作审计数据保留。删除候选不撤销已发布配置。

## 发布与回滚怎么使用

继续在“配置迁移”中导出配置包，在目标环境导入、分析并解决阻断项，然后直接发布。已发布批次仍显示“回滚”按钮。

回滚沿用原规则：有完整旧快照时恢复旧配置；新资产没有旧快照时执行原有停用逻辑；不完整快照不能自动回滚。配置回滚不等于业务数据或数据库结构回滚。

权限仍使用原有 `config-migration:*` 权限。仅有候选权限的角色不会自动获得普通发布或回滚权限，需由管理员按职责配置。

## 升级注意事项

1. 停止旧版候选入口，排空在途发布/补偿操作；需要留档的候选报告与数据先备份。
2. 使用现有独立数据库迁移器执行新增 V099，再启动新版后端并部署新版前端。不要让旧版候选服务连接已删表的数据库。
3. 刷新页面、重新获取菜单；候选菜单和旧路由不再可用，检查配置迁移入口及已发布批次的回滚按钮。

本次只在临时隔离 MySQL 8.0.27 中执行了 V099 验证，未对正在使用的业务库执行迁移。业务库菜单和专属表在升级执行 V099 后才会被清理。候选历史删除后只能从备份恢复；不可仅回退应用程序来恢复该功能。
