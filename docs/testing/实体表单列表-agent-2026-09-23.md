## 功能问题与修复

- **L-01 已修复并页面复测：数值查询清空无效。**复现：先按金额 `123.45` 查询得 1 条，删除金额输入值，界面为空后直接点查询，仍只得 1 条。`NumberField.vue` 未指定 Element Plus 清空值，组件可能将清空还原为数值。已在 [NumberField.vue](/Users/dawei/Documents/ddup/ai/flow/workflow-web/src/extensions/builtin/fields/components/NumberField.vue) 设置 `value-on-clear=null`，并加注释解释列表过滤的语义。修改后在同一运行页面重试，金额查询得 1 条，清空后直接查询恢复 2 条。`test:form-renderer-mode` 与 `build:admin` 均通过。
- **L-02 已修复并页面复测：业务列表默认排序配置未生效。**设计器列表设置中“默认排序字段=金额、方向=降序”保存、刷新并发布后仍显示该配置；旧运行页两条记录依次显示 `123.45`、`9999999999.99`，与降序预期相反。原因是系统实体查询路径读取了默认排序，动态业务实体分页路径始终按创建时间倒序。已使动态路径从已发布列表配置读取排序并在 SQL 分页前按已发布物理列排序，字段编码和 SQL 方向均校验；`DECIMAL` 列使用数据库原生数值顺序。带虚拟列过滤的全量查询也在切页前排序，数值按数值比较。新增四种分页分支 SQL 回归、服务透传回归以及金额 `9.00/10.00` 跨页回归，目标 Maven 测试通过。8080 更新后刷新真实列表，首行 `QA金额边界最大值=9999999999.99`、次行 `QA查询普通值=123.45`，可访问树和截图一致。

## 操作便利性建议

- 表单设计器初次进入显示“状态未知”，列表设计器初次进入显示“发布状态未知”，用户难以区分首次草稿和加载异常；建议按实际版本状态显示“未发布”或明确加载中。
- `DECIMAL(12,2)` 超总位数要提交后才收到泛化错误提示；建议金额输入旁显示允许的整数位/小数位并在输入时就地校验，错误信息带字段名与 `12,2` 上限。
- 默认数值查询方式显示“包含”，尽管可配置“等于”，容易产生错误查询；建议依据数值字段类型默认“等于”。
- 条件必填的条件由真转假后，字段星号即时消失，但先前“请输入数据名称”的红色错误提示仍留到下次提交；这次提交实际成功。建议条件变化时清理该字段失效的校验提示，避免用户以为仍无法保存。
- 表单发布时出现 `/customComponent`、`/entityId` 等高风险提醒，即使这是首次创建；建议首发与已有版本变更区分风险说明。
