# wfpack 跨系统引用改造与表单节点模板退役

日期：2026-09-23。修改当前工作区，未部署，未对业务数据库执行 SQL。

## 新包约定

只接受 `formatVersion=3` 的新 wfpack；格式 1、2 明确拒绝，需从更新后的源系统重新导出。导出使用副本转换，不改写已存储的历史发布快照与哈希。

| 配置 | 包内关联依据 | 目标端行为 |
| --- | --- | --- |
| 用户、角色、用户组、部门/组织固定引用 | 带类型的 `wf-ref://` 编码引用，用户用 username，其余用各自 code | 只按编码查询并写入目标本地 ID；缺失时阻断，不自动新增身份数据，不按源 ID 兜底 |
| 数据范围 matchConfig、filterConfig/audience | 同上，遍历嵌套规则与 JSON 文档 | 保留规则结构，替换固定身份；policyKey 复用方案，语义相同的绑定复用现有记录 |
| USER_FIELD 固定条件 | id/userId/deptId/orgId/roleIds 转为身份编码引用 | 导入后恢复目标本地 ID；动态变量保持原样 |
| 流程动作 | actionCode | 重新取目标 actionDefinitionId 和处理器，校验可用性；源 ID 撞号不参与选择 |
| 子表单固定发布版本 | entityCode/formKey + 固定内容及语义指纹 | 复用内容相同的目标发布版本；缺失时按随包内容创建所需版本，不按源版本号或最新版本猜测 |
| 流程多实例、知会、固定节点操作对象 | 明确类型的身份引用 | 同时处理 BPMN 和节点 JSON，包括流程/开始/结束节点上的知会属性 |
| 工作日历组织、SLA 用户、流程表单 | orgCode、username、entityCode/formKey | 移除目标端按 ID 回退 |

实体、字段、表单、节点、列表等继续按既有 entityCode/fieldCode/formKey/nodeKey/listKey 复用。导入分析和实际发布共用正文引用校验，不能仅凭依赖清单遗漏而跳过缺失引用。数据库关联最终保存目标本地 ID 是正常行为。

### 固定子表单

- 固定内容随包携带；嵌套引用检查循环及最大深度。先准备各实体的表单宿主、字段和依赖，再补齐历史固定内容，最后恢复包内当前表单，避免历史内容成为最终活跃版本。
- 指纹只忽略明确的本地技术元数据，保留业务默认值中的 `id`、空值、字段配置及实际事件行为。目标本地 ID、修订号和发布版本号不同不影响复用。
- 按发布时的冻结内容恢复表单自身及继承的实体事件、接口配置，不用后来修改过的接口草稿代替。接口导出携带 version/snapshotVersion。
- 同一固定表单引用同一接口的不同冻结实现时明确阻断，避免任意选取一个。目标缺少固定内容时，包内必须同时包含该表单的当前配置以便恢复。
