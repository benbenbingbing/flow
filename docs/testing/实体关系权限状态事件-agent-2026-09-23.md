## 待测与风险边界

- R22：普通关联及复杂多级关系尚未覆盖。设计器预览中的“保存”点击后仍停留在预览弹窗，不能据此证明写库成功。

- S03：状态迁移条件与流程联动尚未覆盖；当前状态配置弹窗只定义状态集合，不配置迁移条件。
- E04：事件运行时触发顺序、启停、扩展步骤输出映射及失败回滚尚未覆盖。

## 操作体验建议

1. 关系目标选择器应在搜索未发布实体时明确说明“目标实体需先发布”，避免误以为实体不存在。
2. 表单设计器选中子明细组件后直接添加普通字段会默认嵌套到子组件内；画布应明确显示当前放置目标或在添加前提示。测试时通过截图发现误放，删除后点击根画布重新添加。
3. 默认事件下拉应对 FORM_SAVE 等当前不独立触发的事件给出禁用或醒目标识，避免产生“保存后会执行”的错误预期。
4. 已发布旧表单不随实体关系约束变更自动改写快照。若管理员事后把关系改为必填，后端会立即拒绝零子行，而旧表单可能仍无“必填”提示；关系设置页应提示“需重发引用该关系的表单”，或在发布检查中列出失配。
5. V2 前端零子行校验只提示“子项组成关系存在未通过校验的数据”，建议明确写成“请至少添加 1 条子项”，并将“添加一行”聚焦或高亮。
6. 状态编码冲突的保存错误只说“数据重复，请检查唯一字段”，建议点明重复编码和所在行，便于用户修改。
7. 对未启用级联删除的组成关系，删除父记录后子记录仍保留已不存在父记录的外键。当前行为符合配置，但可在删除确认里提示“会留下无父记录的子项”，并提供清理入口。
8. 关系停用并重发实体后，旧表单仍显示原子表单且允许填写，用户到保存时才看到配置失配错误。实体发布时应列出受影响的已发布表单，提示同步重发，或在运行表单中将停用关系置灰并说明原因。

## 本代理代码与迁移变更

测试账号环境变更：经用户授权，为验证真实权限，曾将现有 `testuser` 与 `lisi` 的本地测试密码重置并经正常改密接口设为临时密码；未改变任何角色或授权。之后用户已自行把 `testuser` 设置为其指定密码，代理不再改动该账号。`testuser` 含 `super_admin`，因此真正的负向测试使用仅有 `common_user` 的 `lisi`。`lisi` 临时密码未写入仓库、报告或持久日志，验收结束后应由用户自行修改并保管；在此之前不能将其视为沿用原密码。

- 修复必填关系未生效：`EntityRelationRuntimeService.saveRelationData` 校验显式空子集合及省略关系键的既有子行；`SubFormField.vue` 将关系必填性映射到子表单最小行数和显示约束。
- 修复新建关系表单节点丢失必填配置：`relation-content.js` 在节点生成与回读时保存 `relationRequired`；`EntityFormDesignByEntity.vue` 从节点配置回读设计态必填显示。子表单发布协议不接受通用 `required` 节点属性，因此以 `subFormConfig.relationRequired` 作为稳定持久化来源。测试表单已重发 V2，旧的已发布 V1 快照不被静默改写。
- 必填关系不再自动生成一条空白子行，用户必须明确添加；零子行时表单提交显示校验错误，避免“空白子记录”绕过关系约束。
- 修复子表单仅剩一行时无法删除：`SubFormRenderer.vue` 在 `rowCount > minRows` 时保留行头和删除按钮，真实页面刷新后已验证。
