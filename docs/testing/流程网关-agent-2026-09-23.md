## 使用体验记录

- 网关节点“应用到画布”与页面“保存草稿”是两次操作；页面会提示未保存，但容易误认为应用已持久化。建议将操作文字或保存入口关联得更明确。
- 列表新建后的字段、列表设置、发布分散在不同入口，首次发布弹窗对初始化配置逐项给出“高风险提醒”，噪声较多。建议区分首次发布与已有版本变更，保留真正需要复核的风险项。
- 排他转并行后，原大额连线的 `conditionGroupConfig` 扩展属性仍留在 XML 中；执行用的 `conditionExpression` 已移除，不影响当前并行逻辑，但后续再改回条件网关时容易误以为条件仍有效。建议在类型转换或编辑面板中解释/清理失效配置。
- 实际选中并行网关的输出连线，右侧“流转条件”仍可选“表达式”和“默认流”；默认流说明仍固定写“一个排他网关只能有一个默认流”。并行分叉不按条件选路，这两个选项对当前来源类型有误导性。建议按来源网关类型禁用或说明其执行语义。
- 并行流程的最后一个审批提交后，列表曾短暂显示“运行中”但任务为空；详情已为“已完成”，重新查询列表后同步为“已完成”。建议完成事件触发列表刷新时等待最终投影，避免暂时矛盾。
- 包容网关条件从旧并行流程切换回来时，连线面板仍能显示旧的 `conditionGroupConfig`；实际 `conditionExpression` 为空。此配置缺陷已通过面板告警和发布预检阻断修复，后续可再优化类型转换时自动保留/恢复条件（应让用户明确检查）。
- 条件标签紧挨任务节点时，点击连线标签可以选中连线但右侧配置面板不总能切换到连线；把任务节点拖远后较容易选中线段。建议扩大连线标签的选中区域或让标签点击稳定打开连线设置。
- 在 r13 转换回包容后，点击金额条件标签再点击短线段，连线名称在画布和 XML 中意外变空；已通过面板重填“金额大于1000”恢复。建议检查设计器对单击标签及后续点击的编辑提交行为，避免误清除名称。
- 包容网关默认流的说明文案仍固定为“一个排他网关只能有一个默认流”，当前网关明明是包容，容易误解。建议按来源网关动态显示说明。
