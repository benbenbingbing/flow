# wfpack 语义校验修复及回归（2026-11-11）

已按 [七项反例评估](wfpack-seven-cases-assessment-2026-11-11.md) 修复五类校验缺口。原始 S08、S09、S13、S15、S16、S18、S23 在创建导入批次之前被拒绝，人工确认文件来源不能豁免这些检查。

## 修改后的行为

| 对应用例 | 修复规则 | 错误位置 |
| --- | --- | --- |
| S08 / S09 | `sourceVersion` 必须为 JSON 正整数，范围 1～2147483647；拒绝缺失、null、小数、字符串、布尔值及越界数值 | 上传解包时指明资产文件及 `sourceVersion` |
| S13 | 清单 `snapshotSchemaVersion` 与正文 `schemaVersion` 均须是受支持版本，并且相等；保留快照版本 1、2、3 | 上传时区分“不支持的快照版本”和“快照版本不一致” |
| S15 / S16 | `packageNo` 必须是非空字符串，最多 100 个 Unicode 字符；拒绝首尾空白、控制字符及假编号字符串 `null`；原样保留合法编号 | 上传时明确提示 `packageNo` 约束 |
| S18 | 按资产类型核对分区白名单；未知分区、跨类型分区、合法与未知混用、`full=true` 夹带非法分区均拒绝 | 上传或导出选择处理时列出对应可选值 |
| S23 | `dependencies.json` 必须存在且是完整 JSON 数组；每项为包含非空字符串 `type`、`key` 的对象；可选 `required`、`targetOnly` 必须是布尔值 | 上传时指明文件或条目位置 |

主要实现位于 `ConfigMigrationPackageCodec` 与新增的 `ConfigMigrationPackageValidation`。语义校验在导入服务查询重复批次、查询目标配置以及创建批次之前完成，因此非法包不会新增导入批次、条目或迁移基线。

选择范围保留已有 Excel、接口扩展及旧 `dataSources` 别名，并保留已实现的底层分区名。附加依赖清单只补结构校验，实际依赖解析仍以资产快照为准；没有新增未经定义的汇总清单逐字节一致性要求。包格式仍支持 3、4。

## 真实 API 回归

临时环境为 MySQL 8.0.27（13313）及隔离应用（18094，管理端口 18194）。从空 schema 顺序完成 129 个 Flyway 迁移，失败数为 0。

| 目标状态 | 异常包验证 | 结果 |
| --- | --- | --- |
| EMPTY：尚未导入任何迁移包 | 原始 7 包 × 未确认/已确认来源 | 14 / 14 返回 HTTP 400、业务码 400 |
| UPGRADE_PENDING：先合法导入较早实体配置，等待正常源包升级 | 同上 | 14 / 14 返回 HTTP 400、业务码 400 |
| CONSISTENT：完成正常源包升级，目标内容一致 | 同上 | 14 / 14 返回 HTTP 400、业务码 400 |

**42 / 42 个异常上传请求通过。** 每次请求前后比较导入批次、条目、迁移基线及业务配置指纹，均无变化。业务指纹包含流程、实体、表单、节点、迁移资产和物理业务表清单；批次文件原文用数据库 SHA256 比较。失败请求可能产生正常的审计记录，未将审计表作为“不写入”的判断范围。

四个正常 API 场景全部通过：

1. 历史格式 3 完整包在空目标首次导入并发布。
2. 正常完整包升级；核对实体名称确实由较早内容更新到源内容。
3. 当前应用实际导出格式 4 完整包，再导入并发布。
4. 当前应用实际导出格式 4 的 `main` 表单局部包，确认只包含所选资产/表单，再导入并发布。

另验证正常跨环境包未确认来源时仍返回确认提示，且不创建导入记录。结束前无 `PUBLISHING` 条目。
