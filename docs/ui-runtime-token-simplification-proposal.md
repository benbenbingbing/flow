# 表单与列表运行时令牌简化方案

状态：已采用，实施说明见 [无配置令牌运行时](ui-runtime-without-config-tokens.md)。日期：2026-10-12。

## 建议

取消前端携带、复制和续期表单/列表配置解析令牌的机制。运行时请求只提供业务定位信息，由后端统一读取有效发布配置、核验访问来源与操作权限。写操作保留一个不带签名、没有有效期的配置摘要，用于识别页面打开后配置发生变化。

不引入新的页面会话 ID 或另一种上下文令牌来替换旧令牌。登录会话和 Embed 接入认证继续使用现有机制。

## 当前事实与边界

- 表单已经取消业务版本，`entity_form_published` 保存当前发布配置；旧协议仍用 `releaseId` 传配置摘要，`releaseVersion=1` 作兼容占位。
- 列表当前仍保留 LIST 发布历史、历史激活，以及关联内容和 Embed 固定列表配置的行为。删除列表解析令牌与取消列表历史是两个独立决策。
- 当前表单解析令牌同时承载用户、任务、记录、父子页面、Embed 会话边界、配置依赖摘要和到期时间。普通列表请求并非全部需要令牌，固定列表与嵌入场景依赖较重。
- 最近的审批报错来自旧流程绑定版本与当前表单令牌混用。删令牌能减少这一类组合错误，但要同时替换后端仍依赖令牌的上下文恢复逻辑。

## 目标行为

| 场景 | 客户端提供的业务定位信息 | 后端权威校验及配置选择 |
| --- | --- | --- |
| 普通表单 | 表单 ID、记录 ID、操作标识；有受限来源时补来源入口 | 表单已发布、实体归属、当前用户可访问记录、字段及操作权限 |
| 普通列表 | 实体编码、列表标识、查询或按钮标识 | 当前发布列表、访问权限、数据范围、固定过滤和按钮权限 |
| 任务审批/加签 | 任务 ID、操作标识和待提交数据 | 实时查询任务，确认可办理人；从任务推导实例、实体、记录、节点及允许的表单 |
| 流程只读详情 | 实例 ID、必要的历史节点标识 | 实例读取权限、实际绑定记录、节点归属、只读能力；不靠普通实体权限替代流程读取权限 |
| 子表单/关联内容 | 已授权根入口、稳定节点/关联编码组成的路径、必要的行定位信息 | 从根入口逐层查询有效配置，确认引用边与实际数据关系；逐层保持数据范围、只读限制和深度约束 |
| Embed 页面 | 现有 Embed 认证和业务定位信息 | 从服务端会话、视图授权及绑定关系选配置；核验允许的实体、字段、动作和记录范围 |

以上都是定位信息，不能单凭客户端传入的 `mode=approve`、`taskId`、`formId` 或某条路径授予权限。任务完成、撤回、转办或权限变更后，下一次请求立即按实时权限处理。

列表按钮的目标表单和动作应从服务端的 `listKey + buttonId` 配置取得；字段事件和数据源只执行当前配置声明的绑定。关联内容按来源记录与关联编码重新生成固定筛选，与用户查询条件取交集；子记录、候选记录及绑定/解绑操作都须重新校验实际关系，不能直接信任客户端目标记录或过滤条件。

嵌套页面只有真正需要表达来源时才携带路径，普通表单与列表不增加额外必填上下文。任意 URL、客户端指定历史发布版本和客户端提供的授权结果均不能参与运行配置选择。

## 配置更新与旧页面

建议复用现有内容/依赖摘要，对外归一为一个 `configHash`：

- 页面加载时返回摘要；摘要覆盖本次操作依赖的根配置及嵌套配置，单独更新子表单也能被识别。
- 读取请求由后端解析有效配置，不要求携带配置令牌或续期。
- 保存、审批提交、删除、导入、动作执行，以及可能有副作用的字段事件或接口调用，在执行任何副作用前比较摘要。不按 GET/POST 简单区分，按操作能力确定是否检查。
- 不一致时保留已填写内容，返回 `409 FORM_CONFIGURATION_CHANGED` 或对应列表错误，提示重新加载并核对；不自动重放写请求。
- 已受理请求在本次执行/事务中复用同一份配置，避免执行到中途因发布而切换规则。继续利用 `CurrentFormRuntimeContext`，必要时将同类机制覆盖到列表。

摘要无需签名、续期、绑定用户或服务器保存页面会话，也不允许客户端凭它选择旧配置。权限仍由后端实时校验。记录本身的乐观锁和请求幂等机制继续独立工作。

如果完全去掉摘要，系统就会始终按提交时的新配置执行。用户看到的按钮、可编辑字段与实际执行规则可能不同；这项行为变化不建议作为默认方案。

## 列表发布策略

本次建议保留列表已有的发布历史与回滚管理能力，先去掉浏览器参与发布坐标选择和令牌传递：

- 普通列表使用当前发布配置。
- 当前有固定列表语义的关联内容/Embed，由后端根据已授权宿主或会话找到绑定的发布记录，不接受浏览器自行选择发布版本。
- 如果产品下一步决定列表也统一读取当前配置，再单独清理历史激活、固定列表依赖及存储结构。不要在去令牌时隐式改变既有列表范围和按钮行为。

## 实施顺序

1. **统一后端解析与授权入口。** 建立一个供表单事件、动作、数据源、校验、数据保存和列表操作共用的运行时上下文解析器。复用现有任务访问、流程读取和实体数据权限服务；集中解析，避免每个业务接口各写一套规则。其输出只在服务端请求/事务内使用。
2. **先改普通页面和审批。** 加载、按钮解析、字段事件、数据源、唯一性/跨字段校验、保存与审批提交统一走新入口；对外改用稳定业务标识和配置摘要。覆盖 PC、移动端和共享 API/Core 包。
3. **改子表单、关联内容与 Embed。** 用逐层权威解析替换父子令牌、签名来源行和遍历上下文。在证明所有原有范围约束仍成立后，停止这些页面配置令牌的签发和接收。Embed 登录与委托会话认证继续保留。
4. **收尾清理。** 删除旧配置令牌字段、签发/验证分支、TTL 设置、自动续期器、临时兼容 DTO 和失效诊断。服务端内部可保留列表发布 ID；审计也可保存受理时的配置摘要，不再回传供客户端选择。

迁移期间旧接口若仍接收令牌，必须维持原验证，不能直接忽略旧令牌后放宽历史配置入口。新接口只在替代授权链完整时开放；PC、移动端、Embed SDK 和自定义扩展同时核对协议，避免长期维护两条解析链。

## 验收标准

- 新协议无需任何表单/列表配置解析令牌；页面停留不再发生此类令牌到期或续期失败。
- 审批、加签、转办后的旧页面、普通新建编辑、流程历史只读、字段事件、动作、数据源、子表单、关联列表和 Embed 均可正常使用。
- 替换他人的任务/记录、切换未授权表单或列表、跳过父级路径、越过关系范围、跨 Embed 会话、通过只读入口发写操作均被拒绝。
- 配置发布后旧页面的写操作在产生副作用前被拦截，并保留输入；只改子表单同样有效。
- 审批人只有任务权限而没有普通列表权限时，合法审批仍可执行；只读流程参与人仍能按流程读取权限查看。
- 不通过重新发布旧流程、修改旧流程 JSON 或数据库补数据来使页面恢复正常。

## 代价和范围

这是一次跨前后端协议调整，主要工作量在嵌套页面和 Embed 的授权来源恢复。收益是删除令牌复制、串用、过期、续期和版本占位的复杂链路；代价是每次请求需要服务端定位和校验上下文。优先复用同一次请求的解析结果，仅缓存配置数据，不跨请求缓存用户授权结论。

普通页面/审批的第一阶段不需要变更数据库结构。后续若清理存储字段或列表历史，另行检查依赖，并按仓库要求新增更高版本迁移；现有 Flyway 迁移保持不变。

本文保留原方案与取舍；实际协议及删除范围以实施说明为准。

## 代码依据

- `UiReleaseResolutionTokenService`：现有签发、过期、用户/Embed 绑定与配置依赖校验。
- `UiConfigReleaseService`：任务令牌校验、流程只读上下文恢复、表单事件和固定列表解析。
- `EntityFormActionService`：任务办理、普通数据访问与流程只读访问的不同授权入口。
- `UiViewCompositionRuntimeService` / `UiViewCompositionTokenService`：来源行及多层关联访问上下文。
- `EntityListPublishedRuntimeService`：普通当前列表与固定列表配置的运行选择。
- `CurrentFormRuntimeContext`：请求内配置一致性与根/子表单摘要。
- `packages/workflow-api/src/releaseTokenRenewal.js`：当前前端令牌发现、续期及身份比较链路。
- `docs/form-global-publish-without-versions-implementation.md`：表单去版本化已落地边界，列表历史仍保留。
