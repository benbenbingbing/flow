# 实体字段内嵌选项停用

2026-11-16 起，实体选择字段（SELECT、MULTI_SELECT、RADIO、CHECKBOX）只允许绑定系统代码表。表单组件还可使用已配置的动态数据源。

本次移除了以下历史兼容路径：

| 范围 | 原兼容行为 | 当前规则 |
|---|---|---|
| 实体设计及保存接口 | 旧内嵌选项面板、`optionsJson` 与结构化 `options` 双写 | 移除面板；接口拒绝提交内嵌选项；选择字段必须绑定代码表 |
| 表单设计和节点保存、发布 | 从实体或字段复制 JSON 到 `componentProps.options` | 拒绝持久化内嵌候选，要求移除旧配置后重新配置来源 |
| PC、移动端和子表单 | 从字段 `options`、`optionsJson`、`componentProps.options` 三路兜底 | 控件只消费宿主解析的代码表或动态候选；没有来源时不读取旧配置 |
| 列表展示、查询和固定筛选 | 解析旧 JSON 生成候选或名称 | 使用代码表解析结果；没有名称时保留原始存储编码 |
| 顺序流与条件编辑器 | JSON/组件属性选项兜底 | 实体候选只取绑定代码表；审批结果选项保持其独立业务配置 |
| 流程实体字段赋值 | 从发布快照里的旧 JSON 读取合法值 | 必须使用代码表，未绑定时明确报错 |
| 版本展示与冻结 | 查询旧字段选项表或 JSON 生成名称 | 新快照只从代码表获取名称；已经冻结的历史版本不重算、不回写 |
| 配置迁移和项目模板 | 构建包时把字段 JSON 复制为表单静态候选 | 导入及构建入口拒绝旧格式；项目模板的 46 个选择字段改为独立代码表资产 |

## 历史数据处理

- 按用户选择保留历史数据，不批量转换、不删除旧列或旧选项表，不改写已有业务值和历史快照。
- `entity_field.options_json`、`entity_form_field.options_json`、`form_field_config.options_json` 和 `entity_field_option` 留在数据库中，退出选项读取和写入协议。实体字段删除时仍清理其历史从表记录，避免孤儿数据。
- API 中保留的旧输入属性只用于识别并拒绝旧客户端请求，不再作为兼容入口输出或执行。
- 存量未绑定代码表的选择字段必须重新配置后才能保存、发布；系统字段和已发布字段原有结构锁定规则继续生效。
- 运行时仍需要传递代码表、系统状态或动态数据源解析得到的 `options` 数组；它们是当前请求的候选结果，不是可持久化的实体内嵌配置。
- 表单字段投影通过 `runtimeOptions` 传递本次解析结果，不能把旧发布快照里的 `field.options` 数组当作运行时结果继续使用。
- 审批动作选项、系统流程状态枚举、自定义组件自身业务参数以及专用级联/数据选择协议属于独立功能。

## 项目示例包

- 当前示例源配置统一使用 `dictType`；46 个代码表定义位于 `workflow-server/biz-project/src/main/resources/project-config/assets/dictionaries.json`。
- 新示例包为 `project-f01-f07-v4.wfpack`，包含 46 个代码表、15 个实体及 5 个流程资产。构建不再转换内嵌 JSON，出现旧格式时直接报错。
- V1/V2/V3 包仅保留为历史制品，包含旧内嵌配置，不能作为当前导入发布输入；应使用重新配置并生成的 V4 包。未修改目标环境中的历史业务数据和已有发布记录。

## 数据库迁移

本次无 SQL 或 Java 迁移新增、修改、删除，数据库结构和系统种子数据保持不变。历史 Flyway 迁移保持不可变。
