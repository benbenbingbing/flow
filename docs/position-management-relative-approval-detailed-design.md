# 职务管理与相对组织审批

2026-11-12：本设计已按 V130 收敛为职务字典和当前人员关系，替代原带时间区间的任职管理设计。

## 产品范围

流程平台只需知道谁在什么组织担任什么职务。维护职务名称、稳定编码、启停、适用组织类型及单人/多人规则；不管理任职履历、生效区间、未来预约、转任、撤销原因、主职、任职排序或任命批次。

## 数据与页面

- `sys_position` 保存可跨组织复用的职务字典，编码创建后不可修改或复用，不自动授予权限。
- `sys_position_assignment` 保存当前人员、组织、职务关系，三元组唯一；9 个字段的完整设计见 [数据库设计](sql/database-design.md#93-sys_position_assignment-当前组织职务人员关系表)。
- `sys_position_assignment_batch` 已由 V130 删除，相应 Mapper、Record、批量预检及幂等回执代码退役。
- 职务管理提供字典与当前人员查询，按组织选择职务并保存当前人员集合。用户管理默认带入归属组织，可设置和移除本人职务。组织管理可直接设置负责人或其他职务人员。
- 页面只需选择组织、职务和人员，保存立即生效；不再要求预检、原因或时间。

## 写入接口与并发

- `PUT /api/system/position/assignments`：`positionCode`、`organizationUnitId`、`userIds`、`expectedUserIds`。完整替换当前集合，空集合清空。
- `DELETE /api/system/position/assignments/{id}`：携带 `revision` 移除当前关系。
- `POST /api/system/org/{unitId}/leader`：`userId`、`expectedUserIds`，复用当前关系保存服务，空用户清空负责人。
- 组织、用户维度及分页查询接口只返回当前关系，不接受历史和有效期查询条件。
- 删除 `/precheck`、`/batch`、`/{id}/revoke`、`/{id}/update-period` 等生命周期接口。
- 保存时先按职务、组织、用户顺序加锁，使用锁定读获取最新集合，防止 MySQL REPEATABLE_READ 下读取旧快照。集合冲突返回 409，相同目标集合重复提交不重复创建。
- 校验功能权限与组织数据范围、对象启用状态、人员归属和单人限制，保留数据库唯一约束及外键。

## 审批语义

流程发起时冻结组织链，节点激活时从当前关系查询人员。保留本级、固定上级、最近有人员的上级、业务层级四种定位方式及设计器试算。

直接分配使用 `ERROR`，只允许唯一人员；候选人及多实例使用 `ALL`。为读取既有部署，旧 `PRIMARY_OR_ERROR` 解析为 `ERROR`，多人时报错，不会随意挑人；新界面和扩展描述仅提供新策略。已生成任务保持原办理人，审批历史由流程自身保存。

负责人 `UNIT_LEADER` 仍是单人职务，保存关系时同步旧负责人字段。投影显示当前设置，运行时过滤停用人员及组织；删除仅为预约生效而存在的定时对账任务。

## 升级与验证

只新增 V130 Java 迁移，V069/V070 及其他历史文件不修改。先复制切换时刻当前关系并验证约束，再替换旧表，删除批次表。历史及未来预约不进入新模型，旧未来预约不会提前生效；单人职务出现多名当前人员时中止升级。通过暂存表及元数据检测支持非事务 DDL 中断后的继续执行，不执行 Flyway repair 或 baseline。

七种空库脚本同步至 V130，最终 199 张表、2,783 个字段。当前测试和实际数据库覆盖范围见 [SQL 初始化说明](sql/README.md)。
