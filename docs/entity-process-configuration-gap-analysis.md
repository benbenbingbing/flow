# 实体配置与流程配置功能完善度分析

> 分析日期：2026-08-20  
> 分析范围：实体定义、表单配置、列表配置、数据权限、发布版本、BPMN 流程设计、节点配置、流程发布和运行治理。

## 1. 总体结论

实体配置整体已经达到“较完善”水平，流程配置的建模能力也比较丰富。当前最需要补充的不是更多字段控件或 BPMN 图元，而是：

- 发布前校验与影响分析；
- 多人编辑冲突控制；
- 数据权限的安全默认值；
- 实体结构变更的数据一致性；
- 跨实体、表单、列表、流程的一体化发布；
- 配置完成后的测试、监控与运维闭环。

其中，流程配置的发布治理明显弱于表单和列表配置，应优先补齐。

## 2. 功能审计结果

| 范围 | 当前完整度 | 已有能力 | 主要不完善点 |
| --- | --- | --- | --- |

## 3. P0：优先解决安全性和发布可靠性

### 3.1 流程发布预检中心

增加和表单、列表一致的 `diff`、`publish-preview`、`validate` 接口，发布前输出：

- BPMN 错误所在节点或连线；
- 无办理人、循环引用、错误表达式、无默认分支；
- 表单版本、实体状态、动作、接口服务等依赖问题；
- 当前运行实例和受影响版本数量；
- 阻断项、警告项和对应修复入口。

当前流程接口基本是直接发布，参见 [ProcessDefinitionController.java](../workflow-server/workflow-process/src/main/java/com/workflow/process/definition/api/web/ProcessDefinitionController.java#L150)，没有表单和列表已有的预览闭环。

### 3.2 流程草稿 revision 与冲突处理

给流程定义增加 `revision`、`expectedRevision` 和 `draftHash`：

- 防止多人或多标签页覆盖整份 BPMN；
- 冲突时展示服务器版本、本地版本和共同基线；
- 区分“线上已发布”和“存在未发布草稿”；
- 列表状态显示“已发布，有待发布修改”。

目前 [ProcessDefinitionDTO.java](../workflow-server/workflow-process/src/main/java/com/workflow/process/definition/api/response/ProcessDefinitionDTO.java#L20) 没有草稿 revision，而表单节点和列表项已经使用 revision。

### 3.3 数据范围改为安全默认值

未绑定规则时不要静默放开全部数据，建议提供三种显式状态：

| 模式 | 含义 |
| --- | --- |
| `DENY_ALL` | 默认拒绝访问 |
| `PERSONAL` | 默认仅本人创建或提交的数据 |
| `EXPLICIT_ALL` | 管理员明确确认允许全部数据 |

当前手册说明未绑定允许规则时可能看到全部数据，参见 [entity.js](../workflow-web/src/data/user-manual/entity.js#L444)。这是最应优先调整的默认行为之一。

### 3.4 实体结构一致性与唯一性保障

增加结构发布状态机和修复入口：

```text
METADATA_SAVED
  -> DDL_PENDING
  -> DDL_RUNNING
  -> SCHEMA_CONSISTENT
  -> DDL_FAILED（可重试、可生成修复计划）
```

DDL 失败后应支持重新执行、比对真实表结构和生成修复计划，避免要求管理员自行检查日志和数据库。

动态表目前不按业务字段创建数据库唯一索引，参见 [DynamicTableService.java](../workflow-server/workflow-entity/src/main/java/com/workflow/entity/data/application/DynamicTableService.java#L494)。应用层唯一性检查存在并发竞争风险，建议根据字段类型采用数据库约束、唯一值占位表或带锁校验。

### 3.5 HOTFIX 风险治理

表单 HOTFIX 的 `REVIEW` 变更采用“高风险提醒但不引入人工审核”的方式：

- 展示具体风险并二次确认；
- 保留 HOTFIX 专用权限和配置对象访问校验；
- 影响实例抽样预览；
- 草稿漂移、影响范围变化或技术不兼容时仍阻断；
- 发布后自动观察窗口和一键回滚。

目前 REVIEW 主要是风险提示，不形成额外阻断，参见 [entity.js](../workflow-web/src/data/user-manual/entity.js#L1306)。

### 3.6 应用级发布候选

把实体结构、表单、列表、数据范围、流程、菜单权限和接口依赖组成一个 Release Candidate：

- 自动生成依赖图；
- 一次性预检；
- 明确发布顺序；
- 统一迁移标记；
- 部分失败时停止后续发布；
- 输出完整发布报告。

当前这些资产虽然都支持版本或迁移，但仍需要管理员分别保存、发布和核对。

## 4. P1：补齐配置体验和运行闭环

### 4.1 BPMN 专用配置面板

增加消息、定时、条件、信号、边界事件、调用活动和事件子流程的专用配置面板。当前部分类型仍依赖 XML 和人工兼容性验证，参见 [process.js](../workflow-web/src/data/user-manual/process.js#L256)。

建议每种事件至少覆盖：

- 事件名称或消息标识；
- 时间表达式及可视化测试；
- 是否中断宿主活动；
- 输入输出变量；
- 超时和异常路径；
- 目标环境依赖检查。

### 4.2 空办理人策略

动态办理人解析可能返回空集合，应支持按流程或节点选择：

- 阻断发布；
- 创建运行 incident；
- 转交管理员组；
- 使用指定兜底人员；
- 等待人工修复后重试。

不能只依靠上线前人工验证，否则流程可能进入无人可办状态。

### 4.3 节点操作矩阵

按用户任务节点配置是否允许：

- 审批和驳回；
- 转办；
- 加签及加签类型；
- 人工知会；
- 撤回；
- 终止；
- 是否必须填写原因；
- 对应权限码和适用条件。

当前运行时已经具备多种任务操作，参见 [processTask.js](../workflow-web/src/api/processTask.js#L88)，但缺少统一的节点级配置矩阵。

### 4.4 实体业务数据批量导入中心（不同于配置迁移）

现有“配置迁移”已经实现，而且是较完整的配置资产迁移中心：支持选择与校验已发布快照、生成和下载 `.wfpack`、上传校验、环境差异分析、依赖及映射处理、发布与回滚。其迁移对象包括实体定义、表单/列表等实体快照、流程、系统实体 UI、字典、工作日历和 SLA 策略，参见 [ConfigMigration.vue](../workflow-web/src/views/system/ConfigMigration.vue#L6) 和 [ConfigMigrationController.java](../workflow-server/workflow-migration/src/main/java/com/workflow/migration/api/web/ConfigMigrationController.java#L38)。因此，**配置迁移本身不是缺失功能**。

本节所指的是另一类能力：把 Excel/CSV 中的一批业务记录导入某个动态实体，即向运行期 `biz_*` 业务表写入数据。配置迁移页面也已明确说明“不包含业务数据、系统表结构和运行台账”。两者边界如下：

| 能力 | 迁移对象 | 典型用途 | 当前判断 |
|---|---|---|---|
| 配置迁移 | 实体/表单/列表/流程等已发布配置快照 | 在开发、测试、生产环境之间交付应用配置 | 已具备，不应列为缺口 |
| 实体业务数据批量导入 | 客户、合同、项目等实体的实际业务记录 | 存量数据初始化、主数据装载、日常批量录入 | 当前仅发现导出，未发现通用导入入口 |

如果平台存在存量系统切换、主数据初始化或用户批量录入场景，可增加：

增加：

- 模板下载；
- 字段映射；
- 枚举、用户、部门和实体引用解析；
- 数据预检；
- 分批导入；
- 失败行下载；
- 幂等键；
- 导入任务进度和审计日志。

当前实体数据 API 有业务记录导出但未发现对应的通用导入接口，参见 [entity.js](../workflow-web/src/api/entity.js#L229)。如果产品明确不承担业务数据初始化和日常批量录入，则本项可以降为 `P2` 或从建设范围移除。

### 4.5 统一配置测试中心

以测试数据和模拟身份串联验证：

- 表单初始化、联动、计算和提交；
- 列表查询、按钮条件和数据范围；
- 流程分支条件和默认流；
- 办理人、会签、或签和下一审批人；
- 流程动作、失败策略和重试；
- SLA、工作日历和升级策略。

现有列表数据范围模拟、下一审批人预览和工作日历模拟可以作为统一测试中心的基础能力。

### 4.6 表单多终端与无障碍能力

建议增加：

- 桌面、平板、手机三种预览；
- 断点级栅格宽度和字段顺序；
- 多语言标签、选项、占位符和校验提示；
- 字段标签、键盘顺序、焦点和错误提示检查；
- 颜色对比和动态状态播报检查；
- 按创建、编辑、查看、审批模式和用户角色预览。

### 4.7 收口字段事件配置

当前仍有填写 JavaScript 的旧字段事件编辑器，参见 [EventConfigPanel.vue](../workflow-web/src/components/EventConfigPanel.vue#L9)，但新运行时走受控事件绑定 API。

建议：

- 将旧事件代码标记为 legacy；
- 提供迁移报告；
- 统一迁移到受控事件、接口服务和输入输出映射；
- 删除容易让配置人员误解的代码执行入口；
- 发布时阻断仍引用未迁移事件代码的配置。

### 4.8 通知渠道

发送任务建议接入：

- 邮件；
- 短信；
- 企业微信；
- 钉钉；
- Webhook 或消息队列。

各渠道统一使用模板、变量 Schema、限流、失败重试、幂等键、送达记录和告警。

## 5. P2：增强平台竞争力

### 5.1 列表个人视图

允许最终用户保存：

- 筛选条件；
- 排序；
- 列宽和列顺序；
- 显示列；
- 默认视图；
- 团队共享视图。

### 5.2 列表聚合和多视图

增加合计、平均、分组、小计、图表、看板和日历视图。聚合应在服务端执行并继续受数据范围控制。

### 5.3 字段索引向导

根据列表查询、固定过滤和排序配置，建议：

- 普通索引；
- 联合索引；
- 索引字段顺序；
- 不适合索引的字段；
- 发布前执行计划和预估扫描行数。

### 5.4 配置协作

增加：

- 表单设计撤销/重做；
- 配置分支；
- 草稿比较；
- 评论和设计评审；
- 配置变更审批；
- 定时发布和发布窗口。

### 5.5 流程实例版本迁移

支持管理员选择满足条件的运行实例迁移到新流程版本，并提供：

- 活动节点映射；
- 变量兼容检查；
- 表单 release 兼容检查；
- 干运行；
- 分批迁移；
- 失败回滚和审计记录。

### 5.6 配置使用关系查询

提供“配置资产被谁引用”能力，例如：

- 字段被哪些表单、列表和流程条件引用；
- 表单被哪些流程节点引用；
- 列表被哪些菜单、子列表和选择器引用；
- 状态被哪些连线、按钮和权限规则引用；
- 接口服务被哪些数据源、事件和流程动作引用。

### 5.7 表单细节补齐

为 `TAB_SET` 增加默认激活页配置。当前明确不支持该配置，参见 [entity.js](../workflow-web/src/data/user-manual/entity.js#L712)。

## 6. 推荐实施顺序

1. 补流程发布预检、revision、数据权限安全默认值和结构一致性。
2. 建设应用级发布候选、统一测试中心和 HOTFIX 风险提示与运行观察。
3. 补 BPMN 专用面板、办理人兜底和通知通道；存在存量数据初始化或批量录入需求时，再建设实体业务数据批量导入中心。
4. 建设个人视图、聚合、配置协作和实例迁移。

近期不建议优先继续增加普通字段控件或更多 BPMN 图元。现有扩展能力已经较丰富，可靠发布和运行闭环带来的收益更高。

## 7. 审计步骤与健康度

| 步骤 | 检查内容 | 健康度 | 说明 |
| --- | --- | --- | --- |
| 1 | 本地平台入口 | 正常，但受登录阻断 | 登录页渲染正常；仓库不提供默认凭据，因此未绕过认证 |
| 2 | 实体配置能力 | 较好 | 基于实体设计模型、表单、列表、API、发布模型和当前用户手册完成 |
