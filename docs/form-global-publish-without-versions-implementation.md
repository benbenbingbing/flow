# 表单统一发布实施记录

实施日期：2026-10-08。V113 首次启动失败经修复后，用户已自行完成 V112/V113；只读查询确认两个版本均成功。代码经过迁移副本验证、发布回归及启动健康检查。以下记录首次启动及后续发布问题的修复过程；本次没有维护实际 Flyway 状态或对实际业务库执行迁移。

## 已实现的行为

- 保留草稿保存、差异预览、发布预检和撤销未发布修改；保存草稿不影响线上。
- 发布只覆盖 `entity_form_published` 中对应 `form_id` 的一行，不生成、递增或选择表单版本。相同内容重复发布复用当前配置。
- 新建、流程发起、运行中任务、历史详情、子表单、列表表单按钮、关联内容和已有 Embed 会话均读取当前配置，不要求重发流程、父表单或 Embed 视图。
- 表单设置和子表单设计器移除版本信息与版本选择；统一发布界面不再提供热修复。表单历史、激活和热修复撤回路由退役，热修复治理控制器、服务、Mapper、观察与流程影响 Port 已删除。
- 列表、流程、实体定义和组件实现保留各自的发布机制，本次只取消表单配置的版本机制。

## 发布与运行边界

内容摘要用于完整性、并发前置条件和旧页面检测，不是表单业务版本。`configHash` 覆盖根表单和子表单依赖；任务、记录、父子关系和 Embed 范围每次请求由后端根据业务定位重新核验。配置解析令牌已移除。

页面不再维护配置授权时限或自动续期。配置变化时保留未保存输入并提示重新核对，写请求不自动重放。详见 [运行时协议](ui-runtime-without-config-tokens.md)。

旧页面提交会返回 `409 FORM_CONFIGURATION_CHANGED`，提示保留填写内容并重新加载核对。已通过校验、开始执行的请求在自己的请求/事务上下文内复用受理配置，防止事件执行后切换规则或重复执行副作用；下一次请求重新读取当前发布。

发布和删除使用共享事务锁，列表发布、历史激活也共享该锁，避免跨表单/列表包含图的并发竞态。发布前校验节点、字段、参数契约及子表单引用图；候选行写入后在同一事务内重新校验直接或传递受影响的已发布关联内容及历史列表，失败整体回滚。表单依赖按稳定身份、列表依赖按固定发布记录追踪；无关旧配置不参与本次发布校验，既有关系保留已发布语义，新草稿和列表历史激活仍遵循统一关系规则。删除保护覆盖当前父表单、列表、已发布流程和 Embed 的稳定身份引用。

默认表单单独保存在按实体唯一的 `entity_form_current_default`。草稿默认开关不影响当前默认入口，发布事务同步更新选择。

唯一占位改用规则语义摘要，布局、显示名称、提示文本和预检开关变化不会切换命名空间。旧占位属于旧命名空间；跨表单 value gate 和业务数据权威复查仍参与最终提交校验。

## 兼容边界

运行时公共请求使用稳定表单身份、`configHash` 与普通 `runtimeContext`，不再要求浏览器传表单版本占位值。旧流程 JSON、Embed 服务端绑定和审计中的内部发布坐标按原有兼容规则读取；不保存或递增表单业务版本。

旧流程 JSON 中的表单版本坐标不参与运行选择；新流程发布仅保存稳定 `formId`。V113 先归档旧 FORM 发布记录，用户确认后由 V114 删除这些记录；发布审计仍保留。运行 Mapper 始终读取当前配置。配置迁移包按实体编码和 formKey 表达稳定子表单引用，导入按依赖顺序发布当前配置；旧固定版本包需要重新导出。

`legacyProps/legacyPropsDocument` 仅作兼容追溯，不进入运行依赖摘要和稳定引用检查。手工弹窗、抽屉等业务导航允许导航环，自动包含与子表单嵌套仍限制循环和八层深度。

## 发布迁移资产来源键超长的修复

发布 `ZDW_FINAL_form002` 时再次出现“字段内容过长，请缩短后重试”。后端日志明确报出 `config_migration_asset.source_history_id` 超长：自定义实体 UI 资产仍使用 `releaseId + ":v" + nextVersion`，而表单当前内容摘要已有 64 字符，拼接后的来源键至少 67 字符。数据库字段仍为 `varchar(64)`，表单配置本身及发布说明没有超长。

`ConfigMigrationAssetService.entityUiAssetSourceKey` 保留长度不超过 64 的既有来源键；超长组合对完整的配置身份和迁移资产序号取 SHA-256，避免截断丢失去重维度。系统实体表单同样使用该组合键，防止 A → B → A 时因内容摘要相同错误复用第一次 A 的完整实体 UI 资产；系统实体列表继续使用原有发布 ID 去重。迁移资产序号只服务导出快照，不恢复表单业务版本或历史运行选择。

新增 `CurrentFormPublishAssetDatabaseTest` 在 H2 上执行完整的 FORM 发布方法、实际快照生成和真实 Mapper 写入。旧实现能够复现相同的 67 字符超长异常；修复后覆盖自定义实体与系统实体发布、A → B → A、相同内容幂等、当前表单单行覆盖，以及资产依赖登记失败时当前配置、默认入口、owner 指针、审计和资产整体回滚。测试表定义直接读取未修改的 V001，保留真实列宽、非空及唯一约束，只转换 H2 不支持的存储语法。

来源键、完整发布事务、发布服务、当前配置 Mapper 和控制器共 81 项聚焦测试通过，0 失败、0 错误、0 跳过。本机 MySQL 只读核对确认 `source_history_id`、owner 的发布指针和发布审计引用均为 64 字符，V112/V113 均成功。本轮没有新增、修改或删除任何迁移文件，也没有修改真实表单草稿或执行实际发布。
