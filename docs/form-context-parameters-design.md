# 表单上下文参数设计

在字段默认值和计算公式里，允许直接选择「当前登录人」「流程发起人」「当前任务」等系统信息。例如，新建申请时自动填写申请人和所属部门，办理任务时按当前节点和申请金额计算审核金额。上下文由服务端按本次访问解析，字段是否填写、何时重算以及是否保存由表单规则决定。

## 配置方式

| 入口 | 配置操作 | 运行效果 |
| --- | --- | --- |
| 表单设置 → 上下文参数 | 查看内置参数、数据类型、可用入口及当前表单的引用位置 | 选中参数即可在字段配置里使用，系统自动识别依赖 |
| 字段属性 → 默认值 | 选择「上下文参数」，再选来源。可配置同类型备用值和适用入口 | 默认只在新建时填写一次。可显式启用「待办打开时预填空字段」，可编辑字段允许修改或清空 |
| 字段属性 → 值联动 → 计算公式 | 选择「插入字段」或「插入上下文参数」，选定适用入口 | 字段变化后重算。计算结果显示为只读，适用入口提交时由服务端生成 |
| 表单预览 | 切换普通新增、流程发起、待办办理、历史查看，填写模拟上下文 | 显示默认值、公式结果和缺失原因，预览值只存在于当前预览 |

「输入参数」继续用于上级页面、列表按钮或父表单主动传入的数据。上下文选择器按「当前登录人」「流程」「任务」分组，显示中文名及可用场景。例如，`task.nodeKey` 标注「待办办理时可用」，用户选择后即可插入公式。发布检查定位到具体字段和规则，如「申请人默认值引用了流程发起人，普通新增时该参数为空」。

### 配置示例

| 业务目的 | 配置 | 效果 |
| --- | --- | --- |
| 新建时自动填写申请人 | 「申请人」是系统用户引用字段，默认值选择「当前登录人 → 用户 ID」 | 打开表单时选中自己，可以改为另一个有权限选择的用户 |
| 自动填写申请部门 | 「申请部门」是系统部门引用字段，默认值选择「当前登录人 → 部门 ID」 | 使用身份目录里的部门归属。用户无部门时留空，由现有必填规则决定能否提交 |
| 审批时预填流程发起人 | 「联系人」是系统用户引用字段，默认值选择「流程 → 发起人用户 ID」，启用「待办打开时预填空字段」 | 只在联系人为空且节点允许编辑时预填，已有联系人优先 |
| 审批时按节点计算费用 | `IF(${ctx.task.nodeKey} == "finance_review", ${field.amount} * 0.03, ${field.amount} * 0.05)`，适用入口选择「待办办理」 | 修改金额时即时刷新结果。提交后保存服务端计算值，历史查看显示当时保存的值 |

## 参数目录

参数键是稳定协议，中文名称可更新。用户、部门、流程、任务的 ID 均用字符串传输；用户和部门引用保留具体引用类型，选择器使用现有机制解析展示名称。组织与部门按身份目录的各自归属读取，目录空值直接保留。

| 参数 | 含义及来源 | 可用条件 |
| --- | --- | --- |
| `actor.userId`、`actor.displayName` | 当前经过认证的实际操作者的系统用户 ID、显示名 | 有可映射的登录用户。授权嵌入使用会话映射用户 |
| `actor.departmentId`、`actor.departmentName` | 当前操作者的部门 ID、名称 | 操作者在身份目录有部门归属 |
| `actor.organizationId`、`actor.organizationName` | 当前操作者的组织 ID、名称 | 操作者在身份目录有组织归属 |
| `process.definitionKey`、`process.definitionName` | 本次流程的定义编码、发布名称 | 发起前已由服务端确定流程定义，或当前入口已关联流程实例 |
| `process.instanceId`、`process.starterUserId`、`process.starterName` | 指定流程实例的 ID、发起人的系统用户 ID 和显示名 | 已有且有权读取的流程实例。旧实例按已知旧格式解析发起人身份，无法唯一确认时返回空值 |
| `task.id`、`task.nodeKey`、`task.nodeName`、`task.assigneeUserId` | 当前办理任务的 ID、节点编码、节点名称、已指派的系统用户 ID | 有权办理的确切待办。候选任务未签收时，办理人参数为空 |

当前登录人每次打开和提交时从认证身份取得。流程发起人来自指定实例，任务办理人来自当前任务。转办、加签、代办和并行任务应沿用实际任务的权限与归属语义，同一个流程的不同待办可以得到不同任务参数。流程尚未启动时只有已确定的定义信息可用。普通实体入口使用它经授权实际关联的实例，重发和历史入口按各自所指的实例取值。按表单数据选流程时，选定结果出来前流程定义参数为空，避免试算结果反过来影响选路。

首期开放表中的标量参数。流程变量在有实际业务需求后按已发布声明逐项开放，要求指定类型、读取权限和适用入口。身份目录的完整资料、任意对象路径和第三方自定义上下文键均在首期受控目录之外。

## 运行规则

### 默认值

1. 上下文默认值默认适用于新建记录，包含通过新增表单发起流程。显式启用「待办打开时预填空字段」后，有办理权限的待办也会在打开时为可见可编辑的空字段预填一次，已有值始终优先。普通编辑、从独立入口重发已有记录和历史查看保持原值。
2. 已授权的入口预填和显式输入参数优先。显式 `null`、空字符串、`0` 和 `false` 都是已提供的值。字段未提供时，采用上下文值，再采用配置的备用值。已有 `FORM_OPEN`、`FORM_INIT`、`AFTER_LOAD` 继续按原流程应用其声明的回填，保留现有入口预填的最终优先级。上下文默认值启用后，该字段按新规则选取初值，原静态默认值可配置成显式备用值。发布时提示清理同字段的 `FIELD_DEFAULT` 数据源绑定。
3. 上下文解析完成后才开放编辑。用户改值或清空后，参数更新、异步回包和字段联动刷新均保留输入。撤销填写恢复本次打开时的初始值，重新打开则按当前上下文初始化。
4. 标准新建提交缺少这个字段时，服务端按同一规则补值。待办预填随页面值提交，待办提交省略字段时保留原值，避免无界面办理或仅提交审批意见时写入业务数据。显式清空按字段类型提交空值。以后重新打开待办时仍为空的字段可再次预填。已经填到可编辑字段里的默认值属于普通业务数据，仍要通过目标字段、引用范围和实体权限校验。「录入人必须等于登录人」这类规则继续由现有系统字段或后端业务约束保证。

### 计算值

- 首期支持显式字段引用 `${field.amount}`、显式上下文引用 `${ctx.task.nodeKey}`、十进制运算 `+ - * /`、括号、同类型 `==` 与 `!=`，以及 `IF`、`COALESCE`。新规则解析成类型化表达式，按节点绑定值。引号、空格等字符保留为数据。发布时检查函数参数、运算类型、结果类型、自引用和循环依赖。运算采用十进制 34 位有效数字、`HALF_EVEN` 中间舍入。DECIMAL 落值按目标字段小数位 `HALF_UP` 舍入，整数目标要求结果为整数，高精度值以字符串传输。前后端用同一组样例锁定结果和错误行为。
- 未填写的字段、此入口暂不可用的上下文参数作为空值处理。`COALESCE` 可声明替代值，`IF` 只计算命中的分支。运算和比较遇到空操作数时产生空结果，`IF` 条件为空时也产生空结果。缺输入时清除预览计算值并提示需要补充的来源。已启用的规则提交时仍缺必要输入、除数为零或结果越界，返回目标字段错误。权限失败沿用原访问控制，备用值仅处理合法空值。
- 初始化结束后按依赖顺序算一遍，随后只重算受变更字段影响的规则。「新增及发起」「编辑」「待办办理」可分别启用。新增和发起共用初始化模式，适用于同一张表单提供「保存草稿」和「提交」的场景。规则只在目标字段经发布配置和入口授权允许写入、有效可见且引用来源可读的场景运行。界面上的计算只读由这条规则设置，与原有字段写权限分别判断。
- 计算结果存入目标业务字段。浏览器提交的计算结果会被丢弃并由服务端重算，目标写入权限仍从该入口解析。查看和历史详情只展示已保存值。采用新规则的字段只允许一项计算来源，发布时检查默认值、既有值联动、`FIELD_COMPUTE`、显式事件和数据源输出映射是否与它冲突。公式和字段显示规则存在循环依赖时阻止发布。

## 发布配置与运行时

将新规则保存到字段节点 `propsDocument`，跟随当前表单发布并进入 `configHash`。参数目录由代码维护，表单引用直接使用稳定键。「上下文参数」页签从字段规则汇总使用情况。复制、导入导出携带规则和稳定引用。老表单缺少新配置时沿用原有静态默认值、`valueFormula` 和 `calculationFormula`。示例为两个不同字段节点的配置片段。

申请人字段

```json
{
  "defaultValueSource": {
    "type": "CONTEXT",
    "key": "actor.userId"
  }
}
```

`defaultValueSource.modes` 省略时为 `CREATE`，代表新增及发起。待办预填使用 `APPROVE`，同一字段可勾选两个入口。发布时结合参数可用范围检查所选入口，并为支持部分场景的参数提示空值处理方式。

审核金额字段

```json
{
  "contextCalculation": {
    "expressionVersion": 1,
    "expression": "IF(${ctx.task.nodeKey} == \"finance_review\", ${field.amount} * 0.03, ${field.amount} * 0.05)",
    "modes": ["APPROVE"]
  }
}
```

### 读取与提交

1. 表单加载先沿现有入口校验身份、表单、记录和权限。流程入口通过真实任务或实例解析节点、实例和发起人，身份侧通过 `CurrentActorPort` 和 `SysUserPort.findUsersByIds` 精确读取当前用户和已确定的用户 ID。认证、任务、记录及父子关系验证仍由原入口负责。
2. 在现有运行时配置响应中增加可选 `contextValues`，使用参数键到标量的映射。仅解析并返回当前已发布且适用的规则所引用、调用者有权读取的参数。合法缺失用 `null` 表示。浏览器把该映射作为初始化和预览输入，与业务 `data`、页面 `params` 和用于定位的 `runtimeContext` 分开。响应按当前访问隔离，运行时值不进入配置摘要、导出包和共享配置缓存。
3. 标准提交沿现有 `formConfigHash` 校验，服务端重新解析可信上下文。先移除本入口启用的计算目标的客户端值，再合并允许提交的字段和可信记录。新增时填充缺省字段，再执行现有 `BEFORE_SUBMIT`，最后计算并校验。计算读取提交前处理后的来源值。首期声明式 `BEFORE_SUBMIT` 映射可以读写公式上游字段。读取或写入当前计算目标的绑定在发布时提示调整。业务扩展需要消费计算结果时，安排在计算完成后的业务环节。
4. 将最终补丁交给现有必填、跨字段、唯一性和写入链路，流程变量和后续流转使用最终结果。计算使用了已有记录时，将参与计算的记录修订号带入现有写锁校验，覆盖未产生字段变更的审批提交。锁内发现记录已变化时返回冲突，保留页面输入并提示重新核对。已有待办通过任务校验确定唯一可信定位。权威计算按已受理请求取值一次，计算冲突沿用现有回滚和幂等机制。配置变更继续返回 `FORM_CONFIGURATION_CHANGED`。
5. 普通表单、待办和无副作用的下一节点预判走同一套后端计算规则。预判遇到现有副作用绑定，继续返回延迟预判。Web 和移动端通过 `workflow-core` 共用初始化与预览求值，自定义表单通过公共运行外层获得适用结果。原生 Embed 沿用会话范围，开启能力的入口需完成提交终检接入后才提供该配置。旧 Excel 导入、无表单的实体写入和后台任务按原规则运行。首期作用域为主表字段，组成子表行和关联内容参数传递沿用现有合同，可在后续按独立子表上下文接入。

### 实施位置

| 层 | 接入点与职责 |
| --- | --- |
| 设计器 | `FormDesignerSettingsDrawer` 增加参数目录与引用，`EntityFormDesignByEntity` 承接默认值来源，`FormNodeValueLinkage` 增加变量插入和新规则编辑。 |
| 配置发布 | `EntityFormNodePropertyPolicy` 接纳新属性，`EntityFormConfigurationValidator` 校验类型、引用、入口和依赖，运行时字段投影保留配置。发布差异展示具体字段和规则变更。 |
| 运行时读取 | 实体发布表单运行时提供独立的参数值投影。`EntityFormResolveService`、`TaskDetailService` 和流程详情入口提供已验证的流程定位，复用 `UiRuntimeResolutionContext` 等现有入口上下文。 |
| 运行时提交 | 在 `PublishedFormSubmissionService` 接入新增缺省值及最终计算，覆盖 `NodeFormSubmissionService` 的预判和正式提交。`EntityMutationTransactionExecutor` 使用现有修订号校验，计算结果与业务记录一并进入提交链。 |

现有 JSON 配置可以容纳本方案。数据库结构和系统种子数据保持现状，Flyway 迁移文件新增、修改、删除均为零。

## 发布顺序与验收

1. 先交付参数目录、设计器选参和普通新增默认值，打通 Web、移动端和服务端标准新建补值。核对 `null`、空字符串、`0`、`false`、显式预填、手动清空、延迟响应、无部门、跨账号访问和用户/部门引用权限。
2. 接入流程定义、实例和任务参数及可选的待办空值预填。验证未启动发起、选路未定、同一实例分别由发起人和办理人打开、未签收、转办、加签、并行待办、重新发起及历史查看。验证待办保留已有值、用户清空和只提交意见的行为，确认越权实例、篡改任务定位和同名输入参数无法参与可信解析。
3. 开放公式计算并接入发布预检、Web/移动预览、服务端终检和下一节点预判。共享求值样例覆盖空值、分支、精度、非法类型、循环和除零。场景回归覆盖伪造计算值、提交前回填改变来源、并发更新、配置冲突、任务失效、静态和旧公式兼容、嵌入会话范围，以及重新打开历史表单时结果保持一致。

运行时业务定位和摘要沿用现有约定，跨字段终检沿用现有表单及实体事务链路。参见 [表单与列表运行时](ui-runtime-without-config-tokens.md)、[表单统一发布](form-global-publish-without-versions-implementation.md)、[表单跨字段校验](form-cross-field-validation-design.md)。
