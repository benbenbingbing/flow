# 表单上下文参数设计

表单上下文参数是服务端根据当前入口提供的系统值。配置一条规则时先选**用途**，再确认**适用入口**，最后选**参数来源**。例如「新建时给申请人填一次当前登录人」，以及「财务待办里按当前节点算审核金额并保存」，需要分别配置默认值和计算规则。

本文记录表单上下文参数的配置方式、取值范围和提交行为。

## 实现进度

「表单设置 → 上下文参数」列出 20 个固定参数。在「默认值 → 公式 → 配置」中，所有已绑定实体字段共用同一组选项。日期和日期时间可以填入单行或多行文本。配置人员选择来源，写入时沿用目标字段的数据校验。正式提交按认证用户、实际入口及业务时区取值。

## 配置位置

| 入口 | 配置操作 | 运行效果 |
| --- | --- | --- |
| 字段属性 → 默认值 → 公式 | 在光标处插入上下文参数，可直接取值或继续组合字段和函数，保存前可试算 | 创建记录时填一次，用户可以修改或清空。适用的标准新建提交可补齐省略的字段 |
| 字段属性 → 值与计算 → 值联动方式 → 公式计算 | 插入字段或上下文参数，选择计算生效的表单模式 | 输入变化后重算。计算字段只读，适用入口提交时由服务端重算并保存 |
| 字段属性 → 条件模式权限 → 条件显示 | 按当前表单绑定的流程节点、用户归属或表单字段判断是否显示 | 条件成立时显示。隐藏时保留已填写的数据 |
| 字段属性 → 条件模式权限 → 条件编辑或禁用 | 同一规则选择「满足条件才可编辑」或「满足条件时禁用」 | 在已有字段写权限上追加判断，保存时服务端复核 |
| 字段属性 → 条件模式权限 → 条件必填 | 按上下文参数和当前字段值判断是否必填 | 条件成立且字段可见、可编辑时增加必填要求，保存时复核 |
| Tab、区块 → 条件模式权限 | 选择上下文参数和比较条件 | 条件控制整个区域及其后代的显示 |
| 表单设置 → 自定义按钮设置 | 配置上下文显示条件和禁用条件 | 结合已有按钮权限，事件按钮执行时重查条件 |
| 字段属性 → 选项联动、数据选择器、接口输入映射 | 将上下文参数映射到只读接口入参或发布列表的筛选参数 | 接口查询和选择器打开时解析参数 |
| 字段属性 → 跨字段校验 | 为单条比较规则选择触发条件 | 只在条件成立时比较，保存时结合最终记录校验 |
| 表单事件、提交前接口 | 在执行条件和输入映射中选上下文参数 | 带有条件的步骤在满足时执行，映射值传给接口作为业务参数 |
| 关联内容、子表单 → 参数传递 | 从源表单选择上下文参数 | 映射到目标页面输入参数。子表单也可初始化空的子字段 |

默认值可直接选择固定参数。条件编辑器提供参数和操作符，`form.currentMode` 提供固定枚举。组合公式通过选择器在光标处插入引用。设计预览使用示例参数，正式运行按当前业务入口取值。

### 手写语法

| 读取对象 | 公式中写法 | 取值范围 |
| --- | --- | --- |
| 表单字段 | `${amount}` | 当前主表业务字段。`amount` 换成发布配置中的字段编码 |
| 表单输入参数 | `${param.projectId}` | 在「表单设置 → 输入参数」声明，由调用方传入。`projectId` 换成该表单的参数编码，按引用位置现有的页面参数支持使用 |
| 系统上下文参数 | `${ctx.currentUser.userId}` | 由服务端按当前表单入口提供。完整写法见变量清单 |
| 字符串和数字常量 | `"finance_review"`、`"10001"`、`0.03` | 节点编码和 ID 用带双引号的字符串，费率和数量用数字 |

变量引用整体直接写 `${...}`，括号内的键区分大小写。`"${ctx.currentUser.userId}"` 是字符串常量，用 `${ctx.currentUser.userId}` 才会取值。公式按声明的字段类型计算，ID 保留为字符串，名称保留为文本。字段、页面参数和系统上下文各自解析，重名时按写法确定来源。

按本次运行定位的对象使用 `current` 前缀，分别是 `currentUser`、`currentProcessInstance`、`currentProcessNode`、`currentTask`。前缀已在对象名上，成员使用 `id`、`key`、`name` 等属性名。已发布的流程定义使用 `processDefinition`。`form` 是表单来源分组，组内的运行值使用 `currentMode`。独立的日期和时间运行值使用 `currentDate`、`currentTime`。

默认值选择器包含新增时可读取的参数，适用范围取决于表单入口。流程定义和节点参数在已确定流程入口时有值。审批规则可使用实际待办提供的实例和当前待办参数。候选待办未签收时，被指派人 ID 为空。

### 从填入到保存的示例

**申请人默认取当前用户**。目标字段为系统用户引用，打开「字段属性 → 默认值 → 公式」，输入下面一行。当前用户 ID 为 `"10001"` 时，字段选中该用户，控件按引用 ID 显示姓名。申请部门字段同理，可输入 `${ctx.currentUser.departmentId}`。

```text
${ctx.currentUser.userId}
```

**部门名称缺失时填固定文本**。目标字段为文本，输入下面的默认值公式。当前用户属于财务部时得到 `"财务部"`，未分配部门时得到 `"未分配部门"`。

```text
COALESCE(${ctx.currentUser.departmentName}, "未分配部门")
```

**按审核节点算费用**。假设实体的申请金额字段编码为 `amount`，财务复核节点编码为 `finance_review`。在「值与计算 → 值联动方式 → 公式计算」输入下式，计算模式选择「审批」。金额为 `1000` 且命中财务复核节点时，保留两位小数的结果为 `30.00`，其他有节点编码的待办为 `50.00`。

```text
IF(${ctx.currentProcessNode.key} == "finance_review", ${amount} * 0.03, ${amount} * 0.05)
```

## 手写参数完整清单

当前方案共列 20 个系统上下文变量，包括 17 个用户和流程变量，以及下方的 3 个表单运行变量。「公式写法」可直接粘贴到支持的公式入口，「示例值」是公式运行后的结果。`USER` 引用字段接收系统用户 ID，`DEPT` 引用字段接收授权范围内的系统部门或组织 ID。流程、任务 ID 及编码按字符串使用。

### 用户、流程和待办参数

| 来源 | 公式写法 | 值类型与示例 | 何时有值 |
| --- | --- | --- | --- |
| 当前用户 | `${ctx.currentUser.userId}` | 系统用户 ID 字符串 `"10001"` | 有认证用户，嵌入入口取会话映射用户 |
| 当前用户 | `${ctx.currentUser.nickname}` | 用户资料中的昵称文本 `"张三"` | 直接读取 `IdentityUser.nickname`，未填写时返回 `null` |
| 当前用户 | `${ctx.currentUser.departmentId}` | 系统部门 ID 字符串 `"20010"` | 当前用户有部门归属 |
| 当前用户 | `${ctx.currentUser.departmentName}` | 部门名称文本 `"财务部"` | 当前用户的部门名称可取 |
| 当前用户 | `${ctx.currentUser.organizationId}` | 系统组织 ID 字符串 `"30001"` | 当前用户有组织归属 |
| 当前用户 | `${ctx.currentUser.organizationName}` | 组织名称文本 `"华东分公司"` | 当前用户的组织名称可取 |
| 流程定义 | `${ctx.processDefinition.key}` | 流程编码字符串 `"expense_approval"` | 服务端已明确选定流程，或正在办理已有实例 |
| 流程定义 | `${ctx.processDefinition.name}` | 发布定义名称文本 `"费用审批"` | 可读取所选定义或当前实例对应的发布定义名称 |
| 当前流程实例 | `${ctx.currentProcessInstance.id}` | 流程实例 ID 字符串 `"56001"` | 当前办理入口有权访问明确的一轮实例 |
| 当前流程实例 | `${ctx.currentProcessInstance.starterUserId}` | 系统用户 ID 字符串 `"10008"` | 有当前实例且能确认该轮发起人身份 |
| 当前流程实例 | `${ctx.currentProcessInstance.starterName}` | 发起人显示名文本 `"李四"` | 有当前实例且可取得该轮发起人的显示名 |
| 当前流程节点 | `${ctx.currentProcessNode.key}` | BPMN 节点编码字符串 `"finance_review"` | 服务端已确认当前表单使用的发布节点绑定。适合判断节点和选择规则分支 |
| 当前流程节点 | `${ctx.currentProcessNode.name}` | 发布节点名称文本 `"财务复核"` | 当前表单有明确的发布节点绑定且节点名称可取 |
| 当前待办 | `${ctx.currentTask.id}` | 待办 ID 字符串 `"78001"` | 当前入口有权办理确切待办 |
| 当前待办 | `${ctx.currentTask.nodeKey}` | 待办所属节点编码字符串 `"finance_review"` | 有当前待办及其所属节点编码 |
| 当前待办 | `${ctx.currentTask.nodeName}` | 待办所属节点名称文本 `"财务复核"` | 有当前待办及其所属节点名称 |
| 当前待办 | `${ctx.currentTask.assigneeUserId}` | 被指派人 ID 字符串 `"10015"` | 当前待办已有指派。候选待办未签收时为空 |

组织和部门取各自归属。旧流程实例的发起人按已知历史格式解析，无法唯一确认身份时返回空值。`currentTask` 取当前表单入口打开且有权办理的那一项待办，由服务端按待办 ID 确认。一个流程实例可同时有多项待办，并行或会签时每项都有自己的 `currentTask.id`，同一节点生成的多项待办可以共用 `currentTask.nodeKey`。只有流程实例定位的入口没有此项待办上下文。提交时会重新校验待办的可办理状态。

`currentProcessNode` 取本次表单实际使用的流程节点绑定，节点编码和名称来自该入口对应的发布流程快照。办理待办时，由确切待办解析绑定。发起前若服务端已明确选用某个节点绑定的表单，也可以取得 `currentProcessNode.*`，此时 `currentTask.*` 为空。普通实体入口或仅确定了流程定义的入口，流程节点值为空。两个并行待办在打开各自表单时独立解析节点，同一节点产生的会签待办可以共享 `currentProcessNode.key`。同一表单被多条流程复用时，可同时比较 `${ctx.processDefinition.key}` 和 `${ctx.currentProcessNode.key}`。

「申请人」「发起人」「被指派人」对应不同对象。例如张三创建申请记录，李四通过授权入口启动这轮流程，待办先指派王五再转给赵六。按原值保存的申请人仍是张三，这轮流程的发起人是李四，赵六打开待办时的操作人和被指派人都是赵六。涉及业务归属或需要长期复用的值，引用已保存的申请人、申请部门等字段。实体系统字段的首次提交人按实体自身规则保存，重新发起后仍是首次提交人。涉及本次操作的值，使用操作人或当前任务参数。

### 表单运行变量

| 公式写法 | 含义 | 值类型与示例 | 何时有值 |
| --- | --- | --- | --- |
| `${ctx.form.currentMode}` | 当前表单的运行模式，沿用设计器「运行模式权限」 | 字符串枚举 `"create"`、`"edit"`、`"approve"`、`"view"` | 表单加载时由入口确定 |
| `${ctx.currentDate}` | 业务时区里的当前日期 | `DATE`，格式 `YYYY-MM-DD`，例如 `"2026-11-27"` | 服务端为本次规则求值时提供 |
| `${ctx.currentTime}` | 业务时区里的当前日期和时间，精确到秒 | `DATETIME`，格式 `YYYY-MM-DD HH:mm:ss`，例如 `"2026-11-27 08:30:15"` | 服务端为本次规则求值时提供 |

#### 表单运行模式

`form.currentMode` 读取表单运行时的 `mode`。服务端根据已验证的入口、记录和待办确定本次打开的模式。多个入口可以共用一种模式。

| 设计器名称 | 取值 | 适用入口 |
| --- | --- | --- |
| 新增 | `create` | 新建记录。保存新草稿和从新增页发起流程共用该模式 |
| 编辑 | `edit` | 编辑已有记录，包括打开已有草稿后首次发起，以及编辑原记录后重新发起 |
| 审批 | `approve` | 办理待办，包括正常办理、加签和退回后重提 |
| 查看 | `view` | 只读查看详情或历史表单 |

`${ctx.form.currentMode} == "approve"` 匹配整个审批模式。条件编辑和禁用仍受运行模式权限和节点权限约束。编辑表单里的历史面板只更新面板内容，主表单仍为 `edit`。

#### 当前日期和时间

`currentDate` 和 `currentTime` 由服务端按业务时区从同一时刻生成。日期默认值使用 `workflow.form.context-zone` 配置，默认 `Asia/Shanghai`。例如当地时间为 `2026-11-27 08:30:15` 时，前者为 `"2026-11-27"`，后者为 `"2026-11-27 08:30:15"`。周末和节假日也按当天取值。申请日期、单据日期和流程发起日期由各自的业务字段保存。

默认值按表单打开时取值，填入后的字段保留该次初始化结果。正式保存时需要重算的公式，以服务端受理本次提交的时刻为准，同一次保存的两个参数共用该时刻。

例如单行文本字段可选择 `${ctx.currentDate}` 显示 `2026-11-27`，多行文本字段可选择 `${ctx.currentTime}` 显示 `2026-11-27 08:30:15`。日期和日期时间控件同样可选择这两个来源。

## 入口和规则适用范围

上下文取值以服务端确认的**本次表单入口**为准。主表规则读取自己的字段和已验证的入口参数。子表单和关联页面通过各自声明的输入参数接收父表映射值。数据选择器可将参数映射到发布列表声明的筛选项。

| 入口 | 运行模式 | 规则可用的来源 | 字段行为 |
| --- | --- | --- | --- |
| 普通新增、保存为新草稿 | `create` | 当前用户 | 执行新增默认值及「新增」计算 |
| 新建记录并发起流程 | `create` | 当前用户、已确定的流程定义，以及已确认的表单节点绑定 | 执行新增默认值及「新增」计算。保存前尚未产生实例和待办 |
| 编辑已有记录或已有草稿，从草稿首次发起 | `edit` | 当前用户。明确进入发起场景时，可取已确定的流程定义和表单节点绑定 | 原字段值作为起点。仅执行显式启用的「编辑」计算，首次发起已有草稿也沿用编辑行为 |
| 审批、加签等实际待办 | `approve` | 当前用户、该实例的定义和实例、该项待办及其表单节点绑定 | 可执行「审批」计算 |
| 退回后从待办重新提交 | `approve` | 当前用户、原实例及其定义、本次退回待办及其表单节点绑定 | 可执行「审批」计算。使用原实例 ID |
| 撤回后重新发起 | `edit` | 当前用户、已确定的新一轮流程定义和表单节点绑定 | 从原记录编辑，按「编辑」计算。新实例 ID 等到启动成功才产生，上一轮仅供历史查看 |
| 普通查看、流程历史 | `view` | 流程详情按现有权限查看对应轮次的流程信息 | 字段规则停止执行，展示入口已有读模型提供的字段值，包括可用的记录快照 |

同一张表单上的「保存草稿」和「发起」可共用新增初始化。服务端只在能于表单规则之前独立确定目标流程时提供定义值。依赖表单计算结果选路时，这一轮初始化和提交计算将定义参数视为空，避免互相依赖。普通编辑按自身入口解析，记录自带的流程编号作为原有字段处理。流程或历史面板切换轮次时，当前表单的上下文随原编辑入口保持固定。

上下文状态条件可用 `form.currentMode` 区分新增、编辑、审批和查看，并与现有的模式权限一起生效。

### 手写配置取值

| 配置项 | 可填值 | 含义 |
| --- | --- | --- |
| 新增默认值 `defaultValueMode` | `"formula"` | 通过 `defaultFormula` 填写默认值公式。记录创建时运行一次 |
| 联动公式 `contextCalculation.modes` | `"create"`、`"edit"`、`"approve"` | 分别对应新增、编辑和审批，使用数组配置。`approve` 覆盖正常办理和退回重提 |

联动公式的可写模式沿用 `form.currentMode` 的取值。查看模式只展示已有数据。公式引用参数本身只读，字段写入由选定的规则和当前入口权限决定。

### 空值和配置错误

| 情形 | 处理 |
| --- | --- |
| 参数键拼错或在所选入口全部不可用 | 发布时定位到对应字段和公式并阻止发布 |
| 参数结果无法写入目标字段 | 写入时按原有字段类型和约束报错 |
| 参数在该入口有机会可用，但本次缺值 | 公式读到 `null`，例如操作人无部门或候选待办未签收。可用 `COALESCE` 取同类型备用值 |
| 无权读取参数来源 | 由原入口权限规则处理，兜底仅适用于合法空值 |
| 默认值取不到值，且没有备用值 | 字段留空，是否可以提交由现有字段校验决定 |
| 持久化计算缺少必要输入、除零或超出字段范围 | 保存时报告目标字段错误 |

上下文作用域随本次表单会话定位。打开时的值用于默认值初始化和试算，正式提交时服务端按当前认证及同一业务入口重新解析。流程变量属于后续扩展，需要单独声明类型、读取权限和适用入口。

## 运行规则

### 新增默认值

1. 新增默认值复用字段已有的公式来源。已授权的入口预填及已映射到字段的显式页面参数优先，包括 `null`、空字符串、`0` 和 `false`。字段缺省才计算默认值公式，可在公式里设置同类型备用值。已有打开、初始化和加载后事件仍按原顺序执行，保留入口预填的优先级。上下文公式与固定值、接口默认值共用字段已有的单选来源。
2. 初始值确定后开放输入，后续参数刷新保留修改或清空。撤销填写恢复本次打开时的初始值。
3. 标准新建提交省略了字段时，服务端按相同公式补值，显式清空按字段类型保留。已填入的默认值属于普通业务数据，经过现有字段、引用范围和实体权限校验。系统审计身份由服务端单独记录。

### 计算值

- 新规则沿用 `${amount}` 字段引用并增加 `${ctx.currentProcessNode.key}` 等上下文引用。发布时检查引用、函数和循环依赖。服务端十进制计算采用 34 位有效数字，DECIMAL 落值按目标字段小数位 `HALF_UP` 舍入，整数目标要求结果为整数。浏览器使用现有公式引擎试算，保存以服务端结果为准。
- 未填写的字段、此入口暂不可用的上下文参数作为空值处理。`COALESCE(值, 备用值)` 取第一个非空值，`0` 和 `false` 均是有效值。`IF(条件, 成立时的值, 其他值)` 只计算命中的分支。运算和比较遇到空操作数时产生空结果，`IF` 条件为空时也产生空结果。缺输入时清除预览计算值并提示需要补充的来源。已启用的规则提交时仍缺必要输入、除数为零或结果越界，返回目标字段错误。权限失败沿用原访问控制，备用值仅处理合法空值。
- 初始化结束后按依赖顺序求值，随后只重算受变更字段影响的规则。「新增」「编辑」「审批」可分别启用，入口映射见上表。目标字段须经发布配置和入口授权允许写入、有效可见，且引用来源可读。界面上的计算只读由这条规则设置，与字段写权限分别判断。
- 支持保存业务字段的提交将计算结果存入目标字段，浏览器计算值由服务端重算结果替换。只接受审批意见的操作沿用原业务记录。查看遵循入口提供的已保存数据。发布时检查新增模式中的默认值与上下文计算是否冲突，并检查字段级公式和条件的循环依赖。

### 条件显示、条件编辑和条件必填

沿用现有条件组，条件来源可加入适用的上下文变量。例如在「核定金额」的可编辑条件中，选「当前流程节点编码」，操作符选「等于」，比较值填 `finance_review`，对应 `${ctx.currentProcessNode.key} == "finance_review"`。为「复核说明」配置必填时，可同时加上「申请金额大于等于 10000」的条件。发布时检查参数类型、入口和条件依赖，避免字段状态循环。

上下文条件受已有可见权限、字段可写权限及整表只读约束。比较所需变量合法缺值时，「满足条件才可编辑」保持不可编辑，条件必填仅在明确成立时触发。用户可以通过显式空值条件配置合法缺值的行为。显示或编辑状态发生变化时保留草稿。提交时由服务端按可信上下文、授权后的字段输入和已有记录重新判定。当前不可编辑的字段如果被提交为不同值，返回该字段错误并保留已保存值。现有静态必填和实体约束继续按原规则执行。

## 发布配置与运行时

规则保存到现有字段节点 `propsDocument`，随表单发布并进入 `configHash`，复制和导入导出携带稳定引用。新增默认值复用 `defaultValueMode` 和 `defaultFormula`。值联动复用已有公式属性，并为启用上下文计算的规则登记求值协议版本及适用模式。未使用上下文的已有表单按原公式行为运行。以下为两个字段的配置片段。

申请人字段

```json
{
  "defaultValueMode": "formula",
  "defaultFormula": "${ctx.currentUser.userId}"
}
```

审核金额字段

```json
{
  "componentProps": {
    "linkageRules": {
      "valueFormula": "IF(${ctx.currentProcessNode.key} == \"finance_review\", ${amount} * 0.03, ${amount} * 0.05)",
      "contextCalculation": {
        "expressionVersion": 1,
        "modes": ["approve"]
      }
    }
  }
}
```

### 读取与提交

1. 表单加载先沿现有入口校验身份、表单、记录和权限。流程入口通过真实任务或实例解析实例和发起人，通过本次可信表单绑定读取发布节点。身份侧通过 `CurrentActorPort` 和 `SysUserPort.findUsersByIds` 精确读取当前用户和已确定的用户 ID。认证、任务、记录及父子关系验证仍由原入口负责。
2. 在现有运行时配置响应中增加可选 `contextValues`，使用参数键到标量的映射。仅解析并返回当前已发布且适用的规则所引用、调用者有权读取的参数。合法缺失用 `null` 表示。浏览器把该映射作为初始化和预览输入，与业务 `data`、页面 `params` 和用于定位的 `runtimeContext` 分开。响应按当前访问隔离，运行时值不进入配置摘要、导出包和共享配置缓存。
3. 标准提交沿现有 `formConfigHash` 校验，服务端重新解析可信上下文。先移除本入口启用的计算目标的客户端值，再合并允许提交的字段和可信记录。新增时填充缺省字段，再执行现有 `BEFORE_SUBMIT`，最后计算并校验。计算读取提交前处理后的来源值。声明式 `BEFORE_SUBMIT` 映射可使用公式上游字段，计算结果可供保存后的业务环节读取。
4. 将最终补丁交给现有必填、跨字段、唯一性和写入链路，流程变量和后续流转使用最终结果。已有待办通过任务校验确定唯一定位。跨字段规则在写入事务内使用最终记录再次校验。
5. 普通表单、待办和无副作用的下一节点预判走同一套后端计算规则。预判遇到现有副作用绑定时延迟求值。Web 和移动端共用初始化与预览求值。子表单通过父表的参数契约获取所选值。

### 实施位置

| 层 | 接入点与职责 |
| --- | --- |
| 设计器 | `FormDesignerSettingsDrawer` 提供参数目录。`FormNodeFormulaInput` 服务于 `FormNodeDefaultValue` 和 `FormNodeValueLinkage`。`FormNodeStateConditions` 提供上下文条件，预览按入口试算。 |
| 配置发布 | `EntityFormNodePropertyPolicy` 接纳新属性，`EntityFormConfigurationValidator` 校验类型、引用、入口和依赖，运行时字段投影保留配置。发布差异展示具体字段和规则变更。 |
| 运行时读取 | 实体发布表单运行时提供独立的参数值投影。`EntityFormResolveService`、`TaskDetailService` 和流程详情入口提供已验证的流程定位，复用 `UiRuntimeResolutionContext` 等现有入口上下文。 |
| 运行时提交 | 在 `PublishedFormSubmissionService` 接入新增缺省值、最终计算和字段状态终检，覆盖 `NodeFormSubmissionService` 的预判和正式提交。`EntityMutationTransactionExecutor` 使用现有修订号校验，计算结果与业务记录一并进入提交链。 |

现有 JSON 配置可以容纳本方案。数据库结构和系统种子数据保持现状，Flyway 迁移文件新增、修改、删除均为零。

## 发布顺序与验收

1. 先打通参数目录、设计器选参和普通新增默认值，包括 Web、移动端及服务端标准新建补值。核对 `null`、空字符串、`0`、`false`、显式预填、手动清空、延迟响应、无部门、跨账号访问、用户/部门引用权限，以及业务时区跨日行为。
2. 接入流程定义、实例、流程节点和待办参数。验证普通实体入口取不到流程节点、已确认的发起表单有节点而尚无待办、保存草稿后首次发起、选路未定、候选未签收、转办、加签和并行待办。覆盖同节点会签的节点编码相同而待办 ID 各自独立、退回重提使用原实例、撤回重发等待新实例、历史切换只影响流程详情。
3. 接入上下文公式和字段状态条件，覆盖发布预检、Web/移动预览、服务端终检和下一节点预判。共享样例覆盖空值、分支、精度、非法类型、循环和除零。场景回归覆盖伪造计算值、尝试修改禁用字段、只读权限、条件必填、状态切换保留草稿、并发更新、任务失效、旧公式兼容及历史页面沿用原有读模型。

运行时业务定位和摘要沿用现有约定，跨字段终检沿用现有表单及实体事务链路。参见 [表单与列表运行时](ui-runtime-without-config-tokens.md)、[表单统一发布](form-global-publish-without-versions-implementation.md)、[表单跨字段校验](form-cross-field-validation-design.md)、[终止、撤回与重新发起](process-cancellation-restart.md)。
