# 表单上下文参数设计

表单上下文参数是服务端根据当前入口提供的系统值。配置一条规则时先选**用途**，再确认**适用入口**，最后选**参数来源**。例如「新建时给申请人填一次当前登录人」，以及「财务待办里按当前节点算审核金额并保存」，需要分别配置默认值和计算规则。

本文定义拟交付的上下文参数协议。手写示例适用于接入该协议后的表单。

## 配置方式

| 入口 | 配置操作 | 运行效果 |
| --- | --- | --- |
| 表单设置 → 上下文参数 | 查看系统参数、类型、可用入口和当前表单的引用位置 | 从当前表单规则汇总使用情况 |
| 字段属性 → 默认值 → 公式 | 插入上下文参数。直接取值时，公式只包含一个参数 | 创建记录时填一次，用户可以修改或清空。适用的标准新建提交可补齐省略的字段 |
| 字段属性 → 待办预填 | 选参数，勾选「正常办理」或「退回后重提」 | 仅打开所选待办时，为尚未填写且可编辑的字段预填一次。用户确认的字段值随提交保存 |
| 字段属性 → 值联动 → 公式计算 | 插入字段或上下文参数，选择计算生效的表单模式 | 输入变化后重算。计算字段只读，适用入口提交时由服务端重算并保存 |
| 表单预览 | 模拟入口和上下文状态 | 显示可选参数、取值结果、空值原因和最终字段值。模拟值只用于试算 |

### 手写语法

| 读取对象 | 公式中写法 | 取值范围 |
| --- | --- | --- |
| 表单字段 | `${amount}` | 当前主表业务字段。`amount` 换成发布配置中的字段编码 |
| 页面输入参数 | `${param.projectId}` | 当前页面已声明的输入参数。使用参数编码，并遵循该公式入口现有的页面参数支持 |
| 系统上下文参数 | `${ctx.actor.userId}` | 由服务端按当前表单入口提供。`ctx.` 后接下表中的完整参数键 |
| 字符串和数字常量 | `"finance_review"`、`"10001"`、`0.03` | 节点编码和 ID 用带双引号的字符串，费率和数量用数字 |

变量引用整体直接写 `${...}`，括号内的键区分大小写。`"${ctx.actor.userId}"` 是字符串常量，用 `${ctx.actor.userId}` 才会取值。公式按声明的字段类型计算，ID 保留为字符串，名称保留为文本。字段、页面参数和系统上下文各自解析，重名时按写法确定来源。

选择器先根据规则用途、入口和字段类型展示兼容参数，再按来源分组。完全不适用的参数可在目录里查看原因，部分场景可能为空的参数标注空值条件。例如「流程发起人 · 已启动的实例中可取」，以及「当前被指派人 · 候选任务未签收时为空」。改变规则入口后立即复查已选参数，发布校验定位到具体字段和规则。

### 从填入到保存的示例

**申请人默认取当前操作人**。目标字段为系统用户引用，打开「字段属性 → 默认值 → 公式」，输入下面一行。当前用户 ID 为 `"10001"` 时，字段选中该用户，控件按引用 ID 显示姓名。申请部门字段同理，可输入 `${ctx.actor.departmentId}`。

```text
${ctx.actor.userId}
```

**部门名称缺失时填固定文本**。目标字段为文本，输入下面的默认值公式。操作人属于财务部时得到 `"财务部"`，未分配部门时得到 `"未分配部门"`。

```text
COALESCE(${ctx.actor.departmentName}, "未分配部门")
```

**办理待办时建议联系人**。目标字段为系统用户引用，原始配置的 `taskPrefill.sourceKey` 填 `process.starterUserId`，`scenes` 填 `["APPROVE"]`。公式里的 `${ctx.process.starterUserId}` 在 `sourceKey` 中对应裸键 `process.starterUserId`。联系人为空时使用这一轮实例的发起人。需要在退回待办也预填时，将 `"RESUBMIT"` 加入 `scenes`。

**按审核节点算费用**。假设实体的申请金额字段编码为 `amount`，财务复核节点编码为 `finance_review`。在「值联动 → 公式计算」输入下式，计算模式选择「待办」。金额为 `1000` 且命中财务复核节点时，保留两位小数的结果为 `30.00`，其他有节点编码的待办为 `50.00`。

```text
IF(${ctx.task.nodeKey} == "finance_review", ${amount} * 0.03, ${amount} * 0.05)
```

## 手写参数完整清单

下表列出首期全部 15 个参数。「公式写法」可直接粘贴，「示例值」是公式运行后的结果。`USER` 引用字段接收系统用户 ID，`DEPT` 引用字段接收授权范围内的系统部门或组织 ID。流程、任务 ID 及编码按字符串使用。

| 来源 | 公式写法 | 值类型与示例 | 何时有值 |
| --- | --- | --- | --- |
| 当前操作人 | `${ctx.actor.userId}` | 系统用户 ID 字符串 `"10001"` | 有认证用户，嵌入入口取会话映射用户 |
| 当前操作人 | `${ctx.actor.displayName}` | 显示名文本 `"张三"` | 当前操作人的目录显示名可取 |
| 当前操作人 | `${ctx.actor.departmentId}` | 系统部门 ID 字符串 `"20010"` | 当前操作人有部门归属 |
| 当前操作人 | `${ctx.actor.departmentName}` | 部门名称文本 `"财务部"` | 当前操作人的部门名称可取 |
| 当前操作人 | `${ctx.actor.organizationId}` | 系统组织 ID 字符串 `"30001"` | 当前操作人有组织归属 |
| 当前操作人 | `${ctx.actor.organizationName}` | 组织名称文本 `"华东分公司"` | 当前操作人的组织名称可取 |
| 流程定义 | `${ctx.process.definitionKey}` | 流程编码字符串 `"expense_approval"` | 服务端已明确选定流程，或正在办理已有实例 |
| 流程定义 | `${ctx.process.definitionName}` | 发布定义名称文本 `"费用审批"` | 可读取所选定义或当前实例对应的发布定义名称 |
| 流程实例 | `${ctx.process.instanceId}` | 流程实例 ID 字符串 `"56001"` | 当前办理入口有权访问明确的一轮实例 |
| 流程实例 | `${ctx.process.starterUserId}` | 系统用户 ID 字符串 `"10008"` | 有当前实例且能确认该轮发起人身份 |
| 流程实例 | `${ctx.process.starterName}` | 发起人显示名文本 `"李四"` | 有当前实例且可取得该轮发起人的显示名 |
| 当前待办 | `${ctx.task.id}` | 待办 ID 字符串 `"78001"` | 当前入口有权办理确切待办 |
| 当前待办 | `${ctx.task.nodeKey}` | 流程节点编码字符串 `"finance_review"` | 有当前待办及其节点编码，可用于判断公式分支 |
| 当前待办 | `${ctx.task.nodeName}` | 节点名称文本 `"财务复核"` | 有当前待办及其节点名称 |
| 当前待办 | `${ctx.task.assigneeUserId}` | 被指派人 ID 字符串 `"10015"` | 当前待办已有指派。候选待办未签收时为空 |

组织和部门取各自归属。旧流程实例的发起人按已知历史格式解析，无法唯一确认身份时返回空值。同一实例的并行任务分别取各自的 `task.*`。按节点写规则时使用实际节点编码，界面显示名称可以单独调整。

「申请人」「发起人」「被指派人」对应不同对象。例如张三创建申请记录，李四通过授权入口启动这轮流程，待办先指派王五再转给赵六。按原值保存的申请人仍是张三，这轮流程的发起人是李四，赵六打开待办时的操作人和被指派人都是赵六。涉及业务归属或需要长期复用的值，引用已保存的申请人、申请部门等字段。实体系统字段的首次提交人按实体自身规则保存，重新发起后仍是首次提交人。涉及本次操作的值，使用操作人或当前任务参数。

## 入口和规则适用范围

上下文取值以服务端确认的**本次表单入口**为准。首期可配置范围是已发布主表字段的默认值公式、待办预填和值联动公式。主表中的规则读取自己的字段和已验证的入口参数。子表单及关联页面继续通过各自的参数契约取值，流程脚本、列表筛选和数据源映射走各自已有的变量空间。

| 入口 | 规则可用的来源 | 字段行为 |
| --- | --- | --- |
| 普通新增、保存为新草稿 | 操作人 | 执行新增默认值及「新增」计算 |
| 新建记录并发起流程 | 操作人、已确定的流程定义 | 执行新增默认值及「新增」计算。保存前尚未产生实例和待办 |
| 编辑已有记录或已有草稿，从草稿首次发起 | 操作人。明确进入发起场景且目标已确定时，可取流程定义 | 原字段值作为起点。仅执行显式启用的「编辑」计算，首次发起已有草稿也沿用编辑行为 |
| 审批、加签等实际待办 | 操作人、该实例的定义和实例、该项待办 | 可执行配置为「正常办理」的预填及「待办」计算 |
| 退回后从待办重新提交 | 操作人、原实例及其定义、本次退回待办 | 可执行配置为「退回后重提」的预填及「待办」计算。使用原实例 ID |
| 撤回后重新发起 | 操作人、已确定的新一轮流程定义 | 从原记录编辑，按「编辑」计算。新实例 ID 等到启动成功才产生，上一轮仅供历史查看 |
| 普通查看、流程历史 | 字段规则停止执行。流程详情可按现有权限查看对应轮次的流程信息 | 展示入口已有读模型提供的字段值，包括可用的记录快照 |

同一张表单上的「保存草稿」和「发起」可共用新增初始化。服务端只在能于表单规则之前独立确定目标流程时提供定义值。依赖表单计算结果选路时，这一轮初始化和提交计算将定义参数视为空，避免互相依赖。普通编辑按自身入口解析，记录自带的流程编号作为原有字段处理。流程或历史面板切换轮次时，当前表单的上下文随原编辑入口保持固定。

### 手写配置的场景枚举

| 配置项 | 可填值 | 含义 |
| --- | --- | --- |
| 新增默认值 `defaultValueMode` | `"formula"` | 通过 `defaultFormula` 填写默认值公式。记录创建时运行一次 |
| 待办预填 `taskPrefill.scenes` | `"APPROVE"`、`"RESUBMIT"` | 分别对应正常办理和退回后重提，使用数组配置，可同时选两个 |
| 联动公式 `contextCalculation.modes` | `"CREATE"`、`"EDIT"`、`"TASK"` | 分别对应新增、编辑和待办，使用数组配置。`TASK` 包含办理和退回重提 |

只读查看和历史查看展示已有读模型，场景枚举仅用于会创建或修改业务字段的入口。公式引用参数本身只读，字段写入由选定的规则和当前入口权限决定。

### 空值和配置错误

| 情形 | 处理 |
| --- | --- |
| 参数键拼错、类型不匹配或在所选入口全部不可用 | 发布时定位到对应字段和公式并阻止发布 |
| 参数在该入口有机会可用，但本次缺值 | 公式读到 `null`，例如操作人无部门或候选待办未签收。可用 `COALESCE` 取同类型备用值 |
| 无权读取参数来源 | 由原入口权限规则处理，兜底仅适用于合法空值 |
| 默认值或待办预填取不到值，且没有备用值 | 字段留空，是否可以提交由现有字段校验决定 |
| 持久化计算缺少必要输入、除零或超出字段范围 | 保存时报告目标字段错误 |

上下文作用域随本次表单会话定位。打开时的值用于预填和试算，正式提交时服务端按当前认证及同一业务入口重新解析。流程变量属于后续扩展，需要单独声明类型、读取权限和适用入口。

## 运行规则

### 新增默认值和待办预填

1. 新增默认值复用字段已有的公式来源。已授权的入口预填及已映射到字段的显式页面参数优先，包括 `null`、空字符串、`0` 和 `false`。字段缺省才计算默认值公式，可在公式里设置同类型备用值。已有打开、初始化和加载后事件仍按原顺序执行，保留入口预填的优先级。上下文公式与固定值、接口默认值共用字段已有的单选来源。
2. 待办预填独立配置。已加载的记录值优先，随后只在所选待办入口为可见、可编辑、尚未填写的字段预填。发起人在退回待办修改时，由该节点的表单权限和「退回后重提」开关共同决定是否预填。新增默认值和待办预填可以指向不同来源。
3. 初始值确定后开放输入，后续参数刷新保留修改或清空。撤销填写恢复本次打开时的初始值。重新打开待办时，仍为空的字段可再次预填。
4. 标准新建提交省略了字段时，服务端按相同公式补值，显式清空按字段类型保留。待办预填属于本次页面草稿，只有表单提交该字段时才写入。无界面办理或仅提交审批意见时，省略字段继续保留。已填入的默认值属于普通业务数据，经过现有字段、引用范围和实体权限校验。系统审计身份由服务端单独记录。

### 计算值

- 新规则沿用 `${amount}` 字段引用并增加 `${ctx.task.nodeKey}` 上下文引用。首期权威求值支持十进制运算 `+ - * /`、括号、同类型 `==` 与 `!=`、`IF` 和 `COALESCE`。参数按类型绑定到表达式节点，引号和空格保留为数据。发布检查函数参数、运算类型、结果类型、自引用和循环依赖。运算采用十进制 34 位有效数字、`HALF_EVEN` 中间舍入。DECIMAL 落值按目标字段小数位 `HALF_UP` 舍入，整数目标要求结果为整数，高精度值以字符串传输。前后端用同一组样例锁定结果和错误行为。
- 未填写的字段、此入口暂不可用的上下文参数作为空值处理。`COALESCE(值, 备用值)` 取第一个非空值，`0` 和 `false` 均是有效值。`IF(条件, 成立时的值, 其他值)` 只计算命中的分支。运算和比较遇到空操作数时产生空结果，`IF` 条件为空时也产生空结果。缺输入时清除预览计算值并提示需要补充的来源。已启用的规则提交时仍缺必要输入、除数为零或结果越界，返回目标字段错误。权限失败沿用原访问控制，备用值仅处理合法空值。
- 初始化结束后按依赖顺序求值，随后只重算受变更字段影响的规则。「新增」「编辑」「待办」可分别启用，入口映射见上表。目标字段须经发布配置和入口授权允许写入、有效可见，且引用来源可读。界面上的计算只读由这条规则设置，与字段写权限分别判断。
- 支持保存业务字段的提交将计算结果存入目标字段，浏览器计算值由服务端重算结果替换。只接受审批意见的操作沿用原业务记录。查看遵循入口提供的已保存数据。采用新规则的字段在同一入口只允许一项写值来源，发布时检查默认值、待办预填、既有值联动、显式事件和数据源输出映射的冲突。显示条件依赖计算目标而计算又依赖该显示条件时，发布阻止循环。

## 发布配置与运行时

规则保存到现有字段节点 `propsDocument`，随表单发布并进入 `configHash`，复制和导入导出携带稳定引用。新增默认值复用 `defaultValueMode` 和 `defaultFormula`。待办预填记录来源键、空值处理和适用入口。值联动复用已有公式属性，并为启用上下文计算的规则登记求值协议版本及适用模式。未使用上下文的已有表单按原公式行为运行。以下为三个字段的配置片段。

申请人字段

```json
{
  "defaultValueMode": "formula",
  "defaultFormula": "${ctx.actor.userId}"
}
```

审批联系人字段

```json
{
  "taskPrefill": {
    "sourceKey": "process.starterUserId",
    "scenes": ["APPROVE"]
  }
}
```

`taskPrefill.scenes` 可选 `APPROVE` 正常办理和 `RESUBMIT` 退回后重提，缺值时可配置 `fallbackValue`，省略则留空。计算模式中的 `TASK` 对应整类待办表单，包含这两种入口。`CREATE` 对应新增记录，`EDIT` 对应编辑已存在的记录。

审核金额字段

```json
{
  "linkageRules": {
    "valueFormula": "IF(${ctx.task.nodeKey} == \"finance_review\", ${amount} * 0.03, ${amount} * 0.05)",
    "contextCalculation": {
      "expressionVersion": 1,
      "modes": ["TASK"]
    }
  }
}
```

### 读取与提交

1. 表单加载先沿现有入口校验身份、表单、记录和权限。流程入口通过真实任务或实例解析节点、实例和发起人，身份侧通过 `CurrentActorPort` 和 `SysUserPort.findUsersByIds` 精确读取当前用户和已确定的用户 ID。认证、任务、记录及父子关系验证仍由原入口负责。
2. 在现有运行时配置响应中增加可选 `contextValues`，使用参数键到标量的映射。仅解析并返回当前已发布且适用的规则所引用、调用者有权读取的参数。合法缺失用 `null` 表示。浏览器把该映射作为初始化和预览输入，与业务 `data`、页面 `params` 和用于定位的 `runtimeContext` 分开。响应按当前访问隔离，运行时值不进入配置摘要、导出包和共享配置缓存。
3. 标准提交沿现有 `formConfigHash` 校验，服务端重新解析可信上下文。先移除本入口启用的计算目标的客户端值，再合并允许提交的字段和可信记录。新增时填充缺省字段，再执行现有 `BEFORE_SUBMIT`，最后计算并校验。计算读取提交前处理后的来源值。首期声明式 `BEFORE_SUBMIT` 映射可以读写公式上游字段。读取或写入当前计算目标的绑定在发布时提示调整。业务扩展需要消费计算结果时，安排在计算完成后的业务环节。
4. 将最终补丁交给现有必填、跨字段、唯一性和写入链路，流程变量和后续流转使用最终结果。计算使用了已有记录时，将参与计算的记录修订号带入现有写锁校验，覆盖未产生字段变更的审批提交。锁内发现记录已变化时返回冲突，保留页面输入并提示重新核对。已有待办通过任务校验确定唯一可信定位。权威计算按已受理请求取值一次，计算冲突沿用现有回滚和幂等机制。配置变更继续返回 `FORM_CONFIGURATION_CHANGED`。
5. 普通表单、待办和无副作用的下一节点预判走同一套后端计算规则。预判遇到现有副作用绑定，继续返回延迟预判。Web 和移动端通过 `workflow-core` 共用初始化与预览求值，自定义表单通过公共运行外层获得适用结果。原生 Embed 沿用会话范围，开启能力的入口需完成提交终检接入后才提供该配置。旧 Excel 导入、无表单的实体写入和后台任务按原规则运行。首期作用域为主表字段，组成子表行和关联内容参数传递沿用现有合同，可在后续按独立子表上下文接入。

### 实施位置

| 层 | 接入点与职责 |
| --- | --- |
| 设计器 | `FormDesignerSettingsDrawer` 增加参数目录。`FormNodeFormulaInput` 增加参数插入并服务于已有 `FormNodeDefaultValue` 和 `FormNodeValueLinkage`。节点属性另设待办预填，预览按入口试算。 |
| 配置发布 | `EntityFormNodePropertyPolicy` 接纳新属性，`EntityFormConfigurationValidator` 校验类型、引用、入口和依赖，运行时字段投影保留配置。发布差异展示具体字段和规则变更。 |
| 运行时读取 | 实体发布表单运行时提供独立的参数值投影。`EntityFormResolveService`、`TaskDetailService` 和流程详情入口提供已验证的流程定位，复用 `UiRuntimeResolutionContext` 等现有入口上下文。 |
| 运行时提交 | 在 `PublishedFormSubmissionService` 接入新增缺省值及最终计算，覆盖 `NodeFormSubmissionService` 的预判和正式提交。`EntityMutationTransactionExecutor` 使用现有修订号校验，计算结果与业务记录一并进入提交链。 |

现有 JSON 配置可以容纳本方案。数据库结构和系统种子数据保持现状，Flyway 迁移文件新增、修改、删除均为零。

## 发布顺序与验收

1. 先交付参数目录、设计器选参和普通新增默认值，打通 Web、移动端和服务端标准新建补值。核对 `null`、空字符串、`0`、`false`、显式预填、手动清空、延迟响应、无部门、跨账号访问和用户/部门引用权限。
2. 接入流程定义、实例和任务参数及待办预填。验证新建直接发起、保存草稿后首次发起、选路未定、候选未签收、转办、加签和并行待办。专项覆盖退回重提使用原实例、撤回重发等待新实例、历史切换只影响流程详情。验证待办保留已有值、用户清空、只提交意见及入口鉴权。
3. 开放上下文公式的权威计算，接入发布预检、Web/移动预览、服务端终检和下一节点预判。共享样例覆盖空值、分支、精度、非法类型、循环和除零。场景回归覆盖伪造计算值、提交前回填改变来源、并发更新、配置冲突、任务失效、旧公式兼容、嵌入会话范围，以及历史页面沿用原有读模型。

运行时业务定位和摘要沿用现有约定，跨字段终检沿用现有表单及实体事务链路。参见 [表单与列表运行时](ui-runtime-without-config-tokens.md)、[表单统一发布](form-global-publish-without-versions-implementation.md)、[表单跨字段校验](form-cross-field-validation-design.md)、[终止、撤回与重新发起](process-cancellation-restart.md)。
