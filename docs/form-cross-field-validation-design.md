# 表单跨字段校验设计

> 状态：已实现，包含前后端比较校验与配置、运行时验证。
> 日期：2026-09-15。
> 范围：同一实体、同一条记录中的字段比较；不涉及子表单。

## 1. 方案结论

在“字段属性 → 状态与校验”新增“跨字段校验”区块。规则挂在需要显示错误的字段上，比较同一实体记录中的另一个字段。例如，在结束时间 `endTime` 上配置 `endTime >= startTime`。

- 用户选择比较方式、目标字段和错误提示，无需写代码或表达式。
- 配置规则后默认生效，仅在规则所属字段当前可见且可编辑时执行；隐藏、只读或禁用时自动跳过，无需额外配置。
- 修改任意参与字段都会重新检查适用状态并校验，失败信息显示在规则所属字段下方。
- 服务端依据可信发布版本，用最终待保存数据执行终检。
- 规则属于当前表单，随保存、发布、复制、恢复及配置迁移流转。
- 沿用节点规则 JSON，不需要数据库迁移。

截图中的 `processStartTime`、`processEndTime` 是系统维护的流程时间。本设计以用户填写的业务字段 `startTime`、`endTime` 演示，不改变系统字段的维护方式或编辑权限。

## 2. 功能范围

| 项目 | 设计 |
| --- | --- |
| 比较对象 | 同一实体、同一条记录中的两个普通字段 |
| 配置位置 | 当前表单中绑定实体字段的 FIELD 节点 |
| 目标字段范围 | 已加入当前表单、属于同一实体且类型兼容的字段，允许隐藏或只读字段作为比较来源 |
| 日期类型 | DATE 对 DATE、DATETIME 对 DATETIME |
| 数值类型 | INTEGER、LONG、DECIMAL、DOUBLE 之间允许比较 |
| 比较方式 | 等于、不等于、大于、大于等于、小于、小于等于 |
| 多条规则 | 同一字段可添加多条，全部通过才有效 |
| 默认生效条件 | 规则已配置，且规则所属字段当前可见、可编辑；不提供适用模式或启用开关 |
| 空值行为 | 任一字段为空时跳过比较；非空要求使用已有必填或条件必填 |
| 生效边界 | 当前表单的已发布规则，不是整个实体的全局约束 |

本功能只比较已有字段值，不配置或改变必填/非必填属性，也不提供“至少填一项”等填写关系规则。

布局容器、Tab、折叠面板不改变字段所属实体。本功能不涉及子表单、跨记录比较、跨实体查询、数组/对象比较、任意脚本、计算表达式或日期偏移量。

实体中尚未加入表单的字段，需先放入当前表单，再选择为比较对象；需要仅作为数据依据时可以设为隐藏或只读。这样配置与运行时的数据来源一致。

## 3. 配置界面

### 3.1 入口与布局

选中“结束时间” → 节点属性 → “状态与校验” → “跨字段校验”。新区域与现有“校验规则”“唯一性”并列，不依赖字段是否支持长度或正则规则。

```text
跨字段校验                                      1 项规则
比较当前字段与同一实体中的其他字段

规则 1                                                删除
当前字段       结束时间
比较方式       [大于等于 ≥                  ▾]
比较字段       [开始时间（startTime）        ▾]
错误提示       [结束时间不能早于开始时间       ]

规则预览：结束时间 ≥ 开始时间
当前字段可见且可编辑时自动校验；隐藏、只读或禁用时跳过。
任一字段为空时跳过比较，必填仍由字段原有设置控制。

[＋添加规则]
```

交互约定：

1. 当前字段自动带入；比较字段支持按名称、编码搜索，排除自身及类型不兼容字段。
2. 错误提示可选填，最多 200 字。留空时根据两端字段标签与操作符生成，例如“结束时间必须大于等于开始时间”。
3. 引用保存字段编码，修改显示名称不破坏引用。删除目标字段或改变字段类型时保留并标红失效规则，发布前必须修复。
4. 每字段最多 20 条规则；相同操作符、目标字段的组合不允许重复添加。
5. 配置规则即默认生效，支持添加、修改和删除，不提供单独的启用、适用模式或跳过策略配置。多规则按配置顺序执行，字段下方显示首个失败提示。
6. 配置保存到草稿，发布后生效。已有流程是否使用新配置，继续遵循现有发布及热修复机制。

### 3.2 填写效果

```text
开始时间   [2026-09-15 10:00:00]
结束时间   [2026-09-15 09:00:00]
           结束时间不能早于开始时间
```

结束时间可见且可编辑时，修改结束时间会重新检查；把开始时间改到结束时间之后，也会在结束时间下方更新提示。两者相同时，“大于等于”通过，“大于”不通过。结束时间隐藏、只读或禁用时，其跨字段规则跳过，不因开始时间改变而阻止提交。

提交失败后定位第一个错误字段，展开所属 Tab/折叠面板。普通输入、日期选择、默认值回填和联动赋值均采用相同规则。

## 4. 规则数据结构

规则写入所属字段节点的 `rulesDocument.validation.crossField`：

```json
{
  "validation": {
    "crossField": {
      "version": 1,
      "rules": [
        {
          "id": "end_after_start",
          "operator": "GE",
          "targetFieldCode": "startTime",
          "message": "结束时间不能早于开始时间"
        }
      ]
    }
  }
}
```

`version` 是数据协议标识，用于识别配置格式，不表示分阶段交付。

| 属性 | 约定 |
| --- | --- |
| `version` | 当前协议值为 1；无法识别的值阻止发布/执行，不能忽略 |
| `rules` | 规则数组；空数组或没有 crossField 表示未配置 |
| `id` | 编辑器生成、当前字段内唯一的稳定标识，用于差异及错误定位 |
| `operator` | EQ、NE、GT、GE、LT、LE，不接受表达式 |
| `targetFieldCode` | 比较字段编码，不接受属性路径、数组索引或跨实体引用 |
| `message` | 可选纯文本，不支持 HTML 或模板执行 |

当前字段由规则所属节点确定，类型来自可信实体字段元数据，不重复保存客户端声明的比较类型。其他规则如 min、max、pattern、uniqueness 保持原有含义。

不存储适用模式、启用状态、隐藏/只读时跳过等策略字段。运行模式只参与现有字段权限计算；跨字段规则统一使用计算后的可见、可编辑状态。

发布时投影为 `EntityFormField.validationRules.crossField`。清空规则必须覆盖旧值，不能在节点/字段兼容合并时恢复旧规则。

## 5. 校验行为

### 5.1 触发与错误更新

- 字段变化、失焦，以及表单提交时，先检查规则所属字段的有效可见性和可编辑性，满足条件才执行比较。
- 建立“比较字段 → 依赖它的规则所属字段”索引。开始时间变化，只更新依赖它的字段，避免每次验证整张表单。
- 默认值、数据源和字段联动赋值完成后，合并当前一轮更新再执行比较，避免展示中间状态。
- 初次打开表单不立即展示跨字段红字；首次修改任意参与字段或首次提交后显示。
- 值修复、规则删除，或所属字段变为隐藏、只读、禁用后，立即清除该规则的旧错误，不能继续阻止提交。
- 所属字段恢复可见且可编辑时，重新检查已有值；是否展示红字沿用首次修改/提交的显示规则。模式切换通过字段状态重新计算生效，不维护独立的模式白名单。
- 校验只读取数据，不修改数据。A 比 B、B 比 A 不会引发赋值循环，不递归触发规则。

### 5.2 空值、显示与权限

统一执行前提为：**规则已配置，且规则所属字段有效可见、有效可编辑。** 先检查此前提，再执行空值及类型判断。以下“当前字段”均指配置规则、承接错误提示的字段，比较来源字段无需同时可编辑。

| 情况 | 行为 |
| --- | --- |
| 任一值为 null、undefined 或空字符串 | 跳过比较，必填规则独立执行 |
| 数值为 0 | 有效值，正常参与比较 |
| 有值但日期或数字格式非法 | 提示格式错误，不作为空值放行 |
| 规则所属字段可见且可编辑 | 默认执行，无需选择新增、编辑或审批模式 |
| 规则所属字段业务上隐藏 | 自动跳过并清除旧错误 |
| 字段位于未选中 Tab 或收起的面板 | 布局收起不等于业务隐藏；字段有效可见、可编辑时继续校验，失败后展开定位 |
| 比较字段隐藏或只读 | 有值时正常比较，不因目标字段不可编辑而跳过 |
| 规则所属字段可见但只读或禁用 | 自动跳过并清除旧错误，不因比较字段变化而阻止提交 |
| 整表只读或查看模式 | 字段有效不可编辑，自动跳过 |
| 浏览器没有获得比较值 | 不等同于明确空值；前端将比较留给服务端终检，不能宣称该项已通过 |

有效可见性包含父级容器、模式显示权限和已有条件显示联动；有效可编辑性包含整表只读、查看状态、字段只读、模式编辑权限和条件禁用等现有约束。前后端复用相同状态语义，不增加新的权限配置。

前端在状态变化后清除不再适用的错误；接收服务端错误时再次检查当前字段状态，避免延迟响应让已隐藏或已只读的字段重新阻止提交。恢复可编辑后仍须重新校验，不能保留旧的通过结果。

读取比较值不扩大字段权限。系统字段作为比较来源时使用系统维护的可信值，客户端不得通过伪造同名字段改变比较结果。

### 5.3 类型比较

- DATE 按有效日历日期比较，标准形式为 YYYY-MM-DD，不把非法日期自动滚动为其他日期。
- DATETIME 沿用当前控件的本地日期时间语义，标准形式为 YYYY-MM-DD HH:mm:ss；服务端已有 LocalDateTime、JDBC 时间值以及无偏移 ISO T 格式须归一化后比较。
- 时间比较精度为秒。非零小数秒、带 Z/时区偏移的输入不自行截断或转换，返回不支持的格式错误，避免前后端在精度和时区上作不同猜测。
- DATE 与 DATETIME 不混比，不默认把日期补成当天零点。
- 数值按数值大小比较。前端按控件输出值执行精确十进制比较，后端采用 BigDecimal 等价语义，不按字符串排序、不采用未经约定的浮点容差。
- 超过 JavaScript 安全整数范围的 LONG 须以字符串保真传输；高精度 DECIMAL 同样支持字符串。比较器拒绝不安全整数 Number；数值控件仍沿用已有精度设置，比较器不会恢复控件或 JSON 数值传输之前已丢失的精度。

## 6. 后端终检

在 `PublishedFormSubmissionService.applyResolvedForm` 中，与现有必填终检相邻增加跨字段校验，执行顺序为：

```text
解析可信表单发布版本及提交权限
          ↓
应用默认值和 BEFORE_SUBMIT 处理
          ↓
构造最终待保存记录视图
          ↓
执行原有必填校验
跨字段校验仅检查当前可见、可编辑的规则所属字段
          ↓
通过：沿现有链路保存/提交审批
失败：返回字段错误，阻止本次提交
```

关键约定：

1. 编辑提交按“数据库旧记录 + 本次允许写入字段 + 提交前处理结果”构造最终视图。缺省字段保留旧值，显式 null 表示清空，不能因为请求未携带开始时间而跳过比较。
2. 原有 `PublishedFormRequiredValidator` 调用保持不变；跨字段校验使用 `PublishedFormRecordView` 合并本次补丁，单次检查只读取一次原记录，不按规则数量重复查库。
3. 规则、字段类型、运行上下文、发布版本和系统字段取可信来源。服务端根据当前入口权限、已发布配置和最终记录重新计算字段可见性与可编辑性，不接受客户端提供的 hidden、readonly、disabled 或校验成功标记来跳过规则。
4. 前端预检通过后，权威提交仍须重新判断字段状态并校验。BEFORE_SUBMIT 改写参与字段或联动条件字段后，按最终数据确定哪些规则适用，再比较最终值；隐藏或不可编辑字段的规则不执行。现有必填校验保持原有行为。
5. 在 `EntityMutationTransactionExecutor` 已有记录锁与事务内，读取写入后的完整记录，再按本次实际采用的可信表单发布身份终检；不通过则回滚。该检查也覆盖无字段变更的审批提交，并防止并发补丁组合出非法结果。流程节点整表只读状态从服务端发布绑定传入，仅控制新增跨字段校验，保持原有必填和提交处理行为。
6. 失败阻止当前实体提交；外部扩展的副作用继续遵循现有 BEFORE_SUBMIT 幂等与事务约定。

核对新增、编辑、流程发起/审批、自定义表单及原生嵌入表单的标准提交入口，确保均接入终检。本次不新增子表单规则配置、遍历或递归校验逻辑。

没有表单上下文的后台任务、导入或实体直接修改接口，不自动套用任意一张表单的规则。需要整个实体始终满足的全局业务约束，应在实体/业务层实施。

## 7. 错误返回

新增稳定错误码 `FORM_CROSS_FIELD_VALIDATION_FAILED`，沿用业务冲突 HTTP 409。在现有响应封装的 data 中携带字段错误：

```json
{
  "fieldErrors": [
    {
      "fieldCode": "endTime",
      "ruleId": "end_after_start",
      "targetFieldCode": "startTime",
      "message": "结束时间不能早于开始时间"
    }
  ]
}
```

新增携带字段错误列表的异常及对应处理器，保持已有通用 `BusinessConflictException` 行为。响应不回传参与比较的实际值。

前端将错误映射到对应字段，并复用 `validationReveal` 展开和定位。旧字段平铺、自定义表单的公共外层也执行平台校验；自定义组件未提供字段定位时显示错误摘要并阻止提交，自身的 validate() 仍照常执行。

## 8. 配置完整性与发布

- 节点 PATCH 校验规则格式、操作符、规则标识和提示长度，不接收适用模式、启用开关或跳过策略字段。
- 完整表单保存与发布检查字段引用、所属实体和类型兼容性。
- 删除字段、改变编码或类型时保留并标红失效规则，允许整理草稿，但必须修复后才能发布。
- 发布拒绝自引用、失效引用、不兼容类型、未知协议及跨实体引用；字段当前隐藏或只读，也不能绕过配置合法性校验，以免恢复可编辑时使用失效规则。
- 复制、导入导出、版本恢复沿用相同校验。规则使用字段编码，节点 ID 变化不影响引用；涉及编码重映射时显式处理。
- 无规则的旧表单行为不变；显式清空、保存和投影不得复活旧规则。
- 运行实例使用自己解析到的发布快照，不读取最新草稿；更新配置继续走既有发布流程。
- 部署先完成后端支持，再开放配置入口。启用新规则后，不可直接回退到会忽略规则的旧服务端。

## 10. 验收标准

| 场景 | 预期 |
| --- | --- |
| 结束时间可见且可编辑，结束晚于、等于、早于开始 | GE 前两种通过，最后一种失败；GT 相等时失败 |
| 只修改开始时间导致违规，结束时间仍可见且可编辑 | 自动刷新结束时间错误，提交失败 |
| 任一值为空或数值为 0 | 空值跳过，必填独立检查；0 正常比较 |
| 非法日期、带偏移时间或非法数字 | 前后端一致拒绝，不隐式转换 |
| 编辑仅提交结束时间 | 与数据库保留的开始时间比较 |
| BEFORE_SUBMIT 改写参与字段或联动条件字段 | 按最终数据重算可见性、可编辑性，只终检仍适用的规则 |
| 规则所属字段隐藏、只读、禁用或整表只读 | 自动跳过，清除旧错误且不阻止提交，前后端一致 |
| 结束时间只读，仅修改开始时间导致时间关系违规 | 结束时间规则跳过，不反向限制开始时间 |
| 比较来源字段隐藏或只读，规则所属字段可见且可编辑 | 使用比较来源的可信值正常校验 |
| 字段恢复可见、可编辑 | 重新校验当前数据，不能沿用旧结果 |
| 可编辑字段位于收起容器或未选中 Tab | 正常校验并展开定位，不视为业务隐藏 |
| 修改目标字段、修复错误、模式切换改变字段状态 | 依赖与适用状态及时更新，旧错误清除 |
| 多规则和互相引用 | 按序反馈，不产生循环 |
| 删除引用字段或改变类型 | 配置错误可见，拒绝发布 |
| 字符串大整数与高精度小数、不安全整数 Number | 字符串精确比较；不安全整数 Number 报错 |
| 两个请求并发修改参与字段 | 终检和写入使用一致记录版本 |
| 绕过前端提交可见、可编辑字段的非法数据，或伪造隐藏/只读标记 | 服务端根据可信字段状态执行校验并拒绝非法数据 |
| 新增、编辑、审批、嵌入、自定义表单 | 无需选择适用模式，各入口均按可见且可编辑状态执行规则 |
| 复制、导入导出、恢复和清空 | 规则完整往返，旧发布快照行为不变 |
