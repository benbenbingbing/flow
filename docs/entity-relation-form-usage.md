# 实体关系到表单展示

以“全流程验收”关联“需求管理”为例：

1. 需求实体中选择或建立 `zdw_all_id` 字段，用于保存验收记录 ID。可用普通文本字段，或引用全流程验收实体的单值实体引用；字符串长度至少 64，保存并发布需求实体。
2. 在全流程验收实体的“实体关系”中新建关系，选择需求实体及 `zdw_all_id`。这个字段存放验收记录 ID。
3. 设置关系名称和关联数量：一对一表示至多一条需求，一对多表示多条需求。内部关系编码和数据键留空即可，系统自动分配，无需建立 `reqRelation` 同名字段。
4. 保存关系并发布全流程验收实体。需求实体的目标表单或列表也须先发布。
5. 打开全流程验收的表单设计，在左侧“实体关系”中选择该关系。一对一点击“选择表单”，一对多点击“选择列表”。选择目标页面，点击“添加到表单”。
6. 画布和预览直接显示目标页面布局；保存的是当前表单草稿，发布当前表单后运行时生效。

## 数据含义

`需求记录.zdw_all_id = 验收记录.id` 是实际关联条件。

`relationCode` 是关系自身的稳定标识；`dataKey` 是实体聚合详情、版本快照中承载关联数据的属性名。两者都不是关联外键。自定义关系编码允许与业务字段同名，留空的数据键会自动避开当前实体字段和已退役关系键；显式指定冲突数据键时会提示具体冲突。

新建关系默认普通关联，不开启级联删除。历史关系的编码、数据键、所有权和基数不因新建默认值变化而改变。

关联字段按服务端建表规则判断存储类型，不信任手填的 `dbType`。普通文本、下拉、单选等单值 VARCHAR 字段可承载 ID，长度范围为 64～4096；数字、日期、长文本、多值字段和主键本身不能作为承载字段。系统用户、部门等已有固定引用语义的字段，以及声明指向其他实体的引用字段，不因数据库类型相同而允许混用。关系只按完整 ID 等值匹配；一对一匹配到多条记录时仍然报错。

## 展示和保存

- 快捷入口默认直接嵌入、立即加载、仅查看；高级位置和目标独立编辑可在“表单设置 → 关联内容”中配置。
- 已有实体关系的“配置”引用关系编码，并非复制一份可自由修改的关联条件。展示设置继承关联实体、匹配字段和一对一／一对多规则，只选择已发布的目标页面、展示位置及操作权限；不再要求重新配置“数据怎么关联”。需要调整规则时，点击“去实体设计修改关系”，在新标签页中维护。
- 关系不存在、停用或加载失败时禁止保存展示配置；关系的目标或数量变化后，需要重新选择匹配的表单／列表。旧配置若使用接口替代关系取数，须明确移除该接口后才能按实体关系保存，原操作扩展和自定义展示组件仍可使用。
- 表单展示单条关联记录，列表展示与当前记录关联的多条数据。设计态只预览已发布布局，不查询业务记录。
- 新记录尚未保存时提示先保存；没有匹配记录时显示空状态。运行态通过服务端签名上下文限定数据范围，不退回无条件列表查询。
- 目标表单、列表及关系定义在父表单发布时固定版本；改变依赖后重新发布父表单。
- 关联内容的编辑独立保存。已有组成型子表单继续使用原来的聚合提交，本入口不把普通关联改造成随父记录提交的数据。

## 列表中的按钮入口

1. 在列表设计的“关联内容”中配置目标页面、数据关系和显示方式（弹窗、抽屉或页面），保存。
2. 在“工具栏按钮”或“操作列按钮”中添加自定义按钮，执行方式选择“打开关联内容”，选择刚保存的关联内容。
3. 在按钮中设置名称、图标、样式、权限码和适用条件，保存按钮，再发布当前列表。
4. 操作列按钮按当前行打开；工具栏按钮必须选中一条记录，未选或多选时禁用。

关联内容不再自动生成“查看…”按钮。历史的行操作和工具栏关联定义可以直接作为按钮目标，无需重建关系，但需要绑定按钮并重新发布列表。行展开和页面内嵌仍直接展示。
启用的按钮引用已删除、已停用或改成内嵌的关联内容时，发布会提示修改按钮配置；可以先停用或删除按钮再发布。
