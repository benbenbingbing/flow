# 实体关系、页面展示与主从编辑

业务关系只在实体设计中定义一次。表单和列表引用关系，不再自行定义引用字段、反向引用或字段匹配条件。单选、多选实体字段仍用于选择和保存记录 ID；子表单、关联列表改为页面组件，不再新增 `SUB_FORM`、`SUB_LIST` 实体字段。

## 功能与保存边界

| 功能 | 配置入口 | 负责内容 | 保存方式 |
| --- | --- | --- | --- |
| 实体关系 | 实体设计 → 实体关系 | 目标实体、外键、数量、所有权和删除规则 | 定义保存后发布实体 |
| 单选／多选实体字段 | 实体设计 → 字段 | 选择记录并保存 ID | 随当前记录保存字段值 |
| 关联表单／列表 | 表单设置或列表设计 → 关联内容 | 选择实体关系、已发布页面、位置和允许操作 | 普通关联的目标数据独立保存 |
| 子表单／明细编辑 | 表单设计左侧 → 组成关系 | 选择已发布子记录表单，设置布局 | 子数据进入主表草稿，随主表统一提交 |
| 扩展页面 | 关联内容面板 → 扩展页面 | 当前记录的另一张页面，或注册接口提供的数据 | 按页面和受控动作执行，不建立另一套实体关系 |

组成关系的“关联内容”仅用于查看。需要新增或修改子记录时，使用组成关系生成的主从编辑组件。页面不能将组成数据改成独立写入，也不能用数据接口覆盖实体关系的查询规则。

## 定义关系

以“全流程验收”关联“需求管理”为例：

1. 在需求实体中建立 `zdw_all_id`，保存验收记录 ID。可以是单值实体引用，也可以是存储类型兼容的普通 ID 字段。
2. 在验收实体的“实体关系”中选择需求实体和 `zdw_all_id`，配置名称、数量及所有权。内部关系编码和数据键可留空，由系统分配；无需创建同名实体字段。
3. 独立维护的需求选择“普通关联”；随验收一起新增、编辑和删除的需求明细选择“组成关系”。一对一允许至多一条子记录，一对多允许多条。
4. 发布相关实体，再发布目标页面，最后发布引用它的表单或列表。

实际条件为 `需求.zdw_all_id = 验收.id`。`relationCode` 是关系标识；`dataKey` 是聚合数据中的属性名，两者都不是外键。

关联字段按服务端建表规则校验，不信任手填的 `dbType`。普通文本、下拉、单选等单值 VARCHAR 字段可承载 ID，长度为 64～4096。数字、日期、长文本、多值字段和主键本身不能作为承载字段；已有用户、部门或其他实体引用语义也不能被覆盖。按完整 ID 等值匹配，不做隐式类型转换。

同一关系可以双向使用：验收页面查看需求；需求页面查看所属验收。后者从关系目录中的“所属记录”选择，使用同一条关系的反向引用，不需要再创建一条关系。反向始终指向一条所属记录，因此使用表单。

## 表单使用

- **普通关联**：左侧实体关系中，一对一选择表单，一对多选择列表。默认嵌入、立即加载、仅查看。更多位置和操作在“设置 → 关联内容”调整。
- **组成关系**：左侧选择“添加主从编辑”，选择已发布的子记录表单。一对一生成子表单，一对多生成明细编辑，可设置分行或表格布局。主表尚未保存时也可以录入子数据；取消主表不会提交子数据。
- **新增关联内容**：必须先选择已定义的实体关系。目标实体、匹配条件及数量只读；这里只选择展示页面、位置和操作。需要改规则时，“去实体设计修改关系”在新标签页打开定义所在实体。
- **扩展页面**：与普通业务关联分开。可展示当前实体的当前记录，或显式使用已注册的数据接口；仍由服务端校验目标权限、接口能力和字段范围。

从快捷入口或设置面板添加的内嵌关联内容，均按“放置位置”显示在设计画布和预览中：字段之后、区块内、指定 Tab 或表单末尾。设计态读取目标页面的已发布布局，不查询业务数据，也不要求当前主表单已发布或已有记录；“按需加载”只影响运行时取数。预览中的新建、编辑和查看模式均可检查关联布局，真实关联数据仍以发布后的业务页面为准。

关系停用、删除或读取失败时禁止保存展示配置。关系的目标或数量发生变化后，需要重新选择适用的页面。新发布不接受旧的页面字段匹配规则、旧子列表实体字段节点或未绑定关系的主从节点；旧草稿应删除旧展示节点，再按上述入口配置。无需迁移业务数据，也不为旧发布版本做兼容承诺。

普通关联没有来源记录 ID 时提示先保存；没有匹配记录时显示空状态，不查询全部数据。一对一匹配多条记录时明确报错。实体、关系及目标页面使用发布时固定的版本；依赖变更后重新发布宿主页面。

## 列表使用

1. “关联内容 → 新增关联内容”选择实体关系和目标页面，配置抽屉、弹窗、页面、行展开或页面内嵌。
2. 抽屉、弹窗和新页面的按钮在“工具栏按钮”或“操作列按钮”中配置，执行方式选择“打开关联内容”。名称、图标、link 样式、条件和权限沿用统一按钮配置。
3. 操作列按钮使用当前行；工具栏按钮要求恰好选中一条记录。保存按钮并发布列表后生效。

关联内容不自动生成额外按钮。启用的按钮引用失效的关联内容时禁止发布。列表需要编辑组成数据时，从父记录表单的主从编辑组件进行。

- 前端：`npm run test:entity-relations`、`npm run test:form-node-schema`、`node src/__tests__/related-content-page-config.spec.js`。
- 浏览器：`node scripts/entity-relation-browser-test.mjs`，真实 Vue 组件和内存测试接口，覆盖关系定义、正反向引用、表单和列表展示、标准按钮、组成组件录入及主表草稿同步，以及设置面板保存后在字段、区块、Tab 和表单末尾的设计态与预览位置，不修改业务数据。
- 后端：关系目录、普通 ID 校验、保存和发布校验、发布版本固定、反向读取及外键写入、主从节点绑定和聚合保存相关测试。

本次没有新增、修改或删除数据库迁移文件。

## 页面之间传递参数

实体关系负责查找关联记录；页面参数负责把本次打开时的业务值带过去，两者分别配置、同时生效。

1. 在目标表单的“设置 → 输入参数”或目标列表的“输入参数”中声明编码、类型、必填和默认值。
2. 在“参数用途”中指定用途。表单可以初始化可编辑空字段；列表可以给已启用查询的字段增加筛选。参数也可以在初始化数据、数据接口映射中通过 `params.参数编码` 使用。保存并发布目标页面。
3. 打开来源页面的“关联内容”，在展示设置第一步的“参数传递”中添加映射：当前数据字段、当前记录 ID、当前页面参数或固定值。自定义列表按钮的打开表单/打开列表设置也提供相同映射。
4. 保存并发布来源页面，之后打开目标页面即可传参。目标声明有变化时，需要重新发布来源页面以更新固定依赖。

例如：目标声明字符串参数 `projectId`，来源把当前数据的 `project_id` 映射过去。目标表单可将 `projectId` 初始化到“所属项目”，目标列表可用它筛选 `project_id`；接口取值使用 `params.projectId`。

- 来源表单读取本次编辑的最新值（包含未保存修改）；列表操作列读取当前行，工具栏读取唯一选中行。工具栏需要行字段或记录 ID 时，未选或多选都会提示，不会默认取第一行。
- 初始化只补空字段，不覆盖用户编辑、已有记录值、只读字段或主键。组成子表单继续使用既有父子参数映射，并复用目标页面声明的用途，关联外键受保护。
- 只读关联同样能接收参数、执行查询。传参不会开放编辑、新增或解除关系等权限。
- 列表参数条件与实体关系、固定条件及权限范围同时生效。同字段条件冲突时返回空结果，不允许参数扩大关系范围。需要参数却未收到、或类型不匹配时，页面提示错误。
- 依赖实体关系的展示仍需要来源记录身份；传入业务参数不代替保存主记录，也不改变关系匹配规则。
