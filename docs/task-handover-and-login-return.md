# 人员交接与登录回跳

## 人员交接

入口为「系统管理 → 人员交接」，地址 `/system/task-handover`。

1. 点击待交接人员，使用与其他页面一致的人员选择弹窗搜索并选择；来源账号可以正常、禁用或已逻辑删除。
2. 查看全部未完成责任，包括已分配任务、候选任务、加签任务以及等待/暂缓任务。
3. 跨页勾选后执行「交接选中待办」，或者执行「交接全部待办」。全部范围以提交时重新查询的结果为准，不受分页限制。
4. 在人员选择弹窗中选择正常且未删除的接收人，填写原因，确认交接。来源与接收人不能相同；取消弹窗保留原选择。

交接不会完成审批、推进流程或重置 SLA。加签任务保留处理顺序和 TODO/HOLD 状态；原任务保留等待状态。候选任务会被明确分配给接收人，其他候选人不能继续办理该任务。同一轮加签的多个独立任务可以交给同一个人，仍需逐项办理。

提交时再次检查接收人状态和任务归属。某项任务已被完成、认领或交接，或者写入失败时，整批回滚，页面保留错误提示供刷新后重试。每项任务记录来源、接收人、管理员和交接原因，并记录系统审计。

已提交审批、正在等待加签的原任务在交接后仍保留原提交人的审批归属。如果需要接收人补选下一审批人，则由接收人在待办中继续确认。

### 权限与接口

| 用途 | 权限 / 接口 |
| --- | --- |
| 菜单及查询 | `system:task-handover:view` |
| 执行交接 | `system:task-handover:transfer` |
| 搜索人员 | `GET /api/task-handover/users?keyword=…&targetOnly=false` |
| 来源待办 | `GET /api/task-handover/tasks?sourceUserId=…&pageNum=1&pageSize=20` |
| 批量交接 | `POST /api/task-handover/transfer` |

交接请求包含 `sourceUserId`、`targetUserId`、`taskIds`、`all` 和 `reason`。`all=true` 时查询来源的全部当前任务，否则必须指定非空 `taskIds`。成功响应包含实际交接数 `transferredCount`。

迁移默认授予现有 `super_admin` 角色菜单与交接权限。其他管理员需要在角色管理中授权；普通节点的「允许转办」设置不影响这项管理操作。

## 登录后回到原单据

电脑端与移动端在未登录访问具体页面时保留目标路由，登录成功后返回该地址，并保留查询参数和锚点。登录失败或刷新登录页不会清空目标；会话失效重新登录也保留原页面。电脑端要求修改初始密码时，完成改密并用新密码重新登录后继续返回目标。

没有有效目标地址时沿用各端默认首页。只接受站内路由，外部地址、协议相对地址、歧义路径和登录页循环会被拒绝。

## 发布

本次只新增两个 Java Flyway 迁移，没有修改、删除或重命名已有版本迁移：

- `V110__task_handover_menu.java`：新增系统管理菜单、交接按钮及超级管理员授权。
- `V111__allow_add_sign_task_handover.java`：将加签人员的 `(add_sign_id, user_id)` 唯一约束改为普通查询索引，保留 `generated_task_id` 唯一性，支持多个独立加签任务交给同一人。

按现有部署流程先运行迁移器，再部署后端及前端。重新登录后加载新增菜单和权限。本次开发验证使用隔离测试数据库及模拟接口，没有对运行中业务数据库执行迁移。

## 验证范围

- 身份目录、权限菜单和迁移测试覆盖禁用/删除来源、正常接收人、重复迁移以及约束变更。
- H2 中运行实际 MyBatis 查询，验证候选用户/用户组/角色、加签存活状态、分页与全部查询。
- 真实 Spring + Flowable + MyBatis 共用 H2 事务，验证整批成功、第二条镜像失败、第二条日志失败及独立连接不可见未提交数据；SLA 适配器仅验证参与同一事务且不改变计时字段。
- 前端测试覆盖跨页勾选、全部范围、权限、确认取消和错误状态；浏览器验收使用模拟接口。
- 登录回跳覆盖目标参数、无效目标、刷新、登录失败、会话失效与正常登录。

H2 的兼容模式和数据库目录模拟测试不代替各目标数据库的实际升级验收。

专项回归及前端构建通过。全仓 `test:maintainability` 仍被已有文件的行数超限阻断，例如 `FlowActionConfigPanel.vue`、`FormButtonConfigPanel.vue`、`ListButtonConfigPanel.vue` 和 `NodeConfigPanel.vue`；本次未放宽预算或扩大范围重构这些文件。
