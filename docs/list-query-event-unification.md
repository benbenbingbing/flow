# 列表查询事件合并与上下文绑定核查

## 配置入口

- 自定义查询：列表设计顶部“事件绑定” → “加载列表（LIST_LOAD）” → 添加“替代平台处理”步骤。接口接收 `filters`、`pageNum`、`pageSize`、`scene`，返回 `records`、`total`、`pageNum`、`pageSize`。前置和后置步骤继续沿用统一事件链。
- 固定条件：列表设置 → 访问范围 → 固定条件。使用字段、比较方式和值逐行配置；多条条件必须同时满足，保存后需发布，底层仍使用原有 JSON 对象。
- 上下文绑定：已移除列表设计入口、接口字段和业务资产中的配置；新增 V095 删除草稿存储列及其数据。

固定条件示例：

```json
{"status":"RUNNING","status_op":"EQ"}
```

多个状态：

```json
{"status":["RUNNING","APPROVED"],"status_op":"IN"}
```

省略 `_op` 时按 EQ；多个字段同时满足。`{}` 表示不附加固定条件。无论列表是否绑定 ALLOW 规则，固定条件都与数据范围取交集；未绑定时仍执行原有的拒绝全部、仅本人或显式允许全部策略。它不是可以被用户覆盖的查询框默认值，也不授予数据权限。

事件前置步骤或参数映射清空、改写 `filters` 后，平台会重新应用固定条件。自定义查询返回的候选 ID 还会通过固定条件、可信关联条件与权限查询复核；不满足条件时整页拒绝，不能仅靠接口承诺遵守条件。此类复核分页沿用已验证窗口与下一页哨兵，不直接透传接口声称的总数。

## 固定条件可视化编辑

列表设置的访问范围使用“字段 / 比较方式 / 值”条件行，支持增删、范围和多值输入，全部条件按 AND 生效。未填写完整或重复字段会阻止保存。旧条件未编辑时原样回写，特殊配置只读保留并可显式删除；未完成的条件同样触发未保存提醒。

存储仍是 `fixedFilterConfig` 对象以及字段 `_op`、`_start`、`_end` 约定，本次无新增、修改或删除数据库迁移。转换单元测试、相关列表/等价代码/JSON 帮助测试及管理端构建通过；模拟 API 的宽屏（1920px）与窄屏（1000px）浏览器验证确认增删、范围、多值、false/0 保存结果。既有配置帮助全量审计仍要求已退役的 `entityList.queryInterfaceExtension` 入口，未改动该过期断言。
