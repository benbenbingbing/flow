# 动态列表与表单配置架构

## 目标

- 常规列表、查询、列展示、表单布局、字段校验和模式权限通过配置完成。
- 高定制需求通过显式注册的后端提供者或前端组件实现。
- 配置不允许执行 JavaScript、Groovy 或自由 SQL。
- 配置设计、运行时渲染和服务端校验使用同一份扩展元数据。

## 分层模型

### 列表

1. 实体字段：`ENTITY_FIELD`。
2. 声明式虚拟列：例如 `FIELD_TEMPLATE`。
3. 自定义数据提供者：`ListFieldDataProvider`。
4. 自定义单元格：`registerCellComponent`。
5. 整页自定义列表：`registerCustomListComponent`。

### 表单

1. 内置字段组件与结构化配置。
2. 自定义字段组件：`registerFormFieldComponent`。
3. 整表单组件：`registerCustomFormComponent`。

## 配置存储

- `entity_list_config.view_config`
  - 查询区域、表格、分页、自定义列表组件参数。
- `entity_list_field.column_config`
  - 固定位置、最小宽度、溢出提示。
- `entity_list_field.query_config`
  - 查询组件、占位提示、默认值。
- `entity_list_field.render_config`
  - 单元格组件参数。
- `entity_list_action.action_params_document`
  - 行按钮功能映射：`mappedFieldCode` 为字段编码，`hideWhenMapped` 为映射后是否隐藏操作列按钮。
- `entity_form.view_config`
  - 标签宽度、自定义表单组件参数。
- `entity_form_field.validation_rules`
  - 长度、数值范围、预设格式。
- `entity_form_field.extension_config`
  - 新增、编辑、审批、查看四种模式的显隐和编辑权限。

公共、高频、需要索引或查询的属性继续使用结构化列；低频扩展属性使用受校验的 JSON。

## 列表按钮功能映射

在“列表设计 → 操作列按钮 → 更多”选择“功能映射”字段，并设置“映射后隐藏按钮”，保存当前按钮并发布列表。
例如“查看”按钮映射到“名称”、隐藏设为“是”，运行时点击蓝色名称即可执行原查看动作。

- 字段选择包含当前列表配置的全部字段（系统字段、普通字段、隐藏字段、虚拟列），不按是否在列表显示过滤。
- 每个按钮映射一个字段；同一字段只允许一个按钮映射，停用按钮仍占用该映射。保存界面与发布校验均检查冲突。
- 标准列表表格复用行按钮分发，内置查看/编辑/审批/删除及函数、业务接口、打开表单/列表/关联内容均沿用原权限、条件、参数、版本和确认流程。组件按钮自行管理交互，暂不支持映射；整页自定义列表需自行适配。
- 可用入口文字为蓝色，支持鼠标、Enter 和空格。规则隐藏或权限不足时只展示原字段内容；禁用入口显示不可用原因。快捷复制不会触发映射动作。
- “映射后隐藏按钮”默认否，只控制操作列入口。映射字段未展示、被删除或映射被清空时保留原按钮；停用动作同时关闭两处入口。所有操作都隐藏时不留下空操作列。
- 映射保存到按钮扩展参数并随列表发布快照保留，无须新增数据库迁移。

## 虚拟查询

列表服务先根据字段配置拆分条件：

- 实体字段条件进入动态 SQL。
- 扩展字段条件不会进入 SQL。
- 扩展提供者补充值后，由 `ListFieldConditionEvaluator` 使用白名单操作符过滤。

数据权限在扩展计算前已执行。扩展查询的数据源未注册时拒绝查询，不能退化为未过滤结果。

## 扩展元数据

前后端扩展都声明：

- 稳定编码。
- 管理员可见名称和说明。
- 是否支持虚拟字段、查询或特定运行模式。
- `configSchema`。
- 可选能力描述。

设计器依据元数据生成配置界面；保存时后端再次校验。

## 工具栏选择要求与列表勾选

- 普通列表的选择行为仅有“不可选择”和“可选择”，分别保存为 `selectionConfig.selectionMode=NONE/MULTIPLE`；历史 `SINGLE` 在普通列表中按允许多选展示，表单选择器及调用方显式指定的单选仍保留。
- 自定义工具栏按钮在“更多设置”中配置 `selectionRequirement`：`NONE`（无需选择，已勾选也可执行）、`SINGLE`（恰好一条）、`AT_LEAST_ONE`（至少一条）。字段保存在现有 `actionParamsDocument`，随按钮保存及列表发布快照传递，无需数据库迁移。
- 打开关联内容、打开页面且参数引用 `FIELD/RECORD_ID` 时要求唯一来源记录，不能放宽为无需选择或至少一条。内置批量删除、导出选中继续要求至少一条。
- 已启用按钮需要数据时自动开启勾选入口；数量不满足时按钮禁用并显示原因，自定义组件同样受点击守卫约束。需要选择的按钮按所有选中记录汇总显示及启用条件。
- 业务接口按钮执行时，服务端读取固定发布快照，对去空、去重后的 ID 校验选择要求，再读取权威记录并校验条件；既有单次处理上限保持不变。
- “打开列表”按钮的 `selectionMode` 只控制目标选择器；弹窗/抽屉中的普通勾选列表不会因此自动隐藏工具栏或出现“确认选择”。

## 兼容策略

- 原注册方法签名继续可用，新增 metadata 参数为可选。
- 原列表和表单配置字段继续保留。
- 未配置高级 JSON 时使用默认值。
- 历史未注册展示型数据源可以继续打开列表，但不能用于查询；再次保存时必须选择有效提供者。
- 自定义组件未注册时回退默认动态渲染。

## 安全约束

- 扩展编码使用安全标识符。
- JSON 限制长度、数组数量、对象数量和最大深度。
- 拒绝 `__proto__`、`prototype`、`constructor` 等危险键。
- 列表扩展失败不允许绕过数据过滤。
- 前端能力只用于展示，编辑、删除、审批仍由后端重新校验。

## 验收范围

- 实体列、隐藏查询列、虚拟展示列、虚拟查询列。
- 查询操作符、空值、数值范围和 IN。
- 列固定、宽度、溢出、表格尺寸、分页配置。
- 新增、编辑、审批、查看四种字段模式。
- 结构化校验、自定义字段组件、整表单组件。
- 未注册扩展、非法 JSON、重复编码、错误模式和错误类型。
