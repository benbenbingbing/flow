# 表单自定义按钮执行方式

> 路径与命令：本文的 `workflow-web/`、`workflow-mobile/`、`packages/`、`extensions/` 和前端 `scripts/` 相对 `workflow-frontend/`；前端 npm/Node 命令从该工作区执行。`workflow-server/`、`docs/`、`deploy/` 仍相对仓库根目录。

表单设计 → 设置 → 按钮与操作 → 添加自定义按钮，在“执行方式”或“更多”中配置动作。配置完成后启用按钮、保存草稿并发布表单。旧按钮默认继续使用事件链，不需要迁移。

| 执行方式 | 配置内容与运行行为 |
| --- | --- |
| 业务接口 / 事件链 | 保存按钮后，通过表格的“事件链”配置执行步骤，保持原有行为。 |
| 函数 | 输入已注册的动作函数名称，接收当前表单数据、模式及记录上下文。 |
| 组件 | 选择已注册的表单组件，以弹窗打开。组件编辑使用独立草稿，“应用到当前表单”通过组件校验后回填，主表保存时提交；关闭不回填。查看模式只读。 |
| 打开列表 | 选择目标实体及已发布列表，支持弹窗、抽屉。 |
| 打开表单 | 选择目标实体及已发布表单，支持新增、编辑和查看。编辑/查看可指定当前字段作为目标记录 ID 来源；引用对象取其 `id`。未指定时仅允许使用同一实体的当前记录。 |
| 打开关联内容 | 选择当前表单已配置的关联内容，沿用关系、目标页面、参数传递及打开方式。 |

## 自定义按钮打开子表单

1. 在实体关系中添加关联表单，完成目标表单、关系和操作配置。
2. 在关联属性中，将展示方式设为弹窗、抽屉或全屏打开。
3. 新增表单自定义按钮，执行方式选“打开关联内容”，选中上述关联内容。
4. 设置按钮显示位置、权限码和适用模式，保存并发布。

运行时需要先保存主表记录，才能根据主表 ID 查找关联数据。按钮沿用关联的可见条件和数据权限；嵌入页面及 Tab 展示的关联不进入此目标列表。

## 扩展开发约定

- 函数复用已有动作注册中心（`LIST_ACTION` 扩展），按行函数、工具栏函数顺序查找。上下文包含 `formData`、`recordId`、`entityCode`、`mode`、`row` 和 `selectedRows`；`row` 为当前草稿与记录 ID，未保存记录的 `selectedRows` 为空。函数应使用表单上下文，不能依赖列表实例专有方法。返回的 `message`、`effects` 沿用表单事件结果处理。
- 组件复用 `FORM` 扩展，并钉定选择时的版本与制品摘要。接收 `form`、`modelValue`、`fields`、`entityFields`、`entityDefinition`、`mode`、`readonly`、`context` 等属性；通过 `update:modelValue` 更新弹窗草稿，通过 `validate()` 校验应用。弹窗组件负责自身交互，主表保存仍执行主表校验。该弹窗不提供列表宿主方法或内嵌动作插槽。
- 打开列表会在上下文提供 `sourceFormData` 和 `sourceRecordId`。打开关联内容使用已有参数映射；打开普通表单不自动建立关联或复制主表字段。
- 点击时重新解析服务端发布配置、按钮权限及启用条件；使用服务端返回的目标，目标页面继续执行自己的读取和保存权限检查。
- 切换执行方式会清空原执行目标。旧事件绑定不会随切换自动删除，但非事件链按钮不能执行遗留绑定。

本次运行宿主为 PC 数据表单及查看/审批弹窗。移动端尚未接入这些快捷执行方式，保留原事件链支持。部署需要同时更新前后端；无数据库迁移。

## 验证

- `npm run test:form-buttons`：配置归一化与持久化、必要字段、服务端目标、权限、关闭后的异步防护、旧事件链。
- `npm run test:form-buttons:browser`：隔离测试数据下的六种配置选项、函数上下文、组件草稿与回填、列表、关联子表单、普通表单新增/编辑/查看。
- 后端 `EntityFormActionConfigPolicyTest`、`EntityFormActionServiceTest`：配置校验及运行时发布参数。
