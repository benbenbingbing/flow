# 用代码复用已有表单和列表的方案

日期：2026-10-14。状态：建议方案，尚未实施。本文替代此前的配置继承方案；下列 SDK 名称和代码是拟议接口，不代表当前已可直接使用。

## 1. 目标与取舍

开发者写一个 Vue/TypeScript 组件，直接使用现有表单或列表的运行能力和标准界面，只编写需要变化的部分。复杂需求可以逐步接管更多界面和交互，业务代码正常评审、测试、构建和部署。

不增加设计器配置项、基础配置选择器、差异 JSON、数据库继承字段或专门的派生发布流程。已有 FORM/LIST 注册清单与组件绑定方式继续使用；新的复用方式由代码表达。

核心关系：

> 自定义页面 = 已有页面的运行实例 + 可复用标准组件 + 自己的 Vue/TypeScript 代码。

“基于哪个页面”是代码引用；“改哪里、怎么改”是组件组合、插槽和函数。平台提供稳定的编程接口，不把每一种业务改动转成设计器选项。

## 2. 对外提供三层代码能力

| 层次 | 建议 API | 开发者如何使用 |
| --- | --- | --- |
| 页面入口 | `FormPage` / `ListPage` | 在自定义页面中指定已有来源，加载并建立对应运行实例 |
| 标准视图与部件 | `BaseForm` / `BaseList`，以及字段、查询区、工具栏、表格、分页等部件 | 默认显示完整标准界面，通过插槽局部替换，也可拆开自由排版 |
| 无界面的运行能力 | `useFormRuntime` / `useListRuntime` | 完全自行绘制界面，复用数据、联动、校验、查询及动作调用 |

三层共享同一套运行逻辑。更换视图不重新创建运行实例；组合多个标准部件也不会各自加载数据。

### 2.1 表单例子：只替换预算输入

下面示意独立自定义页面直接引用已发布的 `project_standard` 表单。`launch` 由业务入口提供记录、模式、任务等定位信息，服务端重新验证；源码中的来源键不构成授权。

```vue
<script setup lang="ts">
import { FormPage, BaseForm } from '@/extensions/sdk'
import BudgetEditor from './BudgetEditor.vue'

const props = defineProps<{ launch: Record<string, unknown> }>()
</script>

<template>
  <FormPage
    :source="{ entityCode: 'project', formKey: 'project_standard' }"
    :launch="props.launch"
    v-slot="{ runtime }"
  >
    <BaseForm :runtime="runtime">
      <template #node-budget="{ input }">
        <BudgetEditor v-bind="input" />
      </template>
    </BaseForm>
  </FormPage>
</template>
```

`node-budget` 中的 `budget` 是基础表单的稳定 `nodeKey`。`input` 是 SDK 适配的输入绑定，包含当前值、更新/失焦回调、禁用和只读等状态。字段外层继续呈现原有标签、显隐、必填和错误信息；标准联动、跨字段校验和唯一性检查继续运行。

业务控件可以写复杂交互、计算和多字段更新。SDK 另外提供 `runtime.patchValues()`，通过同一更新通道触发联动与校验。默认字段呈现保持可调用，插槽可以包住默认内容再补充提示。

### 2.2 列表例子：保留标准列表，增加统计并替换一列

```vue
<script setup lang="ts">
import { ListPage, BaseList } from '@/extensions/sdk'
import PageSummary from './PageSummary.vue'
import ProgressCell from './ProgressCell.vue'
</script>

<template>
  <ListPage
    :source="{ entityCode: 'project', listKey: 'project_standard' }"
    v-slot="{ runtime }"
  >
    <BaseList :runtime="runtime">
      <template #table-before>
        <PageSummary :rows="runtime.rows" />
      </template>
      <template #cell-progress="{ value, row }">
        <ProgressCell :value="value" :record="row" />
      </template>
    </BaseList>
  </ListPage>
</template>
```

未覆盖的查询区、工具栏、其他列、勾选、行操作和分页继续使用标准实现。单元格内容替换保留外围的字段脱敏、功能映射及操作守卫。`PageSummary` 只统计当前页；需要全量汇总时由业务接口按服务端认可的权限和筛选范围计算。

### 2.3 布局变化很大时，直接组合部件

开发者可以取同一个 runtime，自己排列 `FormNode`、`FormActions` 或 `ListSearch`、`ListToolbar`、`ListTable`、`ListPagination`；也可以直接用普通 Vue 组件绘制界面。

插槽用于方便地保留默认界面，不是自定义能力的上限。涉及专门业务请求、异步交互和计算时直接写函数，并按已有业务接口的权限要求执行。

## 3. 在现有自定义组件中怎么使用

现有自定义 FORM/LIST 组件已经运行在宿主内部，因此提供 `useCurrentFormRuntime()` / `useCurrentListRuntime()` 获取当前实例。通过 `BaseForm` / `BaseList` 复用默认视图，不再新建 `FormPage` / `ListPage`。

表单示意：

```ts
const runtime = useCurrentFormRuntime()

// 保留现有整表单组件校验契约，委托给单一运行实例的校验链。
defineExpose({ validate: () => runtime.validate() })
```

这里的 `runtime.validate()` 执行标准校验和已登记的业务校验，不再次回调外层组件的 `validate()`，避免循环。外层提交协调器只执行这一条校验链，兼容旧组件时也不能重复运行同一规则。

`BaseForm` / `BaseList` 始终呈现标准内容，不再读取整页 `customComponent` 来选择自身。字段和单元格自定义扩展继续保留。这样可以直接“用标准页面包住一点自定义内容”，无需在业务组件里手动清空组件名来规避递归。

如果基础是自己写的 Vue 组件，直接 import 并用 props、slots、composables 复用；可进一步把多个业务页面共享的布局写成普通业务组件。使用组合方式即可，不要求通过 Vue 的组件继承机制实现。

## 4. 必须区分来源与当前业务身份

### 独立代码页面引用已有 B

`FormPage(source=B)` 把 B 作为业务主体：加载配置、字段、事件、动作、校验和提交都使用服务端认可的 B 身份与上下文。自定义 Vue 页面只是呈现层，不需要再新建一张空的 A 表单来装它。

列表同理，`ListPage(source=B)` 的查询、导出和动作都使用 B 的运行身份。跨环境引用优先采用实体编码加表单键/列表键；也允许业务入口已经提供经过解析的 ID。

### 已经处于 A 的表单/列表宿主中

通过 `useCurrent...Runtime()` 复用 A。前端不能只加载 B 的字段，就声称后端已按 B 校验和提交。

需要把 B 作为实际业务主体时，应在页面入口建立经过授权的 B 运行实例。流程办理场景必须符合服务端当前节点的绑定，关联内容和 Embed 必须符合各自授权入口；不能在 A 的任务上下文里靠代码指定 B 来更换审批表单。

如果只是借用 B 的排版，开发者可以把公共布局抽成 Vue 组件，仍使用 A 的运行实例；此时校验与业务规则明确属于 A。若两个独立来源分别展示在同一页，它们各自拥有提交边界；需要原子联动保存时通过后端业务服务实现。

## 5. Runtime 应开放的能力

| 表单运行能力 | 列表运行能力 |
| --- | --- |
| 当前值、字段/节点状态、模式、只读、错误 | 当前记录、查询条件、总数、分页、选中记录 |
| 字段更新、多字段补丁、错误定位 | 查询、重置、刷新、分页、更新选中项 |
| 校验及业务校验函数登记/释放 | 读取可用按钮、禁用原因并触发相应动作 |
| 读取并执行当前允许的表单动作 | 复用新增、查看、编辑、删除、导入导出等已有处理 |
| 加载、校验、提交、保存完成等生命周期钩子 | 加载、查询、动作完成等生命周期钩子 |

生命周期钩子通过函数注册，并随组件卸载自动释放。异步钩子按明确顺序 await，一次提交只执行一次；若提交前钩子返回数据补丁，应先应用补丁，再运行校验，最后提交。

提交方法遵循入口能力：独立编辑页可以拥有保存动作，流程页通过原办理协调器执行，子表单只更新其父级模型。不能让每个字段视图都生成一个保存入口。

允许代码对视图模型做排序、组合、局部隐藏和展示计算，不改写发布配置对象、运行摘要或权限字段。服务端会执行的校验、数据源和业务规则若需要改变，应编写对应后端业务实现或使用既有扩展机制；前端函数不能单独改变服务端规则。

## 6. 与当前代码的接入位置

| 当前代码 | 建议调整 |
| --- | --- |
| `FormPreviewLinkage.vue`、`EntityDataFormFields.vue` | 抽出并统一运行状态与校验协调；标准视图消费 runtime；新旧组件契约用适配器衔接 |
| `FormNodeRenderer.vue`、`FormNodeRuntimeItem.vue` | 贯通稳定 nodeKey 对应的插槽和默认节点呈现能力 |
| `EntityDataList.vue` | 抽出列表运行能力，查询/动作/弹窗协调集中到宿主，标准视图与自定义视图共享 |
| `EntityDataSearchForm.vue`、`EntityDataTable.vue` | 形成可公开复用的部件，完整保留勾选、映射动作、权限和条件检查 |
| `extensions/contracts/form.js`、`list.js` | 增加 runtime 的公开 TypeScript 类型和兼容适配，旧 props/emits 继续可用 |
| `CustomFormTemplate.vue`、`CustomListTemplate.vue` | 更新为使用公共 SDK 的简洁样例，验证业务组件只需编写差异 |
| `packages/workflow-api` | 封装已发布来源解析，复用现有请求和运行接口 |

先在 `workflow-web/src/extensions/sdk` 建立稳定导出入口；实现仍可复用现有文件，业务组件不需要依赖页面内部函数和深层文件路径。PC 组件与移动端组件分别实现，共享适合共用的运行逻辑和类型。

现有列表已有按实体编码、列表键读取运行 Schema 的接口。表单运行接口目前按 ID 读取；若要支持示例中的 formKey，应补充面向运行场景的服务端键解析，随后进入同一发布读取及鉴权链，不调用设计器草稿接口替代。

入口适配同时覆盖数据读写协调、流程办理和关联内容协议，不能认为“能读取 Schema”就已经完成编辑提交接入。

## 7. 发布、升级与代码依赖

- 基础配置仍按现有机制发布；代码组件按现有扩展制品规则构建、部署并更新绑定。单纯共享 Vue 代码与独立业务页面遵循应用部署流程。
- 表单继续读取当前发布配置并校验配置摘要；列表按实际运行入口的发布身份工作，历史或嵌入入口仍使用其允许的身份，不能私自切换到最新版本。
- 来源配置对象不经过差异合并，不创建派生配置快照，也不新增基础配置更新按钮。
- 代码依赖 nodeKey、fieldCode 和动作键。建议 SDK 支持开发期断言，例如要求预算节点存在；关键替换目标失效时报告清晰错误，不能悄悄忽略定制。
- 纯代码引用无法自动获得数据库继承关系的删除保护和全量影响分析。由源码声明、部署前冒烟和运行时来源检查覆盖；不要承诺平台能静态识别所有动态计算的来源。
- 来源变化时先处理未保存内容，再重建运行实例；取消过期请求并隔离旧响应，防止记录或任务切换后串用旧数据。

## 8. 实施顺序与验收

1. **形成单一 runtime 和标准视图。** 先让现有自定义组件通过当前实例复用标准内容，完成一个预算字段替换和一个列表统计区域样例。
2. **提供代码页面入口。** 实现指定已有来源的 FormPage/ListPage，包括身份解析、数据加载、提交协调及原场景鉴权。
3. **开放部件组合和生命周期函数。** 为复杂界面提供稳定类型、错误语义和扩展样例，统一注册释放、并发和请求取消行为。
4. **覆盖实际入口。** 验证普通页、流程页、选择器、关联内容及 Embed；移动端按同一契约适配，未支持场景明确报错。

核心验收：

- 没有任何插槽覆盖时，公共标准视图保留原页面行为。
- 替换一个字段后，读写、联动、只读、错误定位和服务端校验仍正确。
- 定制列表后，筛选、分页、勾选、按钮映射、导出范围和动作权限仍正确。
- 同一页面只有一个运行实例；一次操作只触发一次请求、校验链和提交。
- 自定义组件引用标准视图不会递归装载自身；视图卸载后无残留钩子或请求回写。
- 指定 B 来源的独立页始终按 B 执行；错误的任务、记录、关联或 Embed 上下文被拒绝。
- 代码引用失效、基础配置更新、旧页面提交和不支持的运行端能够给出明确反馈。
