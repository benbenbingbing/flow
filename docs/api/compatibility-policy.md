# Embed 外部接口兼容与发布策略

## 契约边界

当前对外只保留以下机器接入边界：

- OAuth 2.0 Client Credentials Token 端点 `/oauth2/token`；
- Embed Launch 端点 `POST /api/open/v1/embed-launches`。

请求、响应、错误和安全要求以
[`embed-v1.yaml`](embed-v1.yaml) 为准。OAuth 不签发或校验业务 Scope；有效机器令牌只能
访问上述 Embed Launch 路由。管理 API、管理页面、数据库结构、内部 Java 类型以及未写入
该 OpenAPI 的端点不构成外部兼容承诺。

同一主版本允许新增可选请求能力和可选响应字段，但不得删除字段、缩窄取值、改变字段
语义、认证方式或既有错误码。客户端必须忽略未知响应字段，并对未知枚举值安全兜底。

## V084 退役背景

V084 删除的公共流程 API、场景、Webhook、Connector、Secret、Scope 和流程授权，没有具名
真实接入方或生产流量证据；仓库中的外部系统、客户端和 k3s 内容均为参考实现或验收脚本，
不是用户采用证明。本次收缩是 [ADR-0007](../architecture/decisions/0007-retire-open-process-integration.md)
记录的产品退役决策，不代表已发布外部契约可以在后续版本中静默删除。

保留边界一旦发生破坏性变更，必须发布新的 URL 主版本，或先执行正式退役流程：盘点具名
消费者、公告影响和替代方案、提供并行迁移窗口与迁移示例、用调用指标确认退出，并在窗口
结束后另行删除。数据库 contract migration 必须晚于旧版本应用和在途请求完全退出。

## 变更流程

1. 修改实现前先更新 `embed-v1.yaml`，说明兼容性判断并同步契约测试。
2. CI 比较当前 OpenAPI 与已发布基线；未升级主版本的破坏性差异必须阻断合并。
3. 字段或行为退役先标记文档并增加使用指标，完成消费者通知和迁移窗口后才能删除。
4. 补丁版本只用于安全或正确性修复，不增加新的接入前提；次版本只增加向后兼容能力。
5. 发布说明列出认证、限流、错误、凭据轮换和运维行为变化，并明确接入方是否需要操作。

## 验收与回退

每次发布必须通过 OpenAPI 结构校验、基线差异检查、OAuth/Embed 真实契约测试和滚动发布
验证。应用回退不能撤销已执行的数据库迁移；破坏性迁移必须使用先停止旧读写、再独立执行
contract migration 的发布顺序，并准备经验证的数据库备份或前向修复方案。

发现兼容性回归时，先停止继续发布并恢复兼容的应用镜像；涉及已经执行的破坏性迁移时，
不得假设 `helm rollback` 能恢复数据。安全问题按 `.github/SECURITY.md` 私密报告。
