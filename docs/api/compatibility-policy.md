# 开放集成兼容与发布策略

## 契约边界

`/api/open/v1`、`/oauth2/token` 的公开字段和已发布 CloudEvents Schema 构成 V1 契约。
管理 API、管理页面、数据库结构、内部 Java 类型和未写入 OpenAPI 的端点不提供外部
兼容承诺。

同一主版本允许新增可选响应字段、新事件类型、新的可选请求能力和新枚举值；不删除
字段、不缩窄取值、不改变字段语义、认证方式或既有错误码。客户端必须忽略未知字段，
未知枚举值必须走安全兜底。需要破坏性变更时发布新 URL 主版本，并保留并行迁移窗口。

## 变更流程

1. 修改实现前先更新 OpenAPI 或事件 Schema，并写明兼容性判断。
2. CI 将当前 OpenAPI 与已发布基线比较；未升级主版本的破坏性差异阻断合并。
3. 新增事件先更新目录和 JSON Schema，再开放管理端订阅。
4. 字段废弃先标记文档并增加使用指标，至少经过一个正式发布通知周期。
5. 只有下一主版本可以删除已废弃字段；删除前提供迁移示例和回退方案。

补丁版本用于安全和正确性修复，不引入新的接入前提。次版本可以增加兼容能力。发布说明
应列出 OpenAPI、事件、认证、限流和运维行为变化，并明确是否需要接入方操作。

## 验收与回退

每次发布必须通过 OpenAPI 校验、基线差异检查、Java/JavaScript 真实契约测试、事件
Schema 校验和至少双 Pod 的滚动发布验证。应用回退不能撤销已执行的数据库迁移，因此
迁移必须在约定回退窗口内与上一应用版本兼容。

发现破坏性回归时，先停止继续发布并恢复上一应用镜像；保持数据库向前版本，禁用新增
入口或事件订阅。安全问题按 `.github/SECURITY.md` 私密报告，不能在公开 Issue 中披露
利用细节。
