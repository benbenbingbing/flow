# 已完成流程及关联业务实体导入方案

日期：2026-10-18。状态：首期代码已实现，尚未执行环境数据库迁移。实施与验证记录见 [实施记录](historical-process-import-implementation.md)。

## 1. 目标与范围

将不同技术实现的旧系统中的已完成流程迁入本系统。旧系统无需提供流程图：在本系统重新设计、发布流程，再把旧审批节点映射到指定发布版本。导入后可从业务实体列表打开“迁入历史”，点击图上节点查看对应审批记录。

业务数据与历史记录均通过 XLSX 上传，先联合预检，再按提交组写入。一个批次可包含流程主实体、组成子实体和共享业务实体，也允许只导入业务数据。不会启动流程、恢复运行态、创建任务或写入 Flowable 的 ACT_* 表。

本期不包含在途流程、旧系统直连采集、附件本体及文件引用搬运、自动生成流程图、导入后撤销和档案修订。旧附件字段为必填或含值时明确拒绝，不静默丢弃。

## 2. 配置与模板的关系

采用“系统固定迁移列 + 实体已发布字段 + 导入配置”，无需为每个实体手写一套导入代码。

| 内容 | 生成或配置方式 |
| --- | --- |
| 来源记录 ID、提交组 | 系统固定列 sourceRecordId、groupKey |
| 业务字段、名称、类型、必填 | 从实体已发布定义生成；不使用未发布草稿 |
| 目标实体及 Sheet 名 | 每个批次配置，支持 1～20 个实体 |
| 旧实体 ID 到新 ID 的转换 | 按关联字段配置目标来源实体标识 |
| 历史只读或共享可维护 | 按实体配置；带历史流程的主实体必须只读 |
| 展示流程图 | 固定一个已发布流程版本 |
| 旧审批节点到新节点 | 按旧节点标识配置，支持仅时间线 |
| 审批操作显示 | 可配置显示映射；始终保留原操作 |

本期使用标准列名，不提供任意旧文件列名的可视化映射。旧数据需先整理为下载模板的结构。子表单、子列表不在主 Sheet 内嵌 JSON，而是把对应业务实体加入批次，使用独立 Sheet 和外键来源映射。

来源系统标识应包含必要的旧租户或业务命名空间；同一来源在后续批次保持一致。来源实体标识同时是 Sheet 名和稳定身份的一部分，应为字母开头、最多 26 位的英文、数字或下划线，不能仅靠大小写区分不同 Sheet。旧流程 ID 在来源系统标识内必须唯一；不同旧流程类型有重号时拆分来源命名空间。

## 3. 导入前准备

1. 在本系统设计并发布目标实体及关系，确认动态物理表已建立。
2. 为主从实体定义组成关系和子实体外键；共享关系使用引用字段。
3. 需要展示审批记录时，设计并发布新的 BPMN 流程。
4. 配置导入操作员权限，然后创建批次并下载模板。
5. 将旧 ID 按文本整理，保留大小写、前导零及稳定编号。

系统主键、流程实例 ID、任务状态等运行字段不接受导入。系统审计信息记录实际导入身份和时间；需要保留旧编号、旧创建人等信息时，应建立明确的普通业务字段。使用自定义业务编码生成器的实体暂不支持历史导入，避免取号扩展产生业务副作用。

## 4. 实体数据文件

每个已配置实体一个 Sheet。表头为迁移固定列与该实体可导入的发布字段：

| 列 | 必填 | 含义 |
| --- | --- | --- |
| sourceRecordId | 是 | 稳定的旧记录 ID，按文本保存 |
| groupKey | 是 | 同组实体及关联流程历史一起提交或回滚 |
| 其他发布字段 | 按实体要求 | 按字段编码填写，类型及基础必填规则与发布定义一致 |

系统字段仅开放发布定义中的 name、status、deptId；其他系统及引擎字段不允许夹带。SUB_FORM、SUB_LIST 通过关联实体处理。多选或多引用字段可用英文分号分隔。用户、部门等现有系统对象字段使用本系统有效 ID；本期不提供旧账号自动匹配。审批记录里的人员作为原始名称快照保存。

建议金额和长编号也按文本填写，避免 Excel 在上传前已经改变精度。单元格不接受公式或错误值，不允许未知 Sheet、重复或未知列、表头之外的有效数据。

### 主从和共享业务实体示例

| Sheet / 来源实体标识 | sourceRecordId | groupKey | 业务引用 |
| --- | --- | --- | --- |
| supplier | S001 | supplier_S001 | 无 |
| expense | E001 | expense_E001 | supplierId = S001 |
| expense_item | I001 | expense_E001 | expenseId = E001 |
| expense_item | I002 | expense_E001 | expenseId = E001 |

对应配置：

- expense.supplierId 的旧 ID 来自 supplier。
- expense_item.expenseId 的旧 ID 来自 expense。
- expense 和 expense_item 为历史只读；supplier 可配置为共享可维护。

系统先创建或复用供应商，再在一个事务中创建报销主记录、两条明细、来源映射及流程档案。任何一条失败都会回滚整个报销组；已成功的供应商组保留。

组成父子必须位于同一组，且使用显式来源 ID 转换；只读主记录的组成子实体也必须只读。共享引用可以来自本批次其他组，也可以通过相同来源标识复用以前已导入、当前可读的记录。引用其他批次记录时，该来源实体配置仍需保留，但其 Sheet 可没有新增数据行。

依赖按实体及组两个层次排序。循环依赖直接报错，不通过先填空外键再补写绕过必填约束。多对多关系可建模为独立关联实体并配置两端引用；不自动推断任意中间表。

## 5. 流程历史文件

文件包含“流程概要”和“审批记录”两个固定 Sheet。仅导业务数据时，无需上传此文件或选择流程版本。

### 流程概要

| 列 | 必填 | 规则 |
| --- | --- | --- |
| sourceInstanceId | 是 | 稳定的旧流程实例 ID |
| entityKey | 是 | 对应实体 Sheet 的来源实体标识 |
| sourceRecordId | 是 | 关联本批次实体行 |
| name | 是 | 原流程名称 |
| initiator | 是 | 原发起人名称 |
| startedAt | 否 | 原开始时间，缺失保持为空 |
| endedAt | 否 | 原结束时间，不能早于开始时间 |
| result | 是 | APPROVED、REJECTED、WITHDRAWN、TERMINATED、COMPLETED_UNKNOWN |
| expectedEvents | 是 | 本次该流程的审批行数，允许明确填写 0 |

COMPLETED_UNKNOWN 表示已结束但具体结果未知，不得用于在途流程。一个实体可关联多轮流程，使用不同 sourceInstanceId 分别归档。预检核对每个流程的审批数量，不推断旧系统应有多少轮流程；来源完整性需按旧系统导出总数核对。

### 审批记录

| 列 | 必填 | 规则 |
| --- | --- | --- |
| sourceEventId | 是 | 同一流程内唯一且稳定的旧操作 ID |
| sourceInstanceId | 是 | 对应流程概要 |
| sourceNode | 是 | 旧节点编码或明确唯一的名称，用于映射 |
| actor | 是 | 原审批人名称 |
| action | 是 | 原审批操作 |
| comment | 否 | 原意见，最多 10000 字 |
| handledAt | 否 | 原办理时间 |
| sequence | 是 | 大于 0 的来源顺序；相同序号按稳定事件 ID 排序 |

旧系统无操作 ID 时，数据整理阶段提供可重复使用的稳定编号。转办、退回、同节点重复审批分别保留，不以节点 ID 去重。

时间接受 ISO 本地日期时间或 YYYY-MM-DD HH:mm:ss，也可读取 Excel 日期单元格。本期保存来源本地时间，不做时区或夏令时换算；跨时区数据需先统一口径。缺失时间不会用导入时间补造。

## 6. 预检、执行与幂等

配置和两类上传内容都有批次修订号。上传只暂存解析后的 JSON，不写业务实体；原始 XLSX 二进制不留存。修改配置或重新上传会清除旧预检结果。

联合预检检查：

- 实体发布状态、动态表、导入及创建权限、支持的编码生成方式；
- 字段类型、基础必填、允许列和来源 ID 重复；
- 引用目标、依赖顺序、组成关系同组及只读约束；
- 完成结果、流程关联、审批数量和节点映射；
- 行数、组大小和输入长度限制。

预检保存标准化输入、实体配置指纹、固定 BPMN 和节点映射，并生成 validationHash。正式执行仍通过实体变更管道执行发布字段规则、唯一约束和其他保存约束，因此预检通过不等于业务保存必然成功。

执行一次请求只推进一个指定组，组内事务包含实体、来源映射、关系最终检查、档案及成功进度。父子分 Sheet 写入时仅暂缓必填子集合检查，提交前检查必填关系及一对一数量。失败组整体回滚，错误另行持久化。批次行锁串行化同批次并发请求，数据库来源唯一键约束跨批次重复写入。

| 状态 | 含义 |
| --- | --- |
| DRAFT / UPLOADED | 配置中 / 已上传待预检 |
| READY | 预检通过 |
| RUNNING | 已提交部分组，可以继续 |
| SUCCEEDED | 全部组提交成功 |
| FAILED / PARTIAL_SUCCESS | 有失败组，分别表示尚无成功组 / 已有成功组 |

浏览器按已冻结顺序逐组调用。关闭页面或暂停后不再发起下一组；当前请求可能仍提交成功，重新打开以服务端状态为准。响应丢失时重试同一个 groupKey 仅返回已提交结果，不意外推进下一组。本期没有常驻后台 Worker。

来源实体身份为 sourceSystem + entityKey + sourceRecordId；来源流程身份为 sourceSystem + sourceInstanceId。身份按带长度分隔的 SHA-256 摘要存储，避免数据库排序规则混淆大小写或前导零。相同来源且内容、目标、配置一致时复用，冲突时报错，绝不静默覆盖。

开始执行后配置及文件冻结。临时故障可重试失败组；需改文件或配置时复制配置新建批次。已成功组保留，并可在新批次按来源一致性复用。实体发布结构变化时停止执行，要求重新建批次预检。

## 7. 档案查看与数据保护

档案保存固定流程版本的 BPMN XML、节点映射、完整事件数组、实体字段标签及本次最终业务数据，以及同组实体和直接引用的共享实体快照。共享实体后续业务修改不改写已保存快照。

点击图上节点展示该节点全部迁入事件；多个旧节点可映射到同一新节点。无法映射的节点必须明确选 TIMELINE_ONLY，仍进入完整时间线。图上只标记迁入记录数量，不据新图推断旧路径、网关选择或引擎执行状态。

业务快照按标签和值只读展示，不执行表单事件、自定义脚本或远程数据源。它代表本次导入的最终业务数据，不代表每个审批节点或每轮流程当时的数据。本期不恢复旧表单布局。实体原生 processStatus 维持普通未启动状态；历史结束结果单独显示在档案，不伪装成本系统引擎实例。

历史只读记录在公共写入管道、普通编辑删除、关系更新删除及流程启动入口受保护。共享可维护实体允许后续正常维护。档案文档本身不提供更新接口。

读取档案需重新检查主记录权限和数据范围；关联快照逐条授权，不可读关联不返回。展示字段按历史字段、当前发布字段和当前可读数据键取交集，删除的字段不继续外露。审批记录及图只在主记录授权通过后返回。富文本按普通文本展示。

| 表 | 用途 |

菜单位于“系统管理 / 历史数据导入”，地址 /system/history-import。权限为 history-import:read、history-import:execute、process:archive:read；此外要求对应实体 import/create/view 和当前数据范围权限。批次仅本人可查看和推进，管理员身份不绕过批次所有权。超级管理员按系统既有规则取得菜单和权限，普通角色需要明确分配。

## 9. API 与资源约束

遵循仓库既有 GET/POST 约定，所有接口均须登录并执行权限或所有权检查。

| 方法与路径 | 作用 |
| --- | --- |
| GET /api/history-import/catalog | 可选实体及已发布流程版本 |
| GET /api/history-import/batches | 本人批次分页 |
| POST /api/history-import/batches | 创建配置和批次 |
| GET /api/history-import/batches/{id} | 配置、预检数量及组进度 |
| POST /api/history-import/batches/{id}/plan | 更新配置，携带 revision |
| GET /api/history-import/batches/{id}/templates/{entities\|history} | XLSX 模板 |
| POST /api/history-import/batches/{id}/files/{entities\|history} | file + revision |
| POST /api/history-import/batches/{id}/validate | 联合预检，携带 revision |
| POST /api/history-import/batches/{id}/execute | validationHash + groupKey + retry |
| GET /api/process-archives | 按 entityCode、recordId 查询档案列表 |
| GET /api/process-archives/{id} | 已授权的档案详情 |

执行报告由页面下载当前批次 JSON，包含数量、逐组结果、原 ID 到目标 ID 及错误。预检失败通过接口和页面反馈，尚无逐行错误 Excel 下载。

单文件最多 10 MB，最多 20 个实体 Sheet；实体、流程概要和审批合计最多 2000 行，单组最多 200 条实体，单元格最多 10000 字。执行组事务超时为 60 秒；大规模迁移按可独立提交的批次拆分。

## 10. 验收要点

1. 模板能随已发布实体字段生成，并导入主实体、明细及共享引用。
2. 主从同组失败时实体、来源映射和档案全部回滚。
3. 重试、重复批次及同组并发不产生重复记录；不同内容发生冲突。
4. 两次相同节点审批均可从图上打开，只有时间线的记录不丢失。
5. 后续流程发布和共享数据编辑不改写档案内容。
6. 非所有者不能读取批次；权限收回后不能读取对应实体档案。
7. 只读历史记录不能正常修改、删除或启动原生流程。
8. 前端构建、后端针对性测试、架构检查与浏览器交互验证均有记录；实际 MySQL 环境仍需按迁移部署步骤验收。
