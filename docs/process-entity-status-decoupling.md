# 流程生命周期与实体业务状态解耦

## 已实现的规则

| 字段 | 业务含义 | 谁可以修改 |
| --- | --- | --- |
| `status` | 实体业务状态，如草稿、评审中、驳回等 | 创建时初始化；实际经过且配置了状态的连线；明确的特殊操作 |
| `process_status` / DTO `processStatus` | 当前 `process_instance_id` 的流程生命周期：`NOT_STARTED`、`RUNNING`、`COMPLETED` | 运行时维护的只读系统字段，普通表单/DTO 写入会被过滤 |
| `entity_process_link.end_type` | 正常结束、终止等独立结束类型 | 结束事件与对账维护；不是实体业务状态 |

流程挂起仍属于 RUNNING；引擎是否挂起、是否存在待办、能否操作仍由引擎校验。所有结束方式的生命周期均为 COMPLETED，不表示审批通过。

新发布流程不再在发起时隐式设为 PENDING，也不在正常结束时隐式设为 APPROVED。连线未配置状态即保持原值。通过连线推进的驳回采用实际连线状态，不再随后强制覆盖为 REJECTED；人工终止保留原来的专门业务状态处理。退回、跳转本身不经过连线时保持原有明确操作语义。本次未增加撤回入口。

## 读取性能与一致性

实体列表、实体详情和新的流程状态条件直接使用业务表中的 `process_status`。实体列表原本已读取业务表，因此没有把本来不存在的逐条引擎查询计为优化收益。

“我发起”先在数据库分页，再补充当前页信息。未结束的历史实例也有历史记录，直接用 `endTime` 判定 RUNNING/COMPLETED，不再额外查询运行实例来判断状态。名称筛选保持原来的部署名称/配置名称回退含义：先找匹配定义，再分页。Flowable 7 的历史查询不支持定义 ID 集合，因此该筛选使用参数化 Mapper 查询当前页 ID。相同定义、用户、实体在本次请求中复用读取结果。活动节点和终止能力仍按引擎读取。

历史实例不能使用实体最新一代实例的生命周期；旧实例结束后再次发起时，两者本来就可能不同。未引入跨请求的实体缓存，也没有为低选择性的状态列盲目添加单列索引；没有宣称未经测量的毫秒级提升。

结束副本经已有持久化 Outbox 和补偿更新，提交后可能存在短暂延迟。关键流程操作、真实待办和执行位置以引擎为准。实体表字段适合展示、筛选、统计，不替代执行授权。

## 兼容与上线

1. 仅新增 Flyway Java 迁移 `V102__entity_process_lifecycle.java`，没有修改、删除或重命名历史迁移。它按登记的动态业务表增加字段，按运行实例/已结束历史回填；保留历史业务状态及发布文档。
2. 无法确认的引擎关联、与自定义字段重名时，迁移会在改表前失败并指出问题，禁止将查不到的运行实例一律当作已完成。需先修复真实数据关联或字段冲突。
3. 新发布 XML 写入 `entityStatusPolicy=TRANSITION_V1`；没有标记的旧部署保留原任务映射和起止回写路径。编辑草稿不会让运行中的旧实例切换成新规则。新连线监听始终读取该实例的部署版本。
4. 上线前检查并补齐需要业务状态变化的开始、通过、驳回等连线，再重新发布流程。没有配置的开始/结束连线不再获得隐式状态；依赖正常结束写 `approved_at` 或 INITIAL_EFFECTIVE 版本的业务，应明确配置对应业务动作，不能把任意结束当作生效。
5. 新增 PROCESS_STATE 条件带 `lifecycleVersion: 1`；旧发布规则未带标记时保持原授权含义。需要改用新语义时，在规则编辑器重新创建该流程状态条件并发布；不批量将旧“正常完成”授权扩大成所有结束方式。
6. 本次没有部署、没有运行开发/生产业务库迁移。MySQL 测试只使用自动销毁的隔离容器。
