# 空办理人策略修改与验证记录

验证日期：2026-09-13。

流程默认策略和节点覆盖策略共用选择编辑器。兜底用户、兜底用户组、责任人和值班组均从目录选择，支持按名称搜索、清空和回显；不再要求输入用户 ID 或用户组编码。切换责任主体类型会清空原选择，拒绝选择禁用用户。旧快照中的用户 ID 和用户组编码可回显，未操作的历史标识不会自动改写。

流程及节点保存共用必选项和重试参数校验，责任主体类型随 BPMN 快照保存。首次等待统一为 5–86400 秒，重试次数为 1–20，退避倍率为 1–10；无穷值、NaN 和非整数次数／延迟不能通过校验。

## 运行时修复

- 固定用户失效或用户组无人可用时，执行配置的空办理人策略；v2 校验不再直接绕过事件和兜底策略。未启用新策略的历史宽松节点保持原兼容行为。
- 应用策略前清除失效的原执行人和候选身份，确保兜底组成员能认领任务，事件等待任务不再保留无效分配。
- 引用其他节点审批人时仅复用人员来源，使用当前节点的空办理人策略或流程默认值。
- 自动重试只支持可重放的人员接口（包括引用链最终指向人员接口的节点）。固定人员、用户组、表达式等缺少人员接口的来源在发布时明确报错，应选择运维事件或兜底策略。
- 历史自动重试事件没有人员接口时转为 `MANUAL_REQUIRED`，清除重试时间，避免相同失败请求号导致永久停留在定时扫描中。

## 逐项结果

| 策略 | 验证结果 |
| --- | --- |
| 阻断发布／启动 | 静态无有效人员被发布校验拦截；运行时阻断回滚任务和实例，事件仍可查询。 |
| 创建运维事件 | 保留无分配任务和 OPEN 事件；人工补充办理人后事件关闭，任务可继续完成。 |
| 兜底用户 | 按目录解析为实际用户名并分配任务；旧失效身份被清除，任务可完成。 |
| 兜底用户组 | 生成正确的候选组，清除原执行人；组成员可认领、完成任务。 |
| 等待并自动重试 | 首次等待、指数退避、到期扫描、恢复分配、重复请求幂等均通过；不会自动完成审批。耗尽后保留 OPEN 事件，记录 RETRY_EXHAUSTED 并停止调度。 |
| 继承流程默认策略 | 使用部署快照，忽略节点残留的兜底与重试字段；显式节点覆盖优先于流程默认。 |

补充验证：禁用兜底用户、无有效成员的兜底组在发布校验被拒绝；部署后兜底对象失效时创建可人工恢复事件。节点引用分别验证继承、兜底组和自动重试，源节点策略不会覆盖当前节点策略。
