# 节点操作权限简化方案

> 状态：2026-09-09 已实施。本方案替代流程设计器中的“节点操作矩阵”。

## 1. 目标

用户任务只配置以下三个独立开关，默认均为开启：

- 允许转办；
- 允许加签；
- 允许发起人终止流程。

新配置不再提供条件表达式、角色或权限码、理由模板、目标范围、加签类型拆分、模拟预览和批量复制。

## 2. 数据模型

三个值保存在用户任务现有的 `assigneeConfig` JSON 根级：

```json
{
  "allowTransfer": true,
  "allowAddSign": true,
  "allowTerminate": true
}
```

配置继续随 BPMN XML 草稿、发布版本和 Flowable 部署快照持久化，并同步进入节点的 `config_json`。不新增表、列、索引或 Flyway 迁移。

## 3. 运行规则

- 前端只有在后端明确返回 `true` 时展示转办、加签和终止入口。
- 转办和加签在业务服务产生任何持久化副作用前校验开关，不能通过直接调用接口绕过。
- 终止仍只允许流程发起人操作；存在多个并行活动用户任务时，所有活动节点都允许终止才可执行。
- 三个开关控制普通用户的办理入口。开放接口的管理取消、流程撤回、异常处置和 SLA 自动升级仍按各自独立规则执行。

## 4. 存量兼容

- 新三字段任意一个存在时，以新模型为准，旧矩阵不再参与该节点判定；缺失的单个新字段按 `true` 处理。
- 旧草稿第一次保存时折叠为三个开关并删除旧矩阵字段。只有无条件开放的旧规则才能折叠为 `true`；带条件、权限码、理由、目标范围或类型限制的规则安全折叠为 `false`，避免扩大权限。
- 已发布且正在运行的旧流程继续读取其部署快照中的旧策略，避免修改历史实例语义；待存量实例结束后可另行删除内部兼容代码。

## 5. 删除范围

- 删除设计器矩阵编辑器及其模拟、覆盖生成客户端；
- 删除矩阵专用的可用动作、模拟和覆盖生成 HTTP 接口；
- 保留现有 `/api/tasks/{taskId}/operations`，统一返回三个最终能力；
- “我发起的”列表新增 `canTerminate`，用于服务端权威控制终止按钮。
