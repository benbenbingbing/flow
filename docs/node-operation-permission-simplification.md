# 节点操作权限简化方案

> 状态：2026-09-23 增加独立撤回开关及 PC 入口。本方案替代流程设计器中的“节点操作矩阵”。

## 1. 目标

用户任务配置四个独立开关。新增节点只有“允许终止”默认开启，其余默认关闭：

- 允许转办；
- 允许加签；
- 允许发起人终止流程；
- 允许发起人撤回流程。

转办、加签占第一行，终止、撤回占第二行；并行节点等说明放入问号提示。

新配置不再提供条件表达式、角色或权限码、理由模板、目标范围、加签类型拆分、模拟预览和批量复制。

## 2. 数据模型

四个值保存在用户任务现有的 `assigneeConfig` JSON 根级：

```json
{
  "allowTransfer": false,
  "allowAddSign": false,
  "allowTerminate": true,
  "allowWithdraw": false
}
```

配置继续随 BPMN XML 草稿、发布版本和 Flowable 部署快照持久化，并同步进入节点的 `config_json`。不新增表、列、索引或 Flyway 迁移。

## 3. 运行规则

- 前端只有在后端明确返回 true 时展示对应操作入口。
- 转办和加签在业务服务产生任何持久化副作用前校验开关，不能通过直接调用接口绕过。
- 终止仍只允许流程发起人操作；存在多个并行活动用户任务时，所有活动节点都允许终止才可执行。
- SLA 自动转办/加签同样受对应节点开关约束；Open API 取消仍受“允许终止”约束。显式配置撤回后，发起人撤回独立受“允许撤回”约束，无需同时允许终止。
- 空办理人事故的管理员处置、关联流程的系统级联终止属于运维恢复和状态一致性机制，作为明确的系统豁免，不作为用户可用操作。

## 4. 存量兼容

- 任一简化字段存在时，以简化模型为准，旧矩阵不再参与该节点判定。旧三字段缺省值继续为 `true`；旧版本缺少 `allowWithdraw` 时沿用原 `allowTerminate` 门禁，显式设置撤回后两者完全独立。
- 新增节点在创建命令中立即写入四个默认值，未打开设置面板也不会回退到历史默认；导入、复制已有配置的节点不会重置权限。
- 旧草稿第一次保存时折叠为四个开关并删除旧矩阵字段。只有无条件开放的旧规则才能折叠为 `true`；带条件、权限码、理由、目标范围或类型限制的规则安全折叠为 `false`，避免扩大权限。
- 已发布且正在运行的旧流程继续读取其部署快照中的旧策略，避免修改历史实例语义；待存量实例结束后可另行删除内部兼容代码。

## 5. 删除范围

- 删除设计器矩阵编辑器及其模拟、覆盖生成客户端；
- 删除矩阵专用的可用动作、模拟和覆盖生成 HTTP 接口；
- 保留现有 `/api/tasks/{taskId}/operations`，统一返回三个最终能力；
- “我发起的”列表返回 `canTerminate` 与 `canWithdraw`。PC 仅对运行中且 `canWithdraw === true` 的行显示撤回；确认后重新读取实例权限，成功后刷新列表和计数。
- PC 与移动端共用 `/api/process-instance/{id}/operations` 查询撤回能力；写接口统一校验发起人、运行状态、所有活动节点开关及旧策略约束。已结束、无活动任务或任一分支禁止撤回均不可撤回。
- 开启撤回、关闭终止时，发布仍要求实体有且仅有一个撤回目标状态。节点设置保存、发布后才用于对应流程版本。
