## 2. P0：安全性和发布可靠性

### 2.1 发布前检查

- 实体、表单、列表和流程配置发布前统一执行结构、引用、权限和运行时约束检查。
- 流程检查覆盖 BPMN 结构、办理人配置、节点操作策略及关键扩展属性。
- 检查结果使用稳定的问题编码、严重级别、配置位置和修复建议，便于前端定位。

### 2.2 草稿并发与版本可靠性

- 草稿加入 revision 乐观锁，避免多人编辑时后提交覆盖先提交。
- 冲突返回当前版本和预期版本，调用端可以明确提示重新加载或合并。
- 发布基于候选版本和冻结快照，不直接把可变草稿暴露给运行实例。

### 2.3 数据权限安全

- 数据范围默认采用拒绝策略，不再在配置缺失、解析异常或未知类型时自动放行。
- 查询条件使用参数绑定和允许字段约束，禁止把任意配置文本拼接为 SQL。
- 增加历史配置盘点与异常范围记录，为存量配置治理提供依据。

### 2.4 数据库结构与唯一性

- 补齐发布、修订、候选版本和治理记录所需表结构、索引及唯一约束。
- 通过数据库约束兜底重复业务键和并发写入，应用层仍保留可读错误提示。

### 2.5 HOTFIX 风险提示、观察与回滚

- HOTFIX 记录发布说明、操作人、影响范围和审计信息；发布说明缺省时由服务端生成默认说明。
- HOTFIX 不绕过结构及安全校验；风险确认后直接发布，不进入人工审核流程。
- 普通发布、候选发布和紧急修复形成可追溯的状态边界。

## 3. P1-4.2：空办理人策略

### 3.1 策略模型

支持以下节点级和流程级策略：

| 策略 | 行为 |
| --- | --- |
| FAIL | 阻止节点继续并记录异常事件 |
| SKIP | 自动跳过当前节点并记录原因 |
| ASSIGN_TO_ADMIN | 分配给平台管理员兜底 |
| ASSIGN_TO_PROCESS_OWNER | 分配给流程所有者 |
| RETRY | 按配置次数和间隔重试解析，耗尽后执行兜底策略 |

### 3.2 运行时与运维闭环

- 预发布检查验证策略结构、重试参数、兜底目标和流程所有者。
- 运行时办理人解析与预检查复用同一策略模型，避免设计态与运行态结论不一致。
- 空办理人事件持久化，支持状态、流程、节点、时间范围查询及人工处置。
- 提供管理页面查看失败上下文、策略快照和处置结果。

## 4. P1-4.3：节点操作矩阵

### 4.1 操作范围

矩阵统一治理审批、驳回、转办、前加签、后加签、并行加签、手工抄送、撤回和终止。

### 4.2 决策维度

- 节点、操作、启用状态、条件表达式和权限标识。
- 原因是否必填、原因模板、目标人员范围、驳回目标范围和加签类型。
- 撤回时间窗口及操作特有约束。
- 多节点批量编辑通过 BPMN command stack 写入，支持撤销和重做。

### 4.3 安全与一致性

- 条件语言采用受限递归下降解析，不执行脚本、方法、反射或任意表达式。
- 前端按钮可见性和后端 API 授权均由同一决策服务给出，直接调用接口不能绕过矩阵。
- 历史任务按照任务绑定的流程定义版本读取冻结策略，发布后的新配置不会篡改历史行为。
- 提供可用操作查询、策略模拟和覆盖用例生成接口。

## 5. P1-4.5：统一配置测试中心

### 5.1 测试对象

统一支持 ENTITY、FORM、LIST、PROCESS、EMPTY_ASSIGNEE、NODE_OPERATION 和 CONFIG_JSON 测试类型。

### 5.2 核心能力

- 测试套件和测试用例版本化保存，并使用乐观锁避免并发覆盖。
- 可从当前配置自动生成基线用例，可在保存前执行快速测试，也可运行完整套件。
- 流程用例复用发布前检查，空办理人与节点操作用例复用真实运行时决策器。
- 每次运行持久化输入指纹、结果、证据、耗时和通过率，支持历史对比与 JSON 报告导出。
- 发布门禁可检查指定范围是否存在新鲜且通过的测试运行；无门禁套件时保持兼容。
- 节点操作矩阵可生成覆盖用例并导入测试中心。

### 5.3 管理入口

- 前端路由：`/system/config-test-center`
- 权限：`config:test:list`、`config:test:manage`、`config:test:run`、`config:test:export`
- 数据库迁移：`V056__unified_config_test_center.sql`

## 6. P2：平台竞争力增强

### 6.1 版本化配置蓝图

- 将实体、表单、列表、流程、节点策略和数据范围沉淀为可搜索蓝图。
- 草稿可修订，发布后形成冻结版本；实例化结果携带来源版本和配置指纹。
- 参数使用 `${{parameter}}` 占位符和 JSON Schema 声明，支持 required、default、enum、pattern 及基础类型。
- 精确占位符保留整数、布尔、数组和对象类型；复杂值禁止嵌入普通字符串。
- 未声明参数、缺失必填参数和未解析占位符均会失败，不执行脚本。

### 6.2 依赖图与变更影响分析

- 显式登记资产之间的引用关系，更新单个源资产时采用原子替换。
- 支持 UPSTREAM、DOWNSTREAM 和 BOTH 三种分析方向。
- 使用有界广度优先遍历，限制最大深度和节点数，检测循环依赖。
- 报告返回影响节点、影响边、深度、风险分级和发布建议，可用于变更评审。

### 6.3 配置质量评分与智能建议

- 扫描明文凭据、不安全脚本、反射或 JavaScript URI、重复标识、深层嵌套和非安全 HTTP。
- 识别宽泛数据范围、操作已启用但缺权限、原因模板缺失、空办理人重试无负责人等业务风险。
- 返回规则编码、严重级别、问题位置、扣分和修复建议，结果可解释、可复现。
- 质量快照持久化，可查看同一资产的历史分数和配置指纹。

### 6.4 可移植配置包

- 蓝图可导出包含元数据、参数 Schema、模板、版本和摘要的 JSON 配置包。
- 导入前验证 SHA-256 摘要，识别传输损坏或内容篡改。
- 包结构不包含可执行代码，可作为环境迁移、交付审计和版本归档载体。

### 6.5 管理入口

- 前端路由：`/system/config-intelligence`
- 权限：`config:intelligence:list`、`config:intelligence:manage`、`config:intelligence:analyze`
- 页面包含蓝图库、参数化实例、依赖登记、影响分析、质量体检和配置包校验。
- 数据库迁移：`V057__configuration_intelligence_center.sql`

## 10. 发布建议

1. 依次执行全部 Flyway 迁移，禁止跳过中间版本或修改历史迁移校验和。
2. 为关键实体、表单、列表和流程建立测试套件，并在逐步推广后启用发布门禁。
3. 对空办理人和节点操作策略执行盘点；列表数据范围直接在列表设计器中维护安全默认策略。
4. 使用依赖影响报告评审高风险配置变更，使用质量分数作为趋势指标而非唯一发布依据。
5. 将导出的配置包纳入版本归档，并在导入目标环境前执行完整性校验。
