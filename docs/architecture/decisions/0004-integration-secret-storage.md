# ADR-0004：集成密钥使用信封加密和可替换解析端口

- 状态：已接受
- 日期：2026-07-29
- 决策范围：开放集成 V1 Secret 管理

## 背景

连接器和 Webhook 需要保存外部凭据与签名密钥。将明文写入 BPMN、表单、动作配置、
数据库普通字段、日志或审计会形成不可接受的泄漏面。仅依赖数据库磁盘加密也不能阻止
应用查询和备份泄漏。

## 决策

1. 配置只保存 `secret://integration/{applicationId}/{secretName}` 引用。
2. V1 的 `IntegrationSecretResolver` 使用 AES-256-GCM 信封加密。
3. 主密钥通过部署 Secret 注入，不进入数据库、镜像、Git、日志或诊断接口。
4. 密文记录保存 key version、nonce、ciphertext 和认证标签，支持重叠轮换。
5. 解密值只在单次调用的最短作用域使用，不缓存明文，不进入异常消息。
6. 管理端创建或轮换 Secret 时只展示一次；后续只展示名称、版本和时间。
7. 解析能力保持端口化，后续可以替换为 Vault、云 Secret Manager 或 External Secrets。

## 生产默认

- 本地和测试环境可以使用显式测试主密钥。
- 生产环境未配置主密钥时，Secret 和 Connector 功能必须拒绝启动或保持关闭，不能生成
  临时主密钥。
- Webhook 签名密钥和 Connector Secret 使用相同加密基础，但权限和命名空间分离。

## 影响

- 数据库备份只包含密文，但主密钥备份和轮换需要独立运维流程。
- 删除或丢失主密钥会使对应 Secret 不可恢复。
- 所有日志、审计、异常和管理 DTO 都需要敏感信息策略测试。
